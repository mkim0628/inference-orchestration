## 미해결 이슈

### 1. [FAIL, 높음] `KVPacketCache._track_noncontiguous()` 버그

**위치**: `src/cache/kv_packet.py:291-301`

**문제**: `get()` 내부에서 `self._store.move_to_end(key)`가 먼저 호출된 뒤 `_track_noncontiguous()`가 실행된다. 이 시점에 `list(self._store.keys())`의 순서는 이미 `move_to_end()`로 변경되어 있어, 이전 접근 키(`prev`)와 현재 키(`key`)의 인덱스 차이가 실제 삽입 순서 기반 비연속성을 반영하지 못한다. 결과적으로 모든 접근이 "인접"으로 판정되어 `_noncontiguous_hits`가 항상 0이다.

**수정 방향**: 삽입 시 별도의 `_insertion_order: List[str]` 를 유지하고, `_track_noncontiguous()` 에서 현재 store 순서 대신 이 고정 삽입 순서 리스트를 기준으로 인덱스 비교를 수행한다.

```python
# put()에서:
self._insertion_order.append(key)

# _track_noncontiguous()에서:
if key in self._insertion_order and prev in self._insertion_order:
    if abs(self._insertion_order.index(key) - self._insertion_order.index(prev)) > 1:
        self._noncontiguous_hits += 1
```

### 3. [Partial, 중간] draft 오류 평균이 threshold를 소폭 초과

**문제**: `mean_relative_error` (draft 오류)가 ~0.0103으로 acceptance_threshold=0.01보다 약간 높다. 이는 INT8 드래프트 코덱의 양자화 오류가 threshold에 근접하여 일부 드래프트가 reject된다는 의미다. 최종 출력 오류(final_error)는 수학적으로 보장되지만, 처리량 이점이 일부 감소한다.

**수정 방향 (권장)**: acceptance_threshold를 0.02로 상향하거나, VeriCacheConfig.acceptance_threshold를 0.01에서 0.015로 완화한다. 단, final_error 보장은 threshold에 비례하므로 ±1.5% 이내로 여전히 허용 범위.
