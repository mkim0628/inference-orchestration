### 아이디어 A-1: PPDAppendFullPrefillClassificationRouter (PPD 프리필 유형 분류 동적 라우터)
- **가설**: 멀티-턴 P/D 분리 환경에서 모든 프리필 요청을 프리필 노드로 라우팅하는 고정 정책이 append-prefill(캐시된 KV를 재사용하면서 신규 입력 토큰만 처리)에서 불필요한 KV 반복 전송과 대역폭 포화를 유발하는 원인임을, PPD(2603.13358)의 핵심 통찰 — "append-prefill은 decode 노드에서 로컬 처리하고 full-prefill만 prefill 노드로 라우팅" — 을 경량 분류기로 구현하면, Turn 2+ TTFT를 68% 단축하면서 P→D KV 전송 대역폭을 대폭 절감할 수 있다. 이전 모든 A 기법(HMAMultiConnectorScheduler, AMPDLazySegmentFetchScheduler, KVServeBayesianScheduler 등)은 프리필 유형 자체를 분류해 라우팅하는 메커니즘이 없었다.
- **접근 방법**:
  1. `PPDAppendFullPrefillClassifier` 클래스 (`src/scheduler/ppd_append_full_classifier.py`): `BaseScheduler` 상속
  2. **프리필 유형 분류 로직**:
     - 요청 수신 시 세션 컨텍스트 해시 비교로 유형 판정:
       - **append-prefill 조건**: `context_hash(current_request)` ⊇ `context_hash(previous_turn)` — 이전 턴 컨텍스트를 포함하면서 신규 토큰만 추가. `append_token_ratio = new_tokens / total_tokens > append_threshold` (기본 0.15 이하가 신규 토큰).
       - **full-prefill 조건**: 캐시에 일치하는 KV가 없거나 새로운 독립 세션.
     - 분류 오버헤드: `context_hash` 조회 O(1) (세션 ID → 이전 턴 해시 레지스트리 딕셔너리 룩업).
     - `PrefillTypeRegistry` (`src/scheduler/prefill_type_registry.py`): `session_id → {last_context_hash, last_kv_pointer, turn_count}` 매핑. 세션 만료 시 TTL 기반 자동 정리.
  3. **동적 라우팅 결정**:
     - **append-prefill 경로**: decode 노드의 캐시된 KV를 직접 재사용. P 노드로의 KV 전송 없음. `src/cache/segmented.py`의 `SegmentedHashCache.get(session_id, prev_kv_pointer)` 경로로 이전 턴 KV 직접 참조.
     - **full-prefill 경로**: 기존 P 노드 라우팅 유지.
     - **SLO-인식 전환 로직**: TTFT SLO 여유(`slo_headroom = slo_deadline - current_latency_p99`)가 낮으면 append-prefill도 P 노드로 오프로드(D 노드 부하가 높을 때). `slo_headroom_threshold` YAML 외부화.
  4. **PPD 라우팅 결정 모니터링**:
     - `{append_prefill_ratio, full_prefill_ratio, d_node_local_hit_rate, kv_transfer_reduction_ratio}`를 `results/<exp-name>/metrics.json`에 기록.
     - append-prefill 경로에서 실제 KV 전송이 0임을 검증하는 `zero_transfer_assert` 단위 테스트.
  5. **이전 A 기법과의 차별점**:
     - KVServeBayesianScheduler(05-21 A-1): Bayesian 기반 압축 전략 공간 탐색 + 3D Pareto 프런트 (전략 선택 메타-최적화).
     - AMPDLazySegmentFetchScheduler(05-18 A-1): 세그먼트 집합 확정 전 KV 전송 보류 (pull-on-demand 타이밍 제어).
     - CacheTTLAdaptiveTTLScheduler(A-3, 이번 사이클): TTL 기반 KV 보존 연장 (보존 기간 관리).
     - PPDAppendFullPrefillClassifier: **프리필 유형(append vs. full)을 런타임에 분류해 decode 노드 로컬 처리로 KV 전송 자체를 우회** — 이전 어느 A 기법도 프리필 유형 분류 기반 라우팅을 도입하지 않았다.
- **대상 환경**: 멀티 노드 (P/D 분리 환경 필수)
- **멀티 노드 고려사항**: D 노드가 로컬 KV 캐시를 충분히 유지할 메모리 예산 필요. P 노드 → D 노드 KV 전송 대역폭(InfiniBand/RDMA) 절감이 append-prefill 비율에 비례해 발생. `PrefillTypeRegistry`는 세션 ID 기반으로 D 노드 로컬에 유지 — 마스터 스케줄러에서 세션-노드 어피니티 매핑으로 동일 세션은 동일 D 노드에 배치.
- **예상 효과**: Turn 2+ TTFT −50~68% (PPD 원논문 기반), KV 전송 대역폭 절감 −40~60% (append-prefill 비율에 비례), Scheduling overhead TTFT +2% 이내 (프리필 유형 분류: O(1) 해시 비교)
- **구현 난이도**: medium
- **우선순위**: 1

### 아이디어 A-2: DualMapDualHashRingSLOAwareInstanceRouter (DualMap 이중 해시-링 SLO-인식 인스턴스 라우터)
- **가설**: 분산 LLM 서빙에서 캐시-어피니티 라우팅(동일 요청 → 동일 인스턴스 → KV 재사용)과 로드 밸런싱(요청 균등 분배)이 구조적으로 상충하는 문제를, DualMap(2602.06502)의 "이중 해시 매핑으로 두 인스턴스 후보를 항상 유지하고 런타임 부하 상태로 더 나은 후보를 O(1) 선택"하는 접근을 `src/scheduler/`에 구현하면, 단일 최적 인스턴스 탐색(O(n)) 대신 2후보 중 1선택(O(1))으로 캐시 어피니티를 근사하면서 처리량을 최대 2.25× 향상시킬 수 있다. 이전 모든 A 기법은 단일 인스턴스 환경이거나 클러스터 레이어의 이중 매핑 전략을 도입한 것이 없었다.
- **접근 방법**:
  1. `DualMapDualHashRouter` 클래스 (`src/scheduler/dualmap_dual_hash_router.py`): `BaseScheduler` 상속
  2. **이중 해시 매핑 자료구조**:
     - 해시 함수 두 개 `H1`, `H2` (서로 독립적, xxHash 기반): 각 요청에 대해 `candidate_1 = instances[H1(prefix_hash) % N]`, `candidate_2 = instances[H2(prefix_hash) % N]`.
     - 두 후보 인스턴스가 항상 다르도록 보장: `H2(x) ≡ H1(x + salt) % N`, `candidate_2 ≠ candidate_1` 조건 위반 시 `candidate_2 = instances[(H2(x) + 1) % N]`.
     - 이중-해시-링 자료구조: 각 인스턴스를 해시 링 2개에 독립적으로 등록. 인스턴스 추가/제거 시 전역 재매핑 없이 해당 링 구간만 갱신.
  3. **런타임 부하 인식 후보 선택**:
     - `candidate_selector(c1, c2, current_state) → instance`:
       - 두 후보의 현재 KV 캐시 히트율(`kv_hit_rate`), 큐 길이(`queue_depth`), SLO 여유(`slo_headroom`)를 비교.
       - 선택 기준: `score(c) = w1 × kv_hit_rate(c) + w2 × (1 - queue_depth(c) / max_depth) + w3 × slo_headroom(c)`. 가중치 `w1=0.5, w2=0.3, w3=0.2` YAML 외부화.
     - **SLO-인식 모드 전환**: SLO 압박(`slo_headroom < slo_critical_threshold`) 시 `w1=0.1, w2=0.8, w3=0.1`으로 자동 전환 (로드 밸런싱 우선).
     - **핫스팟-인식 재균형**: 특정 인스턴스 큐 길이가 `hotspot_threshold`(기본 2× 평균) 초과 시 낮은 부하 인스턴스로 요청 재배정 (캐시 어피니티 잠시 포기).
  4. **경량 스케일링 지원**:
     - 인스턴스 추가: 새 인스턴스를 링 1, 링 2에 각각 등록. 영향 범위: 링 상의 인접 구간만 재매핑 (O(1) 업데이트).
     - 인스턴스 제거: 해당 인스턴스의 링 구간을 다음 인스턴스로 흡수. 해당 KV 캐시는 마이그레이션 없이 TTL 만료로 자연 소멸.
  5. **이전 A 기법과의 차별점**:
     - PrefillShareFanoutRouter(05-18 A-2): 공유 세그먼트 1-to-N 팬아웃 배포 (프리필 노드 → N 디코딩 노드 방향).
     - KVRMCoalescingSegmentScheduler(05-16 A-1): 비연속 세그먼트 블록 합체 전송 (전송 계층 최적화).
     - DualMapDualHashRouter: **클러스터 인스턴스 선택 계층에서 캐시-어피니티와 로드밸런싱을 이중 해시 매핑으로 O(1) 동시 달성** — 2후보 후보군 유지 방식은 이전 어느 A 기법에도 없는 새로운 인스턴스 선택 자료구조다.
- **대상 환경**: 멀티 노드 (다중 인스턴스 클러스터 필수)
- **멀티 노드 고려사항**: 인스턴스 상태 정보(KV 히트율, 큐 길이)는 경량 heartbeat 메시지(100ms 주기)로 마스터 라우터에 집계. 해시 링 자료구조는 마스터 라우터에 단일 인스턴스로 유지. 크로스-랙 인스턴스 간 라우팅 시 네트워크 레이턴시를 `score()` 함수의 추가 패널티 항으로 포함 가능: `w4 × (1 - latency(c) / max_latency)`.
- **예상 효과**: 처리량 +100~125% (DualMap 원논문 최대 2.25× 기반), KV 캐시 히트율 유지 (단일 해시 대비 어피니티 근사 정확도 −5% 이내), Scheduling overhead TTFT +2% 이내 (O(1) 이중 해시 계산 + 상태 비교)
- **구현 난이도**: medium
- **우선순위**: 2

### 아이디어 A-3: CacheTTLToolCallDurationPredictiveTTLScheduler (CacheTTL 도구 호출 시간 예측 기반 적응형 TTL 스케줄러)
- **가설**: 에이전틱 워크로드에서 도구 호출 대기(tool execution pause) 동안 KV 캐시가 퇴거되어 다음 LLM 호출 시 전체 KV를 재계산하는 비효율을, CacheTTL(2511.02230 v4)의 "도구 호출 완료 예측 시간 기반 TTL 계산 + KV 보존 연장"을 구현하고, ThunderAgent(05-19에서 분석됨)의 LLM Program 정적 분석으로 도구 호출 실행 시간을 사전 추정하는 정보를 TTL 계산에 입력으로 사용하면, KV 보존의 비용-편익을 정량화해 JCT(Job Completion Time)를 최대 8× 단축할 수 있다. 이전 모든 A 기법 중 KV를 TTL 기반으로 보존 연장하는 메커니즘이 없었다 — CONCURCongestionBasedAgentAdmissionScheduler(05-20)는 "입장 제어"였고, ThunderAgentProgramScheduler(05-19)는 "쓰래싱 방지 일시 중지"였다.
- **접근 방법**:
  1. `CacheTTLAdaptiveTTLScheduler` 클래스 (`src/scheduler/cache_ttl_adaptive_scheduler.py`): `BaseScheduler` 상속
  2. **도구 호출 실행 시간 예측기**:
     - `ToolCallDurationPredictor` (`src/scheduler/tool_call_duration_predictor.py`): 도구 유형별 실행 시간 히스토리를 EMA(α=0.9)로 추적.
     - 입력: 도구 이름(`tool_name`), 입력 크기(`input_size_bytes`), 과거 실행 시간 분포.
     - 출력: `estimated_duration_ms` + `confidence_interval_ms` (90th 백분위 기반).
     - 히스토리가 없는 새 도구 유형: `default_duration_ms=5000` (보수적 초기값) + 실측 후 업데이트.
  3. **TTL 계산 공식**:
     - `ttl_ms = estimated_duration_ms × ttl_multiplier + scheduling_slack_ms`.
     - `ttl_multiplier`: 기본 1.5 (도구 실행 시간의 1.5배 보존) — 예측 불확실성 버퍼. YAML 외부화.
     - `scheduling_slack_ms`: 스케줄링 지연 전파 추정치 (배치 사이클 × 평균 배치 지연). 실시간 업데이트.
     - 혼잡 상태 조정: KV 풀 점유율 > `congestion_threshold`(기본 0.80) 시 `ttl_multiplier` 축소 (`ttl_multiplier = 1.0`) — 메모리 압박 시 TTL 단축으로 공간 확보.
  4. **TTL 기반 KV 보존 메커니즘**:
     - 요청의 도구 호출 발생 시 `preserve_kv(session_id, ttl_ms)` 호출 → 해당 세션의 KV를 TTL 동안 퇴거 불가(pinned) 상태로 마킹.
     - TTL 만료 전 도구 호출 완료 이벤트 수신 시 즉시 pin 해제 + 다음 LLM 호출 준비.
     - TTL 만료 후에도 도구 호출 미완료 시: KV를 DRAM으로 강등 후 pin 해제 (GPU HBM에서 제거하되 DRAM 보존으로 재사용 가능).
     - EchoKV 온-디맨드 압축 전환(C-2, 이번 사이클)과 연동: TTL 남은 시간 < `compress_trigger_ms`(기본 TTL의 50%) 시 EchoKV 압축 모드로 자동 전환 — TTL-압축 하이브리드 보존.
  5. **이전 A 기법과의 차별점**:
     - CONCURCongestionBasedAgentAdmissionScheduler(05-20 A-1): KV 풀 혼잡도 기반 신규 에이전트 어드미션 제어 (입장 제어).
     - ThunderAgentProgramScheduler(05-19 A-2): Program 정적 분석 기반 쓰래싱 방지 일시 중지 (선점 제어).
     - PBKVAgentSegmentPreservationScheduler(05-13): 확률적 MLP 예측 기반 KV 세그먼트 선점 보존 (보존 결정).
     - CacheTTLAdaptiveTTLScheduler: **도구 호출 실행 시간 예측 → TTL 계산 → 도구 호출 간 KV 보존 연장** — TTL 기반 보존 연장이라는 완전히 새로운 보존 관리 메커니즘.
- **대상 환경**: 단일 노드 / 멀티 노드 양쪽
- **멀티 노드 고려사항**: 멀티 노드에서 TTL 보존 결정은 세션이 할당된 D 노드 로컬에서 실행. 도구 호출 완료 이벤트를 에이전트 오케스트레이터 → D 노드로 전달하는 gRPC 인터페이스 추가. 혼잡 상태 감지는 클러스터 전체 KV 풀 집계값 사용 (마스터 스케줄러에서 100ms 주기로 집계).
- **예상 효과**: JCT −70~87% (CacheTTL 원논문 8× 기반, 도구 호출 간 KV 재계산 제거), Scheduling overhead TTFT +2% 이내 (TTL 계산: O(1) EMA 갱신 + 예측 조회), KV 캐시 메모리 점유 중립 (TTL 기반 보존은 필요 기간만 유지)

### 아이디어 B-1: SessionAwareTurnLevelNonContiguousSegmentCache (세션-인식 턴-레벨 비연속 세그먼트 캐시)
- **가설**: PPD(2603.13358)의 "멀티-턴 세션 내 turn-level KV를 decode 노드에서 로컬 재사용"하는 접근이 Activity B의 비연속 세그먼트 재사용과 경계를 공유하는 새로운 설계 공간을 제시한다 — 멀티-턴 세션의 각 턴 KV를 비연속 세그먼트로 보존하고 다음 턴에 재조합하면, 세션 내 turn-level 비연속 세그먼트 히트율을 전체 캐시 히트율 지표에 포함해 관리할 수 있다. 기존 B 기법들(BlockUnionNonContiguousReuseIndex, AMPDAdapShotLazyLoadPipeline, ThunderAgentStaticSegmentReservation 등)은 세션 ID를 세그먼트 메타데이터로 활용하지 않았으며, "세션 내 turn-level 비연속 재사용"이라는 재사용 단위를 명시적으로 모델링하지 않았다.
- **접근 방법**:
  1. `SessionAwareTurnLevelSegmentCache` 클래스 (`src/cache/session_turn_level_segment_cache.py`): `CacheStore` 인터페이스 상속
  2. **세션-턴 메타데이터 확장**:
     - 기존 `SegmentedHashCache`의 세그먼트 키를 `(content_hash, session_id, turn_id)` 3-tuple로 확장.
     - `TurnSegmentIndex = Dict[session_id → List[TurnSegmentEntry]]`. `TurnSegmentEntry = {turn_id, segment_id, kv_pointer, token_range, timestamp, ttl}`.
     - 세션 내 최근 N 턴의 세그먼트를 우선 보존하는 **세션-인식 LRU**: `session_priority_lru` — 동일 세션의 세그먼트는 cross-session 세그먼트보다 퇴거 우선순위가 낮음(더 오래 보존).
  3. **턴-레벨 비연속 세그먼트 재조합 경로**:
     - Turn 2+ 요청 수신 시 `get_session_segments(session_id, turn_range=[0, current_turn-1]) → List[SegmentMeta]` 호출로 이전 턴들의 세그먼트 메타데이터 즉시 획득.
     - PPDAppendFullPrefillClassifier(A-1)에서 "append-prefill" 판정 시 decode 노드의 세션 세그먼트를 직접 재조합: `assemble_turn_segments(session_id, target_turn_id) → BlockUnionTable`.
     - 비연속 세그먼트 재조합: 각 턴의 KV가 물리적으로 분산되어 있어도 `BlockUnionNonContiguousReuseIndex(05-21 B-1 기구현)`의 block-union 변환으로 직접 표준 어텐션 커널에 투입.
  4. **세션-인식 TTL 통합**:
     - `CacheTTLAdaptiveTTLScheduler(A-3)`의 TTL 보존 결정을 세그먼트 수준으로 전파: 도구 호출 중인 세션의 세그먼트에 TTL 마킹 → 퇴거 불가.
     - TTL 만료 후 압축 전환: 세션 세그먼트를 VQKV(C-1, 이번 사이클) VQ 압축으로 전환해 메모리 점유 축소.
  5. **DapQ 위치-기반 세그먼트 중요도 평가 통합**:
     - 세션 내 비연속 세그먼트의 "재사용 가능성 점수"를 DapQ(2603.11564)의 위치-인식 원칙으로 계산: 세그먼트 위치 범위(token position range)가 현재 디코딩 쿼리 위치에 가까울수록 재사용 가능성이 높다.
     - `reuse_score(segment) = position_proximity(segment.token_range, current_decode_position) × recency(segment.turn_id)`.
     - 의미 유사도보다 위치 근접도를 재사용 가능성 예측의 주 기준으로 사용 (DapQ 원칙 적용).
  6. **이전 B 기법과의 차별점**:
     - BlockUnionNonContiguousReuseIndex(05-21 B-1): PA 블록 → GQA-aware 블록 테이블 변환으로 memcpy 없이 표준 커널 투입 (물리 표현 변환 방식).
     - ThunderAgentStaticSegmentReservationCache(05-19 B-1): Program 정적 분석 기반 사전 예약 (워크플로우 구조 분석).
     - AMPDAdapShotLazyLoadPipeline(05-18 B-1): 세그먼트 집합 확정 후 지연 로드 + 재인코딩 오버랩 (전송 타이밍 최적화).
     - SessionAwareTurnLevelSegmentCache: **세션 ID + 턴 ID를 세그먼트 키로 명시화해 멀티-턴 세션의 turn-level KV를 비연속 세그먼트로 관리** — PPD 멀티-턴 로컬 재사용과 Activity B 비연속 재사용의 교차점을 처음으로 모델링.
- **예상 효과**: 세션 내 비연속 히트율 +30~45% (이전 턴 KV를 세션-인식 LRU로 보존해 turn-level 히트 증가), TTFT −40~60% (세션 내 turn-level 세그먼트 즉시 히트), 비연속 히트의 세션-내 비율 >50% (세션 내 히트가 cross-session 히트보다 높은 비율 달성 목표)
- **구현 난이도**: medium

### 아이디어 C-1: VQKVMultiCodebookTrainingFreeCompressionCodec (VQKV 다중 코드북 학습-프리 벡터 양자화 압축 코덱)
- **가설**: 기존 학습-프리 KV 압축 방법들이 스칼라 양자화(독립 스칼라 압축) 또는 저랭크 근사(차원 축소)에 한정되어 고압축비와 고정확도를 동시에 달성하지 못하는 한계를, VQKV(2603.16435)의 핵심 아이디어 — 각 KV 캐시 벡터를 복수의 코드북에서 가장 가까운 항목으로 매핑하고 정수 인덱스만 저장하는 벡터 양자화 — 를 구현하면, 학습 없이 오프라인 코드북 구성만으로 82.8% 압축률에서 98.6% 정확도 보존을 달성할 수 있다. 이전 C 기법 중 FibQuantVQCodec(05-14)이 VQ를 도입했으나 FibQuant는 랜덤-접근 복원 효율에 집중했고, VQKV는 고압축비-고정확도 동시 달성을 위한 다중 코드북 설계에 집중한다는 근본적 차이가 있다.
- **접근 방법**:
  1. `VQKVMultiCodebookCodec` 클래스 (`src/cache/vqkv_multi_codebook_codec.py`): `CompressionCodec` 인터페이스 구현
  2. **다중 코드북 구성 (오프라인 단계)**:
     - 보정 데이터(200 시퀀스)에서 각 레이어·헤드의 KV 벡터 분포를 수집.
     - M개 서브-코드북 구성: 각 KV 벡터를 M개 서브-벡터로 분할 후 각 서브-벡터에 독립 코드북 학습 (Product Quantization 방식). M=8, 각 코드북 크기 K=256 (기본값). 저장: `configs/vqkv_codebooks_{layer_id}_{head_id}.npz`.
     - 학습 알고리즘: k-means (sklearn, 배치 크기 10000, 최대 100 반복). GPU 가속: `faiss.Kmeans` 활용.
  3. **프리필 단계 인코딩**:
     - 각 KV 벡터 `v ∈ R^d`를 M개 서브-벡터로 분할: `v = [v_1, ..., v_M]`, `v_m ∈ R^(d/M)`.
     - 각 서브-벡터에 대해 해당 코드북의 가장 가까운 센트로이드 인덱스 계산: `idx_m = argmin_c ||v_m - codebook_m[c]||_2`.
     - 저장: M개 정수 인덱스만 저장 (FP16 대비 `d × 16 / (M × log2(K)) = d × 16 / (8 × 8) = d / 4` 비트 → 4× 이상 압축).
     - 레이어별 압축 강도 조정: 상위 레이어(정확도에 민감한 레이어)는 M=4 (낮은 압축), 하위 레이어는 M=16 (높은 압축). `configs/vqkv_layer_config.yaml` 외부화.
  4. **디코딩 단계 복원**:
     - `decode(idx_list) → KV_approx`: 각 인덱스에서 센트로이드 벡터 복원 후 서브-벡터 연결. 복원 오버헤드: 코드북 조회 O(M) = 8회 정수 인덱싱.
     - `torch.gather` 기반 배치 복원 (GPU 친화적 병렬 처리).
  5. **비연속 세그먼트와의 통합 (B+C)**:
     - `SessionAwareTurnLevelSegmentCache(B-1)`의 세션 세그먼트에 VQKV 압축 적용: 도구 호출 TTL 만료 직전 압축 전환.
     - VQ 압축된 세그먼트는 인덱스 스토리지만 필요하므로 동일 KV 풀에 유지 가능한 세그먼트 수 ~5× 증가.
  6. **FibQuantVQCodec(05-14)과의 차별점**:
     - FibQuantVQCodec: 피보나치 격자 기반 VQ + 랜덤-접근 복원 친화 코드북 (접근 효율 중심).
     - VQKVMultiCodebookCodec: Product Quantization 기반 M개 서브-코드북 + 레이어별 압축 강도 적응 조정 (82.8% 압축-98.6% 정확도 동시 달성 중심). 서브-코드북 분해 구조 자체가 FibQuant와 다른 설계.
- **예상 효과**: 메모리 −75~83% (VQKV 원논문 82.8% 기준, 레이어별 M 조정에 따라), accuracy delta ±1.4% (원논문 98.6% 정확도 보존 = −1.4% delta), 생성 컨텍스트 길이 4.3× 확장 (동일 메모리 예산 기준)
- **accuracy-preserving 근거**:
  (1) VQKV 원논문(2603.16435)이 LLaMA3.1-8B 기준 82.8% 압축률에서 LongBench 98.6% 정확도 보존을 실험적으로 검증 — accuracy-preserving 특성이 이미 입증됨.
  (2) Product Quantization의 각 서브-벡터 독립 양자화: 전체 KV 벡터의 오차가 각 서브-벡터 오차의 합에 바운드되며, M=8, K=256 조합에서 재구성 오차가 FP16 원본 대비 충분히 작음 (VQKV 논문의 레이트-왜곡 분석 기반).
  (3) 레이어별 압축 강도 조정: 정확도에 민감한 상위 레이어에 낮은 압축(M=4)을 적용해 모델 출력에 대한 누적 오차를 제한.
  (4) ±1% 이내 달성을 위한 조정: 목표 정확도 delta ±1%가 원논문 ±1.4% 대비 더 엄격하므로, M=6 (중간 압축) 설정 또는 레이어별 M 적응 조정으로 accuracy delta를 ±1% 이내로 맞추는 하이퍼파라미터 탐색 필요.
  검증: WikiText-2 perplexity ±1% + LongBench 8개 서브태스크 + NIAH 128K 컨텍스트 + 압축 강도(M=4/6/8/16)별 정확도 곡선 + FibQuantVQCodec 대비 동일 압축률에서 정확도 비교.
- **구현 난이도**: medium
- **우선순위**: 2

### 아이디어 C-2: EchoKVInterLayerSimilarityResidualCodec (EchoKV 레이어 간 유사성 기반 잔차 재구성 코덱)
- **가설**: 기존 저랭크 압축(LRKV, LaProx 등)이 비가역 파라미터 변환에 의존해 메모리가 충분할 때 풀-프리시전 추론으로 전환이 불가능한 유연성 결여 문제를, EchoKV(2603.22910)의 "레이어 간·레이어 내 어텐션 헤드 유사성을 활용해 부분 KV 부분집합에서 잔차 KV 성분을 경량 네트워크로 재구성 + 표준/압축 추론 간 온-디맨드 전환" 원리를 구현하면, 압축 모드와 표준 모드 간 동적 전환으로 메모리 예산이 변하는 에이전틱 워크로드에서 accuracy-preserving을 유지하면서 메모리 효율을 높일 수 있다. 이전 C 기법 전체는 단방향 압축(압축 후 복원 불가 또는 복원 시 재계산 필요)이었다.
- **접근 방법**:
  1. `EchoKVInterLayerResidualCodec` 클래스 (`src/cache/echoky_interlayer_residual_codec.py`): `CompressionCodec` 인터페이스 구현
  2. **레이어 간 KV 유사성 프로파일링 (오프라인 단계)**:
     - 보정 데이터에서 인접 레이어 쌍 `(l, l+1)`의 KV 텐서 코사인 유사도 행렬 계산.
     - 유사도 높은 레이어 쌍을 "공여-수신(donor-recipient)" 관계로 클러스터링: `layer_similarity_graph`.
     - 결과: `configs/echoky_layer_similarity_graph.yaml` 저장.
  3. **잔차 재구성 경량 네트워크**:
     - 공여 레이어 `l`의 KV에서 수신 레이어 `l+1`의 KV를 근사하는 경량 MLP: `KV_approx_l+1 = ResidualNet_l(KV_l) + residual_l+1`. `ResidualNet_l`: 2층 MLP, 입력/출력 차원 `d_kv`, 은닉 차원 `d_kv/4`.
     - 학습: 1 A100 GPU-시간 (7B 모델 기준, EchoKV 원논문 기반). 7B 모델에 대해 ~100 GPU-시간 이하의 파인튜닝 예산.
     - 저장: `configs/echoky_residual_nets/layer_{l}.pt`.
  4. **온-디맨드 전환 메커니즘**:
     - **표준 모드**: 모든 레이어의 KV를 FP16으로 유지. `EchoKVResidualCodec.compress_mode = False`.
     - **압축 모드**: 공여 레이어의 KV만 FP16으로 저장하고 수신 레이어의 KV를 `ResidualNet`으로 온-디맨드 재구성. 재구성 오버헤드: 레이어당 MLP forward pass (< 0.1ms/레이어).
     - **전환 트리거**:
       - 압축 활성화: KV 풀 점유율 > `compress_trigger_threshold`(기본 0.75).
       - 압축 비활성화: KV 풀 점유율 < `decompress_trigger_threshold`(기본 0.50).
       - `CacheTTLAdaptiveTTLScheduler(A-3)` 연동: TTL 남은 시간 < `compress_trigger_ms` 시 자동 압축 모드 전환.
  5. **CacheTTL TTL 보존 + EchoKV 압축 전환 하이브리드**:
     - 도구 호출 간 KV TTL 보존(A-3): 도구 실행 대기 중 KV를 TTL 동안 보존.
     - TTL 만료 임박 시 EchoKV 압축 모드 전환: KV 메모리 점유를 줄이면서 TTL 보존 기간을 사실상 연장.
     - TTL-압축 하이브리드 보존: 도구 호출 실행 시간이 예측보다 길어질 때 압축으로 메모리를 확보하면서 세션 KV를 유지.
  6. **이전 C 기법과의 차별점**:
     - LRKVSharedFullRankHeadResidualCodec(05-20 C-2): 사전학습 시 공유 풀랭크 + 헤드별 저랭크 잔차 아키텍처 (학습 시점 구조 변경 필요).
     - KVServeBayesianMixedCompressionSelector(05-21 C-2): Bayesian 탐색으로 혼합 전략 최적화 (전략 선택 메타-최적화).
     - CompactAttentionBlockUnionCodec(05-21 C-1): 청크드 프리필 블록-스파스 마스크 → GQA-aware 블록 테이블 변환 (청크드 프리필 특화).
     - EchoKVInterLayerResidualCodec: **레이어 간 유사성 기반 잔차 재구성 + 표준/압축 모드 온-디맨드 전환** — 운용 중 모드 전환 가능 + 잔차 재구성 방식 모두 이전 어느 C 기법에도 없었다.
- **예상 효과**: 메모리 −35~55% (압축 모드 활성화 시, EchoKV 원논문 다양한 압축 비율 기준), accuracy delta ±0.8% (LongBench + RULER 벤치마크, 원논문 기준), 온-디맨드 전환 오버헤드 < 1ms (MLP forward pass 레이어당)
- **accuracy-preserving 근거**:
  (1) EchoKV 원논문(2603.22910)에서 LongBench와 RULER 벤치마크에 걸쳐 다양한 압축 비율에서 기존 방법 대비 일관된 정확도 우위를 실험적으로 검증.
  (2) 레이어 간 KV 유사성이 높은 레이어 쌍에만 잔차 재구성을 적용하므로, 유사도가 낮은 레이어는 압축 없이 FP16으로 유지해 모델 전반의 정확도 손실을 최소화.
  (3) 온-디맨드 전환: 메모리 예산이 충분할 때는 표준 모드(압축 없음)로 동작 → accuracy delta = 0. 압축 모드에서만 정확도 영향 발생.
  (4) `compress_trigger_threshold=0.75` 기본값: KV 풀 75% 이상 사용 시에만 압축 모드 활성화 → 대부분의 요청은 표준 모드로 처리.
  검증: WikiText-2 perplexity ±1% (표준/압축 모드 각각) + LongBench 8개 서브태스크 + RULER 벤치마크 + 모드 전환 전후 perplexity 변화 측정 + 온-디맨드 전환 레이턴시 측정.
- **구현 난이도**: medium
- **우선순위**: 2

### 아이디어 C-3: DapQPositionAwarePseudoQueryEvictionCodec (DapQ 위치-인식 유사 쿼리 기반 KV 퇴거 코덱)
- **가설**: 기존 KV 퇴거 방법들이 프리필 단계의 어텐션 패턴으로 토큰 중요도를 추정해 실제 디코딩 단계 쿼리와의 불일치(query drift)로 중요 토큰이 잘못 퇴거되는 문제를, DapQ(2603.11564)의 핵심 발견 — "유사 쿼리 구성에서 위치 정보(positional information)가 의미 정보(semantic content)보다 결정적" — 을 적용해 위치-인식 유사 쿼리(position-aware pseudo queries)로 KV 중요도를 추정하면, NIAH에서 KV 예산 3%만으로 베이스라인 대비 99.5% 성능을 유지할 수 있다. 이전 C 퇴거 기법 중 LookaheadKV(05-15에 등재, 미래 패턴 예측), SpecAttnVerificationGuidedKVSparseCodec(05-20, 검증 로짓 기반)은 모두 의미 정보 또는 attention 로짓 기반이었으며, "위치 정보 우위 원칙"을 퇴거 결정에 적용한 기법이 없었다.
- **접근 방법**:
  1. `DapQPositionAwareEvictionCodec` 클래스 (`src/cache/dapq_position_aware_eviction_codec.py`): `CompressionCodec` 인터페이스 구현
  2. **위치-인식 유사 쿼리 생성**:
     - 현재 디코딩 위치 `pos_decode`를 기반으로 위치-인식 유사 쿼리 `q_pseudo` 생성:
       - 위치 임베딩(RoPE)을 현재 디코딩 위치에 맞게 회전시킨 "위치-인식 쿼리 벡터": `q_pseudo = RoPE(pos_decode, q_template)`. `q_template`: 레이어별 평균 쿼리 벡터 (오프라인 보정 단계에서 100 시퀀스 평균).
       - 의미 정보 최소화: `q_template`을 의미와 무관한 단위 벡터로 대체 가능 — DapQ의 발견에 따르면 의미 정보 제거가 정확도를 오히려 유지.
     - 생성 오버헤드: RoPE 회전 + 벡터 내적 < 0.05ms/레이어.
  3. **KV 중요도 점수 계산**:
     - 각 KV 토큰 `k_i`에 대해 유사 쿼리와의 어텐션 점수 계산: `importance(k_i) = softmax(q_pseudo · K)[i]`.
     - 배치 처리: 전체 K 텐서와 `q_pseudo`의 행렬-벡터 곱으로 일괄 계산 (O(seq_len × d_k) 연산).
     - **의미 점수 비활성화**: 기존 어텐션 점수 기반 방법의 `q_current · K` 대신 `q_pseudo · K`만 사용.
  4. **예산 기반 KV 선택**:
     - `budget_ratio`: 유지할 KV 비율 (기본 0.30 = 상위 30% KV 유지). YAML 외부화.
     - `importance(k_i)` 상위 `budget_ratio` 비율 KV 유지, 나머지 퇴거.
     - 동적 예산 조정: KV 풀 점유율 > `high_pressure_threshold`(기본 0.80) 시 `budget_ratio=0.15`로 공격적 퇴거. 점유율 < 0.50 시 `budget_ratio=0.50`으로 보수적 퇴거.
  5. **Activity B 비연속 세그먼트 재사용 가능성 평가 통합**:
     - `SessionAwareTurnLevelSegmentCache(B-1)`의 세그먼트 재사용 점수에 DapQ 위치-인식 원칙 적용: 세그먼트의 위치 범위가 현재 디코딩 위치에 가까울수록 재사용 가능성이 높다.
     - `position_reuse_score(segment, current_pos) = exp(-|segment.center_position - current_pos| / decay_factor)`.
  6. **이전 C 기법과의 차별점**:
     - SpecAttnVerificationGuidedKVSparseCodec(05-20 C-1): 자기-추측 디코딩 검증 로짓에서 KV 중요도 추출 (디코딩 단계 attachment 방식, 의미 기반).
     - GlobalRetentionGateEvictionCodec(05-16, 기구현): 레이어·헤드·모달리티 간 전역 경쟁 퇴거 점수 (전역 경쟁 방식).
     - LookaheadKV(05-15): 미래 생성 토큰 패턴으로 현재 KV 중요도 예측 (미래 예측 기반, 의미 정보 활용).
     - DapQPositionAwareEvictionCodec: **위치 정보(RoPE 기반 위치-인식 유사 쿼리)가 의미 정보보다 결정적이라는 DapQ 원칙 적용 — 의미 임베딩을 제거하고 위치 기반 유사 쿼리만으로 KV 중요도 추정하는 최초의 퇴거 정책**.
- **예상 효과**: 메모리 −70~97% (DapQ 원논문 NIAH에서 KV 예산 3% 달성, 실용 목표 30~50% 예산으로 더 안전한 설정), accuracy delta ±0.5% (NIAH 99.5% 성능 보존 + LongBench 기준)
- **accuracy-preserving 근거**:
  (1) DapQ 원논문(2603.11564)에서 NIAH 테스크 KV 예산 3%에서 베이스라인 대비 99.5% 성능 유지를 실험적으로 입증 — 위치-인식 유사 쿼리가 의미 기반 방법보다 정확도 보존에 우월함이 검증됨.
  (2) 위치 임베딩(RoPE)이 어텐션 패턴의 구조적 특성(어떤 위치의 토큰이 중요한지)을 반영하므로, 의미-독립적 위치-인식 쿼리가 실제 디코딩 쿼리를 더 잘 근사한다는 DapQ의 이론적 근거.
  (3) Lookahead Q-Cache와의 비교: DapQ는 의미 정보를 제거해도 정확도가 유지됨을 입증 → 의미 정보 제거가 오히려 query drift를 줄이는 효과.
  (4) 동적 예산 조정: 메모리 압박이 낮을 때 `budget_ratio=0.50` (상위 50% 유지)으로 보수적 설정 → accuracy delta 추가 축소.
  검증: WikiText-2 perplexity ±1% + NIAH(32K/64K/128K 컨텍스트) + LongBench 8개 서브태스크 + 예산 비율(3%/15%/30%/50%)별 정확도 곡선 + 위치-인식 쿼리 vs. 의미 쿼리 대조 실험.
- **구현 난이도**: low
- **우선순위**: 1

     - **Step 6 (VQKV 장기 세그먼트 압축, C-1)**: TTL 만료된 세션 세그먼트를 VQKV로 압축 보존 → 장기 세션 히스토리를 최소 메모리로 유지.
  3. **복합 감소 효과 분석**:

### 아이디어 Cross-2: DapQPositionAwareSessionSegmentDualReductionPipeline (B+C) — DapQ 위치-인식 퇴거 + 세션 비연속 세그먼트 재사용 이중 감소 파이프라인
- **조합 근거**: `DapQPositionAwareEvictionCodec(C-3)`의 위치-인식 KV 중요도 평가 원칙이 `SessionAwareTurnLevelSegmentCache(B-1)`의 세그먼트 재사용 가능성 평가에 직접 적용 가능하다 — "현재 디코딩 위치에 가까운 세그먼트는 재사용 가능성이 높다"는 위치 기반 가설이 B의 비연속 세그먼트 선택 기준이 된다. B-1이 turn-level 세그먼트를 보존하고 C-3이 위치 기반으로 중요 KV만 선택하면, B+C 통합이 "어떤 세그먼트를 유지할지(B)"와 "유지된 세그먼트 내 어떤 KV를 압축할지(C)"를 동일한 위치-인식 원칙으로 일관성 있게 결정한다.
- **구체 설계**:
  1. `DapQSessionSegmentDualPipeline` 모듈 (`src/cache/dapq_session_segment_dual_pipeline.py`)
  2. **통합 처리 흐름**:
     - **Step 1 (세션 세그먼트 조회, B-1)**: `SessionAwareTurnLevelSegmentCache.get_session_segments(session_id)` → 이전 턴 세그먼트 목록.
     - **Step 2 (위치-인식 세그먼트 중요도 평가, C-3 원칙)**: 각 세그먼트에 대해 `position_reuse_score(segment, current_decode_pos)` 계산. 상위 `segment_keep_ratio`(기본 0.50) 세그먼트 선택.
     - **Step 3 (선택된 세그먼트 내 KV 중요도 평가, C-3)**: 선택된 세그먼트의 KV에 대해 DapQ 위치-인식 유사 쿼리로 `importance(k_i)` 계산. 상위 `kv_budget_ratio`(기본 0.30) KV 유지.
     - **Step 4 (비선택 세그먼트 + 비선택 KV 처리)**: 비선택 세그먼트: VQKV 압축 후 장기 보존. 비선택 KV: 즉시 퇴거.
     - **Step 5 (최종 KV 집합 블록-union 구성)**: 선택된 세그먼트의 선택된 KV를 BlockUnionTable로 통합 → 표준 어텐션 커널 투입.
  3. **B+C 이중 감소 효과**:
     - B-1 단독: 세션 세그먼트 보존으로 히트율 향상 (메모리 점유 증가).
     - C-3 단독: 전체 KV 중 30% 유지 (메모리 −70%).
     - B+C 결합: 세션 세그먼트 히트율 향상 + 위치 기반 중요 KV만 선택 = 히트율 향상과 메모리 절감 동시 달성.
  4. **설계 일관성**: B와 C 모두 동일한 "위치-인식" 원칙으로 결정 → 세그먼트 선택(B)과 KV 선택(C)이 일관된 중요도 기준을 공유해 각자 독립 결정 시 발생하는 중요도 불일치 문제를 방지.
- **예상 복합 효과**: 처리량 +25~40% (세션 턴-레벨 히트 + 위치-인식 KV 선택 어텐션 가속), 메모리 −60~75% (세그먼트 선택 × KV 예산 곱연산 감소), accuracy delta ±0.5% 이내 (DapQ 위치-인식 원칙의 정확도 보존 + 세그먼트 위치 기반 선택의 중요 KV 보존 보장)
- **구현 난이도**: medium
- **우선순위**: 1

## planner에게 전달할 요청사항

1. **Activity C 구현 시 accuracy-preserving 검증 방법 명시 필수**:
   - C-3 (DapQPositionAwareEvictionCodec): WikiText-2 perplexity ±1% + NIAH (32K/64K/128K 컨텍스트, KV 예산 3%/15%/30%/50%) + LongBench 8개 서브태스크 + 위치-인식 쿼리 vs. 의미 쿼리 대조 실험 필수.
   - C-2 (EchoKVInterLayerResidualCodec): 표준/압축 모드 각각 WikiText-2 perplexity 측정 + LongBench + RULER + 모드 전환 레이턴시 측정.
   - C-1 (VQKVMultiCodebookCodec): WikiText-2 perplexity ±1% + LongBench + NIAH 128K + 압축 강도(M=4/6/8/16)별 정확도 곡선 + FibQuantVQCodec 대비 비교 필수.

2. **이번 사이클 측정 지표**:
   - Inference Throughput: PPD append-prefill 라우팅으로 Turn 2+ 처리량 +20% 이상 목표.
   - KV Cache Memory Reduction: DapQ 30% KV 예산 + EchoKV 압축으로 −50% 이상 목표.
   - Non-Contiguous Cache Hit Rate: SessionAwareTurnLevelSegmentCache 세션 내 히트율 측정 (세션 내 vs. cross-session 비율 분리 측정).
   - Compression Accuracy Delta: C-3 ±1% 이내 (필수, NIAH 포함).
   - Scheduling Overhead: A-1 프리필 유형 분류 오버헤드 TTFT +2% 이내.

3. **구현 우선순위**: C-3 → Cross-2 → A-1 → A-3 → C-2 → A-2 → C-1 → B-1 → Cross-1 순서.

4. **C-3 구현 시**: `src/cache/dapq_position_aware_eviction_codec.py` 신규 생성. `CompressionCodec` 인터페이스 구현. RoPE 회전 기반 위치-인식 유사 쿼리 생성: `q_pseudo = RoPE(pos_decode, q_template)` (torch 기반). 배치 중요도 계산: `importance = softmax(q_pseudo @ K.T)`. `budget_ratio` 동적 조정: KV 풀 점유율 연동. **accuracy-preserving 검증 필수**: 위 1항 C-3 검증 방법 적용. 위치-인식 쿼리 vs. 평균 쿼리 A/B 비교.

5. **B-1 구현 시**: `src/cache/session_turn_level_segment_cache.py` 신규 생성. `CacheStore` 인터페이스 상속. 세그먼트 키: `(content_hash, session_id, turn_id)` 3-tuple. `TurnSegmentIndex` 자료구조. `session_priority_lru`: 세션 내 세그먼트 퇴거 우선순위 낮음(더 오래 보존). `PPDAppendFullPrefillClassifier(A-1)` 연동: append-prefill 판정 시 `get_session_segments()` 호출. DapQ `position_reuse_score()` 통합.
