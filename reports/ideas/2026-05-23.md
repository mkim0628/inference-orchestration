## Activity A 아이디어

### 아이디어 A-1: KaretoMultiObjectiveParetoStorageTuner (Kareto 다목적 파레토 스토리지 구성 최적화기)
- **가설**: KV 캐시를 외부 스토리지 계층으로 오프로딩할 때 워크로드 변화에 따라 비용·처리량·지연의 세 목표가 구조적으로 상충하는 문제를, Kareto(2603.08739)의 핵심 원리 — 스토리지 구성 공간을 수익 체감 가이드 가지치기(diminishing-return-guided pruning)로 탐색해 파레토 프런티어를 근사하고 그룹별 에빅션 정책을 세밀하게 조정 — 를 `src/scheduler/` 레이어에 구현하면, 워크로드 변화 시 실시간으로 스토리지 구성을 재조정해 고정 구성 대비 처리량을 최대 9.3% 향상, 지연을 최대 58.3% 감소, 비용을 최대 20.2% 절감하는 "적응형 3-티어 KV 스토리지 구성 최적화기"를 달성할 수 있다. 과거 A-1 KVServeBayesianScheduler(05-21)가 압축 전략 공간(양자화 × 퇴거 × 근사)을 Bayesian 탐색으로 최적화했다면, 이 기법은 "각 스토리지 계층의 용량 배분·에빅션 정책·비용" 구성 공간을 파레토 가지치기로 최적화하는 직교적 설계 축이다.
- **접근 방법**:
  1. `KaretoStorageTuner` 클래스 (`src/scheduler/kareto_storage_tuner.py`): `BaseScheduler` 상속
  2. **다목적 최적화 공간 정의**:
     - 스토리지 구성 파라미터: `{gpu_capacity_gb: [16, 24, 40, 80], dram_capacity_gb: [64, 128, 256, 512], ssd_capacity_tb: [1, 2, 4, 8], eviction_policy: [LRU, LFU, H2O, SnapKV], kv_block_size_tokens: [16, 32, 64, 128]}`. 조합: 4×4×4×4×4 = 1024개 후보.
     - 목표 벡터: `(throughput_tps, latency_p99_ms, cost_per_token)` — 3차원.
     - **비지배 집합(non-dominated set)**: 세 목표 모두에서 어느 다른 구성보다 열등하지 않은 구성들의 집합.
  3. **수익 체감 가이드 가지치기 (Diminishing-Return-Guided Pruning)**:
     - 탐색 순서 결정: 예상 개선량(`expected_improvement = delta_throughput / delta_cost`)이 큰 파라미터 차원부터 탐색.
     - 가지치기 기준: 특정 파라미터 축에서 개선량이 직전 스텝 대비 `pruning_threshold`(기본 10%) 이하로 수렴하면 해당 축 탐색 조기 종료.
     - 비지배 집합 추적: 탐색된 구성이 기존 비지배 집합의 어느 원소보다 1차원 이상 우월하면 집합에 추가, 기존 피지배 원소 제거.
     - 탐색 오버헤드: 1024개 후보 중 수익 체감 가지치기로 평균 50~100개만 실제 측정 (90% 후보 가지치기).
  4. **그룹별 세밀 에빅션 정책 (Fine-Grained Group Eviction)**:
     - KV 블록을 에빅션 패턴별 그룹으로 분류: `eviction_group = classify_block(access_pattern, block_size, tier_position)`. 그룹 분류: {hot_recent, warm_periodic, cold_rare, session_agent}.
     - 각 그룹에 독립적 에빅션 정책 적용: hot_recent → LRU, warm_periodic → LFU, cold_rare → SnapKV 점수 기반, session_agent → TTL(CacheTTLAdaptiveTTLScheduler 연동).
     - 그룹 분류 오버헤드: KV 블록 메타데이터(`last_access_ts, access_count, session_id`)에서 O(1) 규칙 기반 분류.
  5. **워크로드 변화 감지 및 재조정**:
     - `WorkloadDriftDetector` (`src/scheduler/workload_drift_detector.py`): 최근 `window_size`(기본 1000) 요청의 `{context_length_distribution, batch_size_distribution, cache_hit_rate}` 분포를 EMA로 추적.
     - 드리프트 감지: Kullback-Leibler 발산이 `kl_drift_threshold`(기본 0.1) 초과 시 파레토 재탐색 트리거.
     - 재탐색 범위: 전체 재탐색 대신 이전 비지배 집합 근방(±10% 파라미터 범위)만 재탐색 (인크리멘털 업데이트).
  6. **KVDriveAttentionPipelineScheduler(05-19 A-1)와의 통합**:
     - KVDrive가 3계층 I/O-컴퓨트 오버랩 파이프라인을 실행하고, Kareto가 3계층의 용량·에빅션 정책을 최적화하는 "KVDrive 실행 + Kareto 구성" 분리 아키텍처.
     - `KVTierRegistry(05-19)` 계층 결정 경계값(`attn_hbm_threshold`, `attn_dram_threshold`)을 Kareto의 파레토 최적 구성으로 동적 갱신.
  7. **이전 A 기법과의 차별점**:
     - KVServeBayesianScheduler(05-21 A-1): 압축 전략 공간(알고리즘 선택 문제) Bayesian 탐색.
     - KVDriveAttentionPipelineScheduler(05-19 A-1): 계층 간 I/O-컴퓨트 오버랩 파이프라인 실행.
     - KaretoStorageTuner: **스토리지 계층 구성 공간(용량·에빅션·비용) 파레토 가지치기 최적화** — 알고리즘 선택이 아닌 계층 구성 파라미터 최적화라는 완전히 다른 설계 축.
- **대상 환경**: 단일 노드 / 멀티 노드 양쪽
- **멀티 노드 고려사항**: 클러스터 전체의 KV 스토리지 구성을 노드별로 독립 최적화하되, 클러스터 수준 비용 집계(노드 간 KV 전송 비용 포함)를 파레토 목표의 비용 항에 반영. InfiniBand 200Gbps 환경에서 DRAM→DRAM 전송 비용을 `cost_per_token`에 포함해 "로컬 SSD 보관 vs. 원격 DRAM 전송" 트레이드오프를 파레토 프런티어에서 자동 균형.
- **예상 효과**: 처리량 +9.3% (Kareto 원논문 기준), 지연 −58.3% (최대, 지연 최적화 모드), 비용 −20.2% (비용 최적화 모드), Scheduling overhead TTFT +3% 이내 (파레토 탐색 오프라인, 런타임: 그룹 분류 O(1) + 에빅션 정책 적용)
- **구현 난이도**: medium
- **우선순위**: 3

### 아이디어 A-2: CPDWarmColdHitRatePredictiveRouterScheduler (CPD 히트율 예측 기반 Warm/Cold 경로 분기 스케줄러)
- **가설**: Together AI CPD의 핵심 통찰 — cold prefill(캐시 미스 대형 프리필)이 warm 요청(캐시 히트 예상)의 fast path를 차단하는 구조적 병목 — 을, P/D 분리 없이 단일 노드 또는 소규모 멀티 노드 환경에서도 "요청의 예측 캐시 히트율로 warm/cold 경로를 소프트하게 분기"하는 경량 예측 라우터로 구현하면, 대형 cold prefill이 warm 요청 TTFT를 오염시키는 tail latency 문제를 2-노드 분리 아키텍처 없이 완화할 수 있다. 이전 모든 A 스케줄러(PPDAppendFullPrefillClassifier 05-22 A-1, AMPDLazySegmentFetchScheduler 05-18 A-1, HMAMultiConnectorScheduler 05-17 A-1 등)는 프리필 유형 분류(append/full), 지연 페치(pull-on-demand), 커넥터 선택 등의 방향이었으며 "예측 캐시 히트율 기반 warm/cold 소프트 분기"를 도입한 기법이 없었다.
- **접근 방법**:
  1. `CPDWarmColdHitRateRouter` 클래스 (`src/scheduler/cpd_warm_cold_hit_router.py`): `BaseScheduler` 상속
  2. **경량 히트율 예측기 (Lightweight Hit Rate Predictor)**:
     - 요청 수신 시 `predict_hit_rate(request) → float` 계산. 입력: `{prefix_hash, context_length, session_age, top_k_segment_match_ratio}`.
     - 예측 모델: 선형 회귀 (4개 피처 × 1개 출력, 온라인 학습). 저장: `configs/cpd_hit_rate_predictor_weights.yaml`. 추론 오버헤드: < 0.01ms.
     - 온라인 갱신: 실제 히트 결과(`1`=히트, `0`=미스)로 SGD(학습률 0.01) 업데이트. 히트율 예측 오차 EMA 추적.
     - `high_hit_threshold`(기본 0.70): 예측 히트율 ≥ 0.70이면 "warm" 요청으로 분류.
     - `low_hit_threshold`(기본 0.25): 예측 히트율 < 0.25이면 "cold" 요청으로 분류. 중간: "neutral" 경로.
  3. **Warm/Cold/Neutral 3경로 소프트 분기**:
     - **Warm 경로**: 배치 큐의 앞자리에 배치 (우선 처리). 컨텍스트 길이 제한: 50K 토큰 이하 우선. 배치 슬롯: 전체 배치의 `warm_slot_ratio`(기본 0.60) 예약.
     - **Cold 경로**: 배치 큐의 뒷자리. 독립 cold 배치로 처리 (warm 요청과 섞지 않음). Cold 배치 전용 슬롯: `cold_slot_ratio`(기본 0.30).
     - **Neutral 경로**: 남은 슬롯(`neutral_slot_ratio`=0.10)에 배치. 히트율 업데이트 후 warm/cold 재분류.
     - 슬롯 비율 YAML 외부화. 큐 압박(`queue_depth > queue_pressure_threshold`) 시 warm_slot_ratio 조정(cold 요청 수용 증가).
  4. **Warm 배치 내 캐시 지역성 극대화**:
     - Warm 배치 내 요청들을 `prefix_similarity_score`로 재정렬: `sort_by = prefix_lcp_length(req_a, req_b)`. 유사 접두사 요청끼리 같은 배치로 묶어 KV 재사용 극대화.
     - `DualMapDualHashRouter(05-22 A-2)`의 이중 해시-링과 연동: Warm 요청은 DualMap이 캐시 어피니티 기반으로 인스턴스 선택.
  5. **Cold 배치 격리로 Warm TTFT 보호**:
     - Cold 배치 실행 중 warm 요청 수신 시 cold 배치를 `yield_to_warm_threshold`(기본 100ms 처리 후) 이후 중단 가능: CUDA Preemption 신호 (`torch.cuda.synchronize()` + 배치 재스케줄).
     - Cold 배치 중단 → warm 배치 삽입 → cold 배치 재개 → TTFT SLO 유지.
  6. **이전 A 기법과의 차별점**:
     - PPDAppendFullPrefillClassifier(05-22 A-1): append/full 프리필 유형 분류로 decode 노드 로컬 처리 (유형 분류 기반).
     - KVServeBayesianScheduler(05-21 A-1): 압축 전략 공간 Bayesian 탐색.
     - CONCURCongestionBasedAgentAdmissionScheduler(05-20 A-1): KV 풀 혼잡도 기반 어드미션 제어.
     - CPDWarmColdHitRateRouter: **예측 캐시 히트율 기반 warm/cold 3경로 소프트 분기 + warm 배치 내 캐시 지역성 최대화 + cold 격리로 TTFT 보호** — 히트율 예측을 스케줄링 신호로 사용하는 것 자체가 이전 어느 A 기법에도 없었다.
- **대상 환경**: 단일 노드 / 멀티 노드 양쪽
- **멀티 노드 고려사항**: 멀티 노드에서 warm/cold 분기 결정을 마스터 라우터에서 수행 후 warm 요청은 "warm 노드" 풀, cold 요청은 "cold 노드" 풀로 배치 — CPD 3-노드 아키텍처의 소프트웨어 근사. DualMapDualHashRouter와 결합해 warm 노드 풀 내에서 캐시 어피니티 기반 인스턴스 선택.
- **예상 효과**: 처리량 +25~35% (warm 배치 처리 우선화 + cold 격리로 배치 효율 향상), Warm 요청 TTFT −40~60% (cold prefill 오염 제거), Scheduling overhead TTFT +2% 이내 (히트율 예측: 선형 모델 < 0.01ms)
- **구현 난이도**: medium
- **우선순위**: 2

### 아이디어 B-1: CLCPositionalBiasThresholdGatedSegmentReuse (CLC 위치 편향 임계 게이트 기반 선택적 비연속 세그먼트 재사용)
- **가설**: 2603.20218이 규명한 위치 독립 재사용의 정확도 한계 — "임의 위치에서 KV를 직접 재사용하면 위치 인코딩 불일치로 심각한 정확도 저하 발생" — 를, 비연속 세그먼트 재사용 전에 "위치 편향 크기(positional bias magnitude)"를 측정하는 경량 게이트로 구현하면, 위치 편향이 임계값 이하인 세그먼트는 직접 재사용하고 임계값을 초과하는 세그먼트에만 AdapShot RoPE 재인코딩(05-18 B-1 기구현)을 적용하는 "선택적 위치 재인코딩"이 가능하며, 전체 재인코딩 대비 오버헤드를 최소화하면서 정확도 보존과 비연속 히트율을 동시에 달성할 수 있다. 이전 B 기법들(AMPDAdapShotLazyLoadPipeline 05-18 B-1, BlockUnionNonContiguousReuseIndex 05-21 B-1 등)은 재인코딩을 항상 적용하거나 전혀 적용하지 않는 이분법적 설계였으며, "위치 편향 크기를 측정해 재인코딩 필요성을 온라인으로 판단"하는 선택적 게이트 메커니즘이 없었다.
- **접근 방법**:
  1. `CLCPositionalBiasGatedSegmentCache` 클래스 (`src/cache/clc_positional_bias_gated_segment_cache.py`): `CacheStore` 인터페이스 상속
  2. **위치 편향 크기 측정 (Positional Bias Magnitude Estimator)**:
     - 세그먼트의 원본 위치 범위 `[pos_orig_start, pos_orig_end]`와 현재 컨텍스트 내 목표 위치 범위 `[pos_target_start, pos_target_end]`를 비교.
     - **위치 편향 측정값** `ΔPos`:
       ```
       ΔPos = |pos_target_start - pos_orig_start| / max_context_length
       ```
       정규화된 위치 이동량 (0~1 범위).
     - **RoPE 왜곡 예상값** `rope_distortion`: RoPE 주파수 구성 기반 위치 이동에 따른 어텐션 점수 왜곡 상한 추정.
       ```
       rope_distortion = max_freq × ΔPos_abs / d_model
       ```
       `max_freq`: RoPE 최대 주파수 (모델별 상수), `ΔPos_abs`: 절대 위치 이동 거리.
     - 측정 오버헤드: 정수 뺄셈 + 나눗셈 2회 (< 0.001ms/세그먼트).
  3. **선택적 재인코딩 게이트**:
     - `bias_threshold`(기본 0.15): `ΔPos ≤ bias_threshold`이면 "직접 재사용 안전" → AdapShot 재인코딩 스킵.
     - `bias_threshold < ΔPos ≤ rope_distortion_threshold`(기본 0.40): "부분 재인코딩" → 세그먼트 내 처음 N 레이어만 재인코딩 (`partial_reencoding_layers: [0, N//2]`).
     - `ΔPos > rope_distortion_threshold`: "전체 재인코딩 필수" → AdapShot 전체 재인코딩 적용.
     - 임계값 자동 교정: 정확도 측정(perplexity delta)으로 `bias_threshold`를 오프라인 교정 데이터 기반으로 조정 (`configs/clc_bias_gate_thresholds.yaml`).
  4. **안전 재사용 조건 데이터베이스 구축**:
     - 2603.20218의 실험 프레임워크를 `tests/unit/test_positional_bias_gate.py`에 구현:
       - 위치 이동 거리별(ΔPos = 0.0, 0.1, 0.2, ..., 1.0) 재사용 정확도(perplexity delta) 측정.
       - 크로스-청크 어텐션 누락 비율별 품질 저하 측정.
       - 결과를 `configs/clc_safe_reuse_conditions.yaml`로 저장 → 런타임 게이트 임계값 캘리브레이션에 사용.
  5. **BlockUnionNonContiguousReuseIndex(05-21 B-1)와의 통합**:
     - `BlockUnionNonContiguousReuseIndex.get_block_union()`이 세그먼트 히트 목록을 반환한 후, 각 히트 세그먼트에 `CLCPositionalBiasGatedSegmentCache.check_bias(segment_meta) → ReencodingPolicy`를 적용해 재인코딩 정책을 결정.
     - 직접 재사용 세그먼트: block-union 인덱스에 즉시 포함.
     - 재인코딩 필요 세그먼트: AMPDAdapShotLazyLoadPipeline(05-18 B-1) 재인코딩 큐로 전달.
  6. **이전 B 기법과의 차별점**:
     - AMPDAdapShotLazyLoadPipeline(05-18 B-1): 세그먼트 확정 후 비동기 로드 + AdapShot RoPE 재인코딩 항상 적용.
     - BlockUnionNonContiguousReuseIndex(05-21 B-1): block-union 표현 변환 + RoPE 재인코딩 필요 여부 이분법적 판단(원본 위치 일치/불일치).
     - SessionAwareTurnLevelSegmentCache(05-22 B-1): 세션 ID + 턴 ID 기반 turn-level 비연속 세그먼트 관리.
     - CLCPositionalBiasGatedSegmentCache: **위치 편향 크기를 연속값으로 측정해 직접 재사용/부분 재인코딩/전체 재인코딩을 3단계로 구분하는 선택적 게이트** — 2603.20218이 규명한 정확도 한계 메커니즘을 직접 구현하는 최초의 B 기법.
- **예상 효과**: 비연속 히트율 +20~35% (직접 재사용 허용 세그먼트 비율 증가, ΔPos ≤ 0.15인 세그먼트의 즉시 재사용), 재인코딩 오버헤드 −40~60% (불필요한 전체 재인코딩 제거), TTFT −25~40% (재인코딩 스킵된 세그먼트의 즉각 처리)
- **구현 난이도**: low
- **우선순위**: 2

## Activity C 아이디어

### 아이디어 C-1: RuntimeCertifiedBoundedErrorQuantizedAttentionCodec (Runtime-Certified 런타임 오류 경계 인증 양자화 코덱)
- **가설**: 기존 모든 KV 캐시 양자화 방법이 accuracy-preserving을 오프라인 벤치마크 결과로만 경험적으로 검증하고 런타임에 오류 경계를 보장하지 못하는 한계를, Runtime-Certified(2605.20868)의 핵심 메커니즘 — (1) INT8 Key + INT4 Value GPU 저장, FP16 원본 RAM 보존, (2) 이중 항 오류 분해(어텐션 분포 왜곡 + 값 재구성 오류)로 헤드별·스텝별 오류 상한 온라인 계산, (3) 오류 상한이 임계값 초과 시 FP16 폴백 사다리 — 를 `src/cache/` 레이어에 구현하면, Activity C의 핵심 제약 "압축 정확도 delta ±1% 이내"를 경험적 검증에서 **수학적 런타임 보장**으로 격상할 수 있으며, LLaMA 3.1-8B 기준 128K 컨텍스트에서 FP16 밀집 어텐션과 노이즈 이내 동등 품질을 달성할 수 있다. 이전 23개 사이클의 모든 C 기법(DapQPositionAwareEvictionCodec, EchoKVInterLayerResidualCodec, VQKVMultiCodebookCodec, CompactAttentionBlockUnionCodec, SpecAttnVerificationGuidedKVSparseCodec 등)은 accuracy-preserving을 경험적 벤치마크로만 검증했으며, 런타임 오류 경계를 수학적으로 계산하고 폴백을 결정하는 인증 메커니즘이 없었다.
- **접근 방법**:
  1. `RuntimeCertifiedQuantizedAttentionCodec` 클래스 (`src/cache/runtime_certified_quant_codec.py`): `CompressionCodec` 인터페이스 구현
  2. **계층화 KV 캐시 구조**:
     - **GPU HBM**: INT8 Key + INT4 Value (압축 저장). `key_int8[layer][head][token] = quantize_int8(key_fp16)`. `value_int4[layer][head][token] = quantize_int4(value_fp16)`.
     - **시스템 RAM**: FP16 원본 Key + Value 보존 (`key_fp16_backup, value_fp16_backup`). RAM 전송: 비동기 H2D/D2H (별도 CUDA Stream).
     - 양자화 파라미터: per-token 동적 스케일 (`scale_k, zero_k, scale_v, zero_v` FP16, token당 저장).
  3. **이중 항 오류 분해 (Two-Term Error Decomposition)**:
     - **항 1 — 어텐션 분포 왜곡**: Key 양자화로 인한 어텐션 소프트맥스 분포 왜곡 오차:
       ```
       δ_attn = ||softmax(Q·K^T/√d) - softmax(Q·K̃^T/√d)||_∞
       ```
       `K̃`: INT8 복원 Key. 헤드별 상한: `δ_attn_bound = max_q_norm × ||K - K̃||_F / (√d × softmax_min)`.
     - **항 2 — 값 재구성 오류**: Value 양자화 후 어텐션 가중합 오차:
       ```
       δ_value = ||Σ α_i (v_i - ṽ_i)||_F
       ```
       `α_i`: 어텐션 가중치, `ṽ_i`: INT4 복원 Value. 상한: `δ_value_bound = ||α||_1 × max_i ||v_i - ṽ_i||`.
     - **결합 오류 상한**: `error_bound = δ_attn_bound + δ_value_bound` (삼각 부등식).
     - 계산 오버헤드: 행렬 노름 계산 O(seq_len × d) — 디코딩 스텝당 추가 < 0.5ms (CUDA 커널).
  4. **다단계 폴백 사다리 (Multi-Stage Fallback Ladder)**:
     - **레벨 0 (INT8K+INT4V)**: 정상 운영. `error_bound ≤ error_threshold`(기본 0.005 = 0.5% perplexity).
     - **레벨 1 (INT8K+FP16V)**: `error_bound > error_threshold` 시 Value를 RAM에서 FP16으로 즉시 복원. Value 재구성 오류만 제거 → `δ_value_bound = 0`.
     - **레벨 2 (FP16K+FP16V)**: 레벨 1 이후도 `δ_attn_bound > error_threshold/2` 시 Key도 FP16으로 복원. 완전한 FP16 어텐션.
     - **레벨 전환 오버헤드**: RAM→GPU D2H: 32K 컨텍스트 기준 < 2ms (PCIe 4.0 16x). 레벨 전환 빈도 추적: `{fallback_rate_level1, fallback_rate_level2}`를 `results/<exp-name>/metrics.json`에 기록.
     - 폴백 결정 캐싱: 동일 요청의 다음 스텝에서 레벨 전환이 발생했던 헤드는 다음 스텝도 상위 레벨로 선제 적용.
  5. **Activity C 정확도 보증 통합**:
     - `error_threshold` 기본값 0.005 → ±0.5% perplexity delta에 대응 (Activity C 목표 ±1% 이내의 절반으로 보수적 설정).
     - `certified_accuracy_report`: 배치 완료 시 실제 폴백 비율, 오류 경계 분포, 실측 perplexity delta를 자동 생성.
  6. **vLLM HMA 통합 경로**:
     - `vllm_integration/attention_backend_patch.py`에 `RuntimeCertifiedAttentionBackend` 추가. vLLM v0.21.0 HMA DDR 커넥터가 FP16 원본을 RAM에 보존하는 경로를 폴백 사다리의 Level 2 복원 경로로 직접 재활용.
- **예상 효과**: 메모리 −50~65% (INT8K+INT4V 기준 FP16 대비), accuracy delta ±0.5% 수학적 보장 (error_threshold=0.005 설정 기준), FP16 대비 노이즈 이내 동등 품질 (Runtime-Certified 원논문 LLaMA 3.1-8B 128K 컨텍스트 검증 기반)
- **accuracy-preserving 근거**:
  (1) Runtime-Certified 원논문(2605.20868)에서 LLaMA 3.1-8B, PG-19·NIAH·RULER 벤치마크, 128K 컨텍스트에서 FP16 밀집 어텐션과 노이즈 이내 동등 품질을 수학적으로 인증된 오류 경계 하에서 달성함을 검증.
  (2) 이중 항 오류 분해가 어텐션 분포 왜곡(항 1)과 값 재구성 오류(항 2)를 분리 계산하므로, 결합 오류 상한이 실제 오류를 항상 상회하는 보수적 상한(conservative upper bound)임이 수학적으로 증명됨.
  (3) 다단계 폴백 사다리: 오류 상한이 임계값 초과 시 즉시 FP16 복원 → 이론적으로 accuracy delta = 0 복귀 가능. 최악의 경우에도 FP16과 동일한 정확도를 보장.
  (4) `error_threshold = 0.005`는 Activity C 목표 ±1% 이내의 절반으로 설정해 실제 오류가 수학적 상한보다 작은 gap을 고려해도 ±1% 이내 달성을 보장.
  검증: WikiText-2 perplexity ±1% (INT8K+INT4V 모드, 폴백 사다리 활성화 상태) + NIAH (32K/64K/128K 컨텍스트) + RULER 벤치마크 + 실측 폴백 비율(`fallback_rate_level1, level2`) + 오류 경계 분포(헤드별·레이어별) + FP16 대비 정확도 곡선.
- **구현 난이도**: medium
- **우선순위**: 1

### 아이디어 C-2: KVSculptDistillationAdaptiveLayerBudgetCodec (KVSculpt 증류 기반 적응적 레이어 예산 배분 압축 코덱)
- **가설**: "레이어 간 압축 난이도가 최대 100× 차이"라는 KVSculpt(2603.27819)의 발견이 기존 균일 압축 정책의 비효율을 정량화하는 근거를 제공한다 — 균일 예산 배분 시 압축 난이도가 낮은 레이어에 과도한 예산이, 난이도가 높은 레이어에 부족한 예산이 배분되어 전체 accuracy delta가 높은 레이어에 집중된다. KVSculpt의 파일럿 압축 실행으로 레이어별 압축 난이도를 사전 프로파일링하고, L-BFGS Key 최적화 + 최소제곱 Value 최적화의 증류 방식을 난이도 비례 예산 배분에 통합하면, 동일 메모리 예산에서 KL 발산을 기존 방법 대비 3.5~4.1× 감소시키면서 accuracy-preserving을 달성할 수 있다. 이전 모든 C 기법은 레이어 균일 압축(DapQ, EchoKV, VQKV, CompactAttention 모두 레이어별 동일 정책)이었으며, 증류 패러다임 + 레이어별 난이도 비례 예산 배분의 조합이 없었다.
- **접근 방법**:
  1. `KVSculptDistillationCodec` 클래스 (`src/cache/kvsculpt_distillation_codec.py`): `CompressionCodec` 인터페이스 구현
  2. **파일럿 압축 실행 — 레이어별 압축 난이도 프로파일링**:
     - 보정 데이터(50~100 시퀀스)에서 각 레이어에 균일 압축(50% KV 예산)을 적용한 파일럿 실행.
     - 레이어별 압축 난이도 측정: `difficulty(layer_l) = KL_divergence(attn_full_l, attn_compressed_l)`.
     - 결과: `configs/kvsculpt_layer_difficulty_profile.yaml` — 레이어별 KL 발산 값 저장.
     - 프로파일링 오버헤드: GPU-시간 < 5분 (7B 모델 기준, 보정 데이터 50 시퀀스).
  3. **난이도 비례 예산 배분 (Difficulty-Proportional Budget Allocation)**:
     - 레이어별 압축 예산: `budget(layer_l) = total_budget × (1 + γ × normalized_difficulty(l))`.
       - `normalized_difficulty(l) = difficulty(l) / max(difficulty)`. 범위: [0, 1].
       - `γ`(기본 0.5): 난이도 반응 강도. `γ=0` 시 균일 배분.
     - 배분 제약: `Σ_l budget(l) = total_budget` (예산 보존).
     - 고난이도 레이어: 더 많은 KV 유지 (낮은 압축률). 저난이도 레이어: 더 적은 KV 유지 (높은 압축률).
  4. **L-BFGS Key 최적화 (온라인 경량화 버전)**:
     - KVSculpt 원논문의 L-BFGS 최적화를 프리필 단계에 간소화 적용: 각 레이어의 Key 집합 `K_compressed`를 어텐션 출력 KL 발산을 최소화하는 방향으로 L-BFGS 5-10 반복 최적화.
     - 목적 함수: `min_{K_compressed} KL(softmax(Q·K_orig^T/√d) || softmax(Q·K_compressed^T/√d))`.
     - 최적화 토큰 수: 레이어 예산 `budget(l)` 개의 Key만 유지.
     - 오버헤드: 프리필 시 레이어당 L-BFGS 5-10 반복 → < 10ms/레이어 (배치 크기 1, seq_len 2048 기준).
  5. **최소제곱 Value 최적화**:
     - 닫힌 형태 최소제곱: `V_compressed = argmin ||A·V_orig - A·V_compressed||_F`. `A`: 어텐션 가중치 행렬 (L-BFGS Key 최적화 후 고정).
     - 해: `V_compressed = (A^T A)^{-1} A^T A V_orig = V_orig` (선택된 토큰만 유지하는 경우). 실제로는 선택된 `budget(l)` 개 토큰의 Value를 원본 그대로 유지 + 나머지 Value 퇴거.
     - 추가 오버헤드: 최소제곱 계산 O(budget × d) → < 1ms/레이어.
  6. **교대 반복 (Alternating Optimization)**:
     - L-BFGS Key 최적화 → 최소제곱 Value 최적화 → 반복 (기본 3회 교대).
     - 수렴 기준: KL 발산 변화량 < `convergence_tol`(기본 1e-4).
  7. **이전 C 기법과의 차별점**:
     - DapQPositionAwareEvictionCodec(05-22 C-3): 위치-인식 유사 쿼리 기반 중요도 퇴거 (단순 퇴거, 레이어 균일).
     - EchoKVInterLayerResidualCodec(05-22 C-2): 레이어 간 유사성 기반 잔차 재구성 (KV를 재구성하는 접근, 온-디맨드 전환).
     - VQKVMultiCodebookCodec(05-22 C-1): Product Quantization 다중 코드북 (양자화 방식, 레이어별 M 조정).
     - KVSculptDistillationCodec: **파일럿 실행 → 레이어별 KL 발산 난이도 프로파일 → 난이도 비례 예산 배분 → L-BFGS+최소제곱 교대 증류 최적화** — 증류 패러다임 + 레이어별 난이도 측정 기반 비균일 예산 배분이 이전 어느 C 기법에도 없었다.
- **예상 효과**: 메모리 −40~60% (레이어별 난이도 비례 예산 배분, KVSculpt 원논문 기준), accuracy delta ±0.6% (KL 발산 3.5~4.1× 감소, 원논문 기준), KL 발산 감소 −70~75% (균일 압축 대비 KVSculpt 증류 최적화)
- **accuracy-preserving 근거**:
  (1) KVSculpt 원논문(2603.27819)에서 L-BFGS Key 최적화 + 최소제곱 Value 최적화가 Select+Fit 기준 KL 발산을 3.5~4.1× 감소시킴을 실험적으로 검증.
  (2) 적응적 레이어 예산 배분 적용 시 추가 1.3× KL 발산 감소 — 추론 시간 추가 비용 없이 정확도 보존 향상.
  (3) 난이도 비례 예산 배분: 고난이도 레이어(KL 발산이 큰 레이어)에 더 많은 예산을 배분해 모델 출력에 대한 누적 오차가 균일 배분 대비 감소.
  (4) L-BFGS 최적화가 어텐션 출력 KL 발산을 직접 최소화하므로, 압축 후 어텐션 동작이 원본과 가장 가깝게 보존됨이 수학적으로 보장.
  검증: WikiText-2 perplexity ±1% + LongBench 8개 서브태스크 + 레이어별 KL 발산 분포 측정 + 균일 예산 vs. 난이도 비례 예산 정확도 비교 + γ=0.0/0.25/0.50/1.0 별 정확도-압축률 곡선 + 파일럿 압축 오버헤드 측정.
- **구현 난이도**: medium
- **우선순위**: 2

### 아이디어 C-3: TriAxialKVThreeAxisTaggedMixedPrecisionCodec (TriAxialKV 3축 태그 기반 혼합 정밀도 에이전틱 압축 코덱)
- **가설**: 에이전틱 워크로드의 KV 캐시가 시간적 최근성·모달리티·의미적 역할이라는 세 가지 직교 축에서 구조적 이질성을 보인다는 TriAxialKV(2605.17170)의 발견을 `src/cache/` 레이어에 구현하면, 채팅 템플릿 기반 단일 패스 3축 태깅 + 태그별 INT2/INT4 혼합 정밀도 배분으로 BF16 대비 4.5× KV 캐시 용량과 30% E2E 처리량 향상을 달성하면서 BF16과 동등한 정확도를 유지할 수 있다. 과거 모든 C 기법 중 3축 직교 이질성 태그를 비트폭 할당에 활용한 방법이 없었다 — DapQPositionAwareEvictionCodec(05-22 C-3)가 위치 단일 축 기반이라면, TriAxialKV는 위치(시간적 최근성)·모달리티·의미적 역할 3축 동시 활용으로 설계 차원이 다르다.
- **접근 방법**:
  1. `TriAxialKVMixedPrecisionCodec` 클래스 (`src/cache/triaxialkv_mixed_precision_codec.py`): `CompressionCodec` 인터페이스 구현
  2. **3축 태그 생성기 (채팅 템플릿 기반 단일 패스)**:
     - **축 1 — 시간적 최근성(Temporal Recency)**: `recency_tag = "recent"` if `token_position > total_len × recency_threshold`(기본 0.70), else `"old"`. 기준: 최근 30% 토큰은 "recent".
     - **축 2 — 모달리티(Modality)**: `modality_tag = "image"` if 이미지 토큰 범위 내 (채팅 템플릿 `<|image_start|>...<|image_end|>` 파싱), else `"text"`.
     - **축 3 — 의미적 역할(Semantic Role)**: 채팅 템플릿 파싱으로 토큰을 역할 분류:
       - `"system"`: 시스템 프롬프트 내 토큰 (`<|system|>...<|end|>`).
       - `"user_query"`: 사용자 쿼리 토큰.
       - `"tool_call"`: 도구 호출 토큰 (`<|tool_call|>...<|end|>`).
       - `"observation"`: 도구 실행 결과 토큰.
       - `"reasoning"`: 추론 체인 토큰 (`<think>...<\/think>`).
       - `"response"`: 최종 응답 토큰.
     - **3-tuple 태그**: 각 토큰에 `(recency_tag, modality_tag, semantic_role_tag)` 3-tuple 할당.
     - 태깅 오버헤드: 채팅 템플릿 파싱 + 위치 비교 O(seq_len) 단일 패스 (추가 LLM 추론 없음, < 1ms/시퀀스).
  3. **태그별 비트폭 할당 (칼리브레이션 기반)**:
     - 보정 데이터(100 시퀀스)에서 각 3-tuple 태그 조합의 어텐션 출력 왜곡 민감도 측정:
       ```
       sensitivity(tag) = ||attn_output_fp16 - attn_output_quantized(tag, bitwidth)||_F
       ```
     - 고정 메모리 예산 하에서 태그별 INT2/INT4/INT8 비트폭 최적 할당:
       - 목적: `min Σ_tag sensitivity(tag) × count(tag)` s.t. `Σ_tag bitwidth(tag) × count(tag) ≤ memory_budget`
       - 솔버: 탐욕 알고리즘 (민감도/비트폭 비율 기준 정렬). 결과: `configs/triaxialkv_bitwidth_config.yaml`.
     - 기본 비트폭 할당 (원논문 기반):
       - `(recent, *, reasoning)` → INT8 (최고 중요도).
       - `(recent, text, user_query/tool_call)` → INT4.
       - `(old, text, observation)` → INT4.
       - `(old, *, system/response)` → INT2.
       - `(*, image, *)` → INT4 (이미지 토큰 균일).
  4. **혼합 정밀도 양자화 커널**:
     - `QuantizeMixedPrecisionKernel`: 토큰별 비트폭을 태그에서 조회해 INT2/INT4/INT8 양자화를 혼합 적용. CUDA 커널에서 태그 테이블을 shared memory에 로드해 병렬 처리.
     - 저장 효율: INT2 = 2비트, INT4 = 4비트, INT8 = 8비트. 평균 3~4비트/토큰 (태그 분포 의존).
  5. **SessionAwareTurnLevelSegmentCache(05-22 B-1)와의 통합 (B+C)**:
     - 세션 내 turn-level 세그먼트에 TriAxialKV 태그 적용: 각 세그먼트의 시간적 최근성(turn 거리)·의미적 역할(tool_call/observation/reasoning)로 비트폭 결정.
     - 이전 턴 세그먼트(old recency)의 system/response 역할 토큰은 INT2로 압축 → 장기 세션 히스토리 메모리 절감.
  6. **이전 C 기법과의 차별점**:
     - DapQPositionAwareEvictionCodec(05-22 C-3): 위치 단일 축 기반 중요도 퇴거 (퇴거 정책, 1축).
     - EchoKVInterLayerResidualCodec(05-22 C-2): 레이어 간 유사성 기반 잔차 재구성 (레이어 구조 활용, 퇴거/재구성 방식).
     - VQKVMultiCodebookCodec(05-22 C-1): Product Quantization 다중 코드북 양자화 (양자화 방식, 균일 구조).
     - TriAxialKVMixedPrecisionCodec: **시간적 최근성 × 모달리티 × 의미적 역할 3축 직교 이질성 기반 INT2/INT4/INT8 혼합 정밀도 양자화** — 3축 동시 활용 + 에이전틱 역할 분류 + 추가 추론 없는 단일 패스 태깅이라는 완전히 새로운 설계 조합.
- **예상 효과**: 메모리 −75~78% (BF16 대비 4.5× KV 캐시 용량, TriAxialKV 원논문 기준), 처리량 +25~30% (E2E 처리량 향상, 원논문 기준), accuracy delta ±0.7점 이내 (BFCL Memory 벤치마크 기준)
- **accuracy-preserving 근거**:
  (1) TriAxialKV 원논문(2605.17170)에서 Qwen3-VL-32B-Thinking의 컴퓨터-사용 에이전트(OSWorld) 실행 시 BF16과 동등한 정확도를 달성하고, Qwen3-32B BFCL Memory에서 BF16 대비 0.7점 이내 정확도 보존을 실험적으로 검증.
  (2) 3축 태그 기반 민감도 측정: 어텐션 출력 왜곡에 민감한 토큰 조합(recent × reasoning 등)에 높은 비트폭을 할당해 민감 토큰의 양자화 오차를 최소화.
  (3) 단일 패스 채팅 템플릿 파싱으로 구조 정보를 직접 활용: 의미적 역할 분류가 임의 어텐션 패턴 분석보다 더 안정적인 중요도 신호를 제공 (TriAxialKV 원논문의 근거).
  (4) 비트폭 할당 탐욕 알고리즘이 `sensitivity(tag) / bitwidth(tag)` 비율 기준으로 최적 배분을 근사 → 동일 메모리 예산에서 총 왜곡을 최소화.
  검증: WikiText-2 perplexity ±1% + BFCL Memory 벤치마크 + LongBench 8개 서브태스크 + 태그 조합별(recency × role) 정확도 히트맵 + 비트폭 설정(INT2/INT4/INT8 각 조합) 별 정확도 곡선 + BF16 대비 KV 메모리 절감율 측정.
- **구현 난이도**: medium
- **우선순위**: 2

### 아이디어 Cross-1: RuntimeCertifiedKVSculptAdaptiveDistillationPipeline (C 내부 시너지: 인증형 증류 압축) — C-1+C-2
- **조합 근거**: `RuntimeCertifiedQuantizedAttentionCodec(C-1)`이 런타임 오류 경계를 계산해 양자화 품질을 수학적으로 모니터링하고, `KVSculptDistillationCodec(C-2)`가 레이어별 난이도 프로파일로 증류 예산을 배분한다. 두 기법을 결합하면 "KVSculpt 증류가 KV를 압축하고, RuntimeCertified 오류 경계가 압축 품질을 실시간 인증"하는 파이프라인이 가능하다 — KVSculpt의 L-BFGS 최적화가 어텐션 출력 KL 발산을 최소화하고 RuntimeCertified의 오류 상한이 이를 검증해 임계값 초과 시 해당 레이어의 예산을 즉각 증가(온라인 예산 재배분)하는 적응형 폐루프 구조다. 이 조합은 "압축 + 인증 + 온라인 예산 적응"을 통합하는 새로운 C 아키텍처다.
- **구체 설계**:
  1. `RuntimeCertifiedDistillationPipeline` 모듈 (`src/cache/runtime_certified_distillation_pipeline.py`)
  2. **통합 처리 흐름**:
     - **Step 1 (오프라인 레이어 난이도 프로파일링, C-2)**: KVSculpt 파일럿 실행으로 `configs/kvsculpt_layer_difficulty_profile.yaml` 생성.
     - **Step 2 (난이도 비례 초기 예산 배분, C-2)**: γ=0.5 기반 레이어별 압축 예산 설정.
     - **Step 3 (증류 압축 실행, C-2)**: 프리필 단계에서 레이어별 L-BFGS + 최소제곱 교대 최적화.
     - **Step 4 (런타임 오류 경계 계산, C-1)**: 각 디코딩 스텝에서 헤드별·레이어별 오류 상한 계산.
     - **Step 5 (온라인 예산 재배분)**: `error_bound(layer_l) > adaptive_threshold(layer_l)` 시 해당 레이어의 압축 예산 즉각 증가 (더 많은 KV 유지). 다음 배치에 반영.
     - **Step 6 (폴백 결정, C-1)**: 레이어 예산 증가 후에도 오류 상한이 임계값 초과하면 해당 헤드 FP16 폴백.
  3. **폐루프 품질 제어**:
     - `adaptive_threshold(layer_l)` 초기값: `error_threshold / (1 + normalized_difficulty(l))` — 난이도 높은 레이어는 더 엄격한 임계값.
     - 온라인 예산 재배분: 이전 N 배치의 폴백 비율을 누적해 예산 재배분 결정. 폴백이 잦은 레이어는 다음 배치에서 더 높은 예산 배정.
- **예상 복합 효과**: 처리량 +20~30% (KVSculpt 증류 + RuntimeCertified 인증 병렬화), 메모리 −55~70% (증류 압축 + 인증 기반 예산 최적화 결합), accuracy delta ±0.4% 수학적 보장 (RuntimeCertified 인증 + KVSculpt 증류 최적화 결합)
- **구현 난이도**: medium
- **우선순위**: 1

### 아이디어 Cross-2: CPDWarmColdRuntimeCertifiedKVCompressionStack (A+C) — CPD 히트율 라우터 + Runtime-Certified 양자화 전송 파이프라인
- **조합 근거**: `CPDWarmColdHitRateRouter(A-2)`가 warm/cold 요청을 분리하고, cold 요청(캐시 미스 대형 프리필)이 생성한 KV를 warm 노드 또는 decode 노드로 전송할 때, `RuntimeCertifiedQuantizedAttentionCodec(C-1)`이 INT8K+INT4V로 압축한 KV를 전송하고 오류 경계가 임계값 초과 시에만 FP16으로 폴백하는 "전송-전 오류 인증 파이프라인"이 가능하다. CPD의 cold prefill 격리(A)와 RuntimeCertified의 압축 KV 전송 인증(C)이 자연스럽게 결합되어 "cold 프리필 결과를 압축 전송 + 정확도 SLO 인증"이라는 P/D 분리 환경의 대역폭-정확도 최적화를 동시에 달성한다.
- **구체 설계**:
  1. `CPDRuntimeCertifiedStack` 모듈 (`src/engine/cpd_runtime_certified_stack.py`)
  2. **통합 처리 흐름**:
     - **Step 1 (Warm/Cold 분기, A-2)**: `CPDWarmColdHitRateRouter`가 요청의 예측 히트율로 warm/cold 경로 분기.
     - **Step 2 (Cold 프리필 처리)**: Cold 배치에서 대형 프리필 실행 → KV 생성.
     - **Step 3 (전송 전 압축 + 오류 인증, C-1)**: `RuntimeCertifiedQuantizedAttentionCodec`이 생성된 KV를 INT8K+INT4V로 압축 + 헤드별 오류 경계 계산. 오류 경계 > `transfer_error_threshold` 인 헤드만 FP16으로 전송, 나머지 INT8K/INT4V 전송.
     - **Step 4 (Warm 노드 수신 + 재사용)**: Warm 노드가 압축 KV 수신 → `RuntimeCertifiedQuantizedAttentionCodec.decode()` + 잔여 오류 경계 재계산 → 어텐션 계산.
  3. **대역폭 절감 정량화**:
     - `bandwidth_reduction = (FP16_size - avg_compressed_size) / FP16_size`.
     - `avg_compressed_size = FP16_heads_ratio × FP16_size + (1 - FP16_heads_ratio) × INT4V_size`.
     - FP16_heads_ratio(폴백 비율)에 따라 동적 결정. 평균 예상: INT8K+INT4V 헤드 70%, FP16 폴백 헤드 30% → 평균 압축률 ≈ 60%.
- **예상 복합 효과**: 처리량 +30~45% (CPD warm 배치 우선화 + cold KV 전송 병목 해소), P→D KV 전송 대역폭 −40~60% (INT8K+INT4V 압축 전송), accuracy delta ±0.5% 수학적 보장 (RuntimeCertified 인증)
- **구현 난이도**: medium
- **우선순위**: 2

### 아이디어 Cross-3: CLCBiasGateTriAxialSessionDistilledPipeline (A+B+C) — CPD 히트율 라우터 + CLC 위치 편향 게이트 + TriAxialKV 에이전틱 압축 + KVSculpt 증류
- **조합 근거**: 네 기법이 에이전틱 멀티-턴 RAG 워크로드의 KV 생명주기 전체를 커버한다: `CPDWarmColdHitRateRouter(A-2)`가 warm/cold 분기, `CLCPositionalBiasGatedSegmentReuse(B-1)`가 안전한 비연속 재사용 조건 판단, `TriAxialKVMixedPrecisionCodec(C-3)`가 에이전틱 3축 혼합 정밀도 압축, `KVSculptDistillationCodec(C-2)`가 레이어별 증류 예산 최적화. 특히 B-1이 "위치 편향이 낮은 세그먼트만 직접 재사용"하고 C-3이 "재사용된 세그먼트를 의미적 역할별 혼합 정밀도로 압축"하면 B+C가 동일한 에이전틱 역할 분류 원칙 하에 일관성 있게 동작한다.
- **구체 설계**:
  1. `CLCTriAxialDistilledPipeline` 모듈 (`src/engine/clc_triaxial_distilled_pipeline.py`)
  2. **통합 처리 흐름**:
     - **Step 1 (Warm/Cold 분기, A-2)**: CPDWarmColdHitRateRouter → warm 요청은 비연속 재사용 경로.
     - **Step 2 (위치 편향 게이트, B-1)**: 히트된 세그먼트에 CLCPositionalBiasGate 적용 → 직접 재사용/부분/전체 재인코딩 분류.
     - **Step 3 (TriAxialKV 3축 태그 압축, C-3)**: 재사용된 세그먼트의 KV에 3축 태그 기반 혼합 정밀도 양자화 적용 (old recency 세그먼트는 INT2/INT4로 압축).
     - **Step 4 (KVSculpt 증류 레이어 예산 조정, C-2)**: 레이어별 난이도 프로파일로 태그별 비트폭 할당의 레이어별 미세 조정.
     - **Step 5 (RuntimeCertified 오류 인증)**: 전체 압축 KV에 오류 경계 계산 → 임계값 초과 헤드 폴백.
  3. **에이전틱 RAG 워크로드 최적화**:
     - RAG 청크: observation 역할 → INT4(중간 중요도) + 위치 편향 게이트로 안전 재사용 조건 판단.
     - 시스템 프롬프트: system 역할 + old recency → INT2 (장기 보존, 저비트).
     - 추론 체인: reasoning + recent → INT8 (최고 중요도).
- **예상 복합 효과**: 처리량 +35~50% (warm 우선화 + 비연속 재사용 + 에이전틱 압축 복합), 메모리 −65~78% (TriAxialKV 4.5× + KVSculpt 레이어 예산 + 위치 편향 게이트 직접 재사용), accuracy delta ±0.6% (RuntimeCertified 수학적 인증 + 에이전틱 태그 기반 압축)
- **구현 난이도**: high
- **우선순위**: 3

## planner에게 전달할 요청사항

1. **Activity C 구현 시 accuracy-preserving 검증 방법 명시 필수**:
   - C-1 (RuntimeCertifiedQuantizedAttentionCodec): WikiText-2 perplexity ±1% + NIAH (32K/64K/128K 컨텍스트, INT8K+INT4V 모드) + RULER 벤치마크 + 실측 폴백 비율(`fallback_rate_level1, level2`) + 오류 경계 분포(헤드별·레이어별) + FP16 대비 정확도 곡선. **수학적 보장 검증 필수**: 오류 상한이 실측 오류보다 항상 크거나 같음을 100 시퀀스 이상에서 확인.
   - C-2 (KVSculptDistillationCodec): WikiText-2 perplexity ±1% + LongBench + 레이어별 KL 발산 분포 + 균일 예산 vs. 난이도 비례 예산 비교 + γ=0.0/0.25/0.50/1.0 별 정확도 곡선 필수.
   - C-3 (TriAxialKVMixedPrecisionCodec): WikiText-2 perplexity ±1% + BFCL Memory + LongBench + 태그 조합별 정확도 히트맵 + BF16 대비 메모리 절감율 측정.

2. **이번 사이클 측정 지표**:
   - Inference Throughput: C-1 RuntimeCertified INT8K+INT4V 모드로 메모리 절감 → 더 많은 배치 → 처리량 +20% 이상 목표.
   - KV Cache Memory Reduction: C-3 TriAxialKV 4.5× 용량 절감 + C-2 KVSculpt 레이어 예산 최적화 → −60% 이상 목표.
   - Non-Contiguous Cache Hit Rate: B-1 CLCPositionalBiasGate로 직접 재사용 가능 세그먼트 비율 증가 → 비연속 히트율 +20% 이상 목표.
   - Compression Accuracy Delta: C-1 ±0.5% 수학적 보장 (필수, 오류 경계 계산 포함).
   - Scheduling Overhead: A-2 히트율 예측 오버헤드 TTFT +2% 이내.

3. **구현 우선순위**: C-1 → Cross-1 → B-1 → A-2 → C-2 → C-3 → A-1 → Cross-2 → Cross-3 순서.

4. **C-1 구현 시**: `src/cache/runtime_certified_quant_codec.py` 신규 생성. `CompressionCodec` 인터페이스 구현. GPU HBM: INT8 Key (`quantize_int8()`) + INT4 Value (`quantize_int4()`). 시스템 RAM: FP16 원본 보존 (비동기 H2D 스트림). **이중 항 오류 분해**: δ_attn_bound (Key 양자화 어텐션 왜곡) + δ_value_bound (Value 재구성 오류). **다단계 폴백 사다리**: Level 0→1→2 (`error_threshold = 0.005`). `certified_accuracy_report` 자동 생성. **수학적 보장 검증 필수**: 100 시퀀스에서 오류 상한 ≥ 실측 오류 항상 성립 확인.

5. **B-1 구현 시**: `src/cache/clc_positional_bias_gated_segment_cache.py` 신규 생성. `CacheStore` 인터페이스 상속. `ΔPos = |pos_target_start - pos_orig_start| / max_context_length` 계산. 3단계 게이트: `ΔPos ≤ 0.15`(직접 재사용), `0.15 < ΔPos ≤ 0.40`(부분 재인코딩), `ΔPos > 0.40`(전체 재인코딩). `tests/unit/test_positional_bias_gate.py`: 위치 이동 거리별 정확도 측정 테스트 스위트. `BlockUnionNonContiguousReuseIndex(05-21 B-1)` 연동.

6. **Activity C 구현 시 공통 필수 사항**: 모든 C 기법은 `src/metrics/` 내 perplexity 측정 코드 포함 + 압축 전후 perplexity를 `results/<exp-name>/metrics.json`에 기록. C-1은 추가로 `{fallback_rate_level1, fallback_rate_level2, error_bound_mean, error_bound_p99}` 기록 필수.
