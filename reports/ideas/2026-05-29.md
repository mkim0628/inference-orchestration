### 아이디어 A-1: ResidentKVClaimContractScheduler (Resident KV Claims 컨트랙트 기반 재사용 예약-활성 prefill 경합 스케줄러)
- **가설**: 기존 vLLM/SGLang의 KV 할당기는 재사용 예약 KV(resident KV)와 활성 prefill의 풀 경합을 암묵적으로 처리하며, 활성 prefill이 resident KV를 묵시적으로 퇴거시키는 실패 모드가 발생한다. Resident KV Claims(2605.24259)의 4-요소 컨트랙트 — (1) 구체화 서술(재사용 트리거 조건), (2) 라이프사이클 상태(claimed/active/released), (3) 실현 가능성 결과(admit/deny/partial), (4) 클레임 텔레메트리(귀인 로그) — 를 `src/scheduler/`에 구현하면, resident KV가 active prefill에 의해 묵시적으로 퇴거되는 실패 모드를 "스케줄러-가시적 거부 + 클레임-귀인 로그"의 명시적 컨트랙트로 전환해 KV 퇴거율을 구조적으로 줄이고 예측 가능한 재사용 보장을 달성할 수 있다. 과거 28개 사이클의 모든 A 기법(HexAGenT DAG, PegaFlow, CacheTTL TTL 보존, CONCUR 혼잡 기반 어드미션, IndexMem TTL Fallback, ObjectCache S3, DualPath NIC, RandomizedCompetitive 등) 중 "재사용 의도를 클레임 컨트랙트로 형식화해 active prefill 경합 시 명시적 스케줄러 거부로 전환"하는 기법이 없었다.
- **접근 방법**:
  1. `ResidentKVClaimScheduler` 클래스 (`src/scheduler/resident_kv_claim_scheduler.py`): `BaseScheduler` 상속
  2. **KV 클레임 컨트랙트 자료구조 (KV Claim Contract)**:
     - `KVClaimContract(claim_id, segment_ids, materialization_predicate, lifecycle_state, feasibility_outcome, telemetry_log)`:
       - `materialization_predicate`: 재사용 트리거 조건 (세그먼트 해시 집합 + 예상 재사용 시간 윈도우 `reuse_window_ms`).
       - `lifecycle_state`: `Literal["claimed", "materializing", "active", "released", "denied"]`.
       - `feasibility_outcome`: `Literal["admit", "deny", "partial"]` — 풀 경합 시 어드미션 결과.
       - `telemetry_log`: `List[(timestamp, event_type, block_count)]` — 클레임 귀인 로그.
     - `ClaimRegistry`: `{claim_id → KVClaimContract}` 딕셔너리. 스케줄러에 중앙 관리.
  3. **풀 실현 가능성 검사 (Pool Feasibility Check)**:
     - 새 active prefill 요청 수신 시 `feasibility_check(active_demand, resident_claims)`:
       - `available = pool_total - sum(claimed_blocks for c in resident_claims if c.lifecycle_state == "claimed")`
       - `if active_demand > available`: 실현 가능성 실패 → `feasibility_outcome = "deny"` 또는 가장 낮은 우선순위 클레임을 부분 해제(`"partial"`)
       - `else`: `feasibility_outcome = "admit"` — active prefill 정상 진행
     - 클레임 우선순위: `priority(claim) = reuse_window_remaining_ms / claimed_blocks` — 임박한 재사용이 높은 우선순위.
  4. **클레임 라이프사이클 관리**:
     - 세그먼트가 재사용 예약될 때: `claim_register(segment_ids, reuse_window_ms)` → `KVClaimContract` 생성, 해당 KV 블록에 hard-protect 마킹.
     - Active prefill이 `claimed` 블록 퇴거 시도 시: 풀 실현 가능성 검사 실패 → prefill 요청을 큐에 보류(backpressure) 또는 거부.
     - 재사용 완료 후: `claim_release(claim_id)` → 블록 보호 해제.
     - TTL-aware 해제: `reuse_window_ms` 초과 시 자동 `claim_release` → HexAGenT DAG(05-28 A-1) 워크플로우 DAG의 태스크 완료 이벤트와 연동 가능.
  5. **클레임 텔레메트리 + 귀인 (Claim Telemetry & Attribution)**:
     - 모든 클레임 생성·거부·해제 이벤트를 `telemetry_log`에 기록: `(timestamp, "claim_created"|"admit"|"deny"|"partial"|"released", block_count)`.

  6. **HexAGenT DAG 스케줄러(05-28 A-1)와의 통합**:

     - 태스크 완료 → `claim_release()` 자동 호출. DAG 완료 지평선(`standalone_completion_horizon`)을 `reuse_window_ms`로 사용.
  7. **이전 A 기법과의 차별점**:
     - CacheTTL(2511.02230, 이미 보고): TTL 기반 KV 보존 (TTL 만료 시 영구 폐기, 클레임 컨트랙트 없음).
     - CONCUR(2601.22705, 이미 보고): 혼잡 기반 어드미션 제어 (입장 제어, resident-active 경합 컨트랙트 없음).
     - IndexMemTTLFallbackScheduler(05-27 A-1): TTL 만료 → 잠재 기억 폴백 (소프트 전환, 명시적 클레임 컨트랙트 없음).
     - HexAGeTWorkflowScheduler(05-28 A-1): KV 용량 인식 배치 결정 (용량 인식, 재사용 의도 클레임 컨트랙트 없음).
     - ResidentKVClaimScheduler: **재사용 의도를 4-요소 컨트랙트로 형식화 → active prefill 경합 시 명시적 스케줄러 거부 + 클레임 귀인 — 이전 어느 A 기법에도 없었다.**

## Activity B 아이디어

### 아이디어 B-1: GroundedSafetyGatedNonContiguousSegmentReuseValidator (GroundedCache 4-게이트 안전성 검증 기반 비연속 KV 세그먼트 재사용 안전 필터)
- **가설**: 현재 비연속 KV 세그먼트 재사용 기법(Irminsul, KV Packet, IndexMem Soft Hit 등)은 "콘텐츠 해시 일치 → 재사용"의 이진 판단을 사용하며, 세그먼트가 원본 컨텍스트에서 분리된 새 위치에서 재사용될 때 의미적 정합성이 보존되는지 검증하지 않는다. GroundedCache(2605.27494)의 4-게이트 재사용 안전성 프레임워크를 KV 세그먼트 레벨로 내려 — (1) 세그먼트 콘텐츠 유사도, (2) 현재 컨텍스트와의 증거 중첩도, (3) 소스 버전 유효성, (4) 재사용 세그먼트의 어텐션 기여 예측 지지율 — 의 4-게이트를 동시에 통과할 때만 비연속 세그먼트 재사용을 허용하는 "재사용 안전 필터"를 `src/cache/`에 구현하면, 현재 비연속 재사용의 정확도 보존 조건(±1%)을 구조적으로 강화할 수 있다. 과거 모든 B 기법(Irminsul, KV Packet, IndexMem Soft Hit, Block Union, CLC 등)은 "어떻게 빠르게 재사용하는가"에 집중했으며, "재사용이 의미적으로 안전한가"를 정형화한 안전성 게이트 기법이 없었다.
- **접근 방법**:
  1. `GroundedSafetyGatedSegmentCache` 클래스 (`src/cache/grounded_safety_gated_cache.py`): `CacheStore` 인터페이스 구현, 기존 `IrminsulMLASegmentCache`(05-26 기구현) 래핑
  2. **4-게이트 안전성 검증 (4-Gate Safety Validation)**:
     - **Gate 1 — 세그먼트 콘텐츠 유사도 (Content Similarity)**:
       - 재사용 후보 세그먼트의 토큰 n-gram 유사도: `content_sim = jaccard(ngrams(candidate_tokens), ngrams(current_context_window))`.
       - 임계값: `content_sim_threshold`(기본 0.85) — 0.85 미만이면 즉시 거부.
       - 계산 오버헤드: n=3 n-gram 집합 교집합, O(chunk_tokens) ≈ 0.1ms.
     - **Gate 2 — 증거 중첩도 (Evidence Overlap)**:
       - 세그먼트의 엔티티/키워드 집합과 현재 컨텍스트의 키워드 집합 중첩율: `evidence_overlap = |entities(segment) ∩ entities(current_context)| / |entities(segment)|`.
       - `evidence_overlap_threshold`(기본 0.6) — 세그먼트 엔티티 60% 이상이 현재 컨텍스트에 등장해야 재사용 허용.
       - 엔티티 추출: TF-IDF 상위 20개 토큰 사용 (경량, 모델 호출 불필요).
     - **Gate 3 — 소스 버전 유효성 (Source Version Validity)**:
       - 세그먼트 원본 컨텍스트 버전 해시: `source_version_hash = sha256(original_context_token_ids)`.
       - 현재 컨텍스트가 원본 컨텍스트의 갱신 버전인 경우 버전 불일치 → 거부 또는 부분 재사용.
       - 버전 추적: `KVClaimContract`(A-1 ResidentKVClaimScheduler)의 `materialization_predicate` 필드와 연동 — 클레임 시 `source_version_hash` 등록.
       - Irminsul(05-26) CDC 콘텐츠 해시 키잉과 통합: CDC 해시 일치 + 소스 버전 유효 → Gate 3 통과.
     - **Gate 4 — 어텐션 기여 예측 지지율 (Attention Contribution Support)**:
       - 재사용 세그먼트의 예상 어텐션 기여가 현재 쿼리를 지지하는지 경량 추정: `attn_support = cosine_sim(mean_kv_vector(segment), current_query_embedding)`.
       - `attn_support_threshold`(기본 0.5) — 유사도 0.5 미만이면 해당 세그먼트가 현재 컨텍스트에 기여하지 않을 가능성 높음 → 거부.
       - `mean_kv_vector(segment)`: 세그먼트 K 벡터 평균 (캐시 저장 시 1회 계산, O(chunk_tokens × head_dim)).
  3. **게이트 통과 기록 + 부분 재사용 (Partial Reuse on Gate Failure)**:
     - 4개 게이트 모두 통과: `"safe_reuse"` → Irminsul δ-회전 + 재사용 진행.
     - Gate 1 실패: 재사용 완전 거부 → 재계산.
     - Gate 2 또는 Gate 4 실패: `"partial_reuse"` — 해당 세그먼트의 c_KV만 재사용(위치-자유), k_r 재계산.
     - Gate 3 실패 (버전 불일치): `"stale_segment"` → 기존 세그먼트 즉시 무효화 + 캐시에서 퇴거 트리거.
  4. **안전 히트율 지표 (Safety-Gated Hit Rate)**:
     - 기존 `{hard_hit, soft_hit, miss}` → 확장: `{safe_reuse_hit, partial_reuse_hit, gate_rejected, stale_evicted, miss}` 5단계.
     - `safety_gate_pass_rate = safe_reuse_hit / (safe_reuse_hit + gate_rejected + stale_evicted)` — 재사용 안전성 통과율 지표.
     - `src/metrics/hit_rate.py`에 `safety_gate_pass_rate` + `stale_eviction_rate` 지표 추가.
  5. **accuracy-preserving 근거**:

## Activity C 아이디어

### 아이디어 C-1: WynerZivPolynomialSensitivityAdaptiveWindowEvictionPolicy (Wyner-Ziv 다항식 절단-민감도 기반 이론-인도 적응형 슬라이딩 윈도우 KV 퇴거 정책)
- **가설**: 기존 슬라이딩 윈도우 기반 KV 퇴거(StreamingLLM, H2O, SnapKV, IndexMem 등)는 윈도우 크기를 경험적으로 튜닝하거나 고정 hyperparameter로 사용하며, "주어진 정확도 예산(ε) 달성에 필요한 최소 윈도우 크기"에 대한 이론적 근거가 없다. Wyner-Ziv Bounds(2605.25085)의 핵심 발견 — 컨텍스트 절단 민감도가 다항식 감쇠 `S(d) = C × d^{-α}` (d = 절단 거리, α ≈ 1~3, C = 모델/태스크 의존 상수)를 따른다 — 를 런타임에 적합(fit)하고, 이 다항식 민감도 함수로 "정확도 예산 ε을 달성하는 이론적 최소 윈도우 크기 `W*(ε)`"를 도출해 슬라이딩 윈도우 크기를 동적으로 결정하면, 경험적 고정 윈도우 대비 메모리를 절감하면서도 정확도 보존(±1%)을 이론적 근거 하에 보장할 수 있다. 과거 C 기법 전체(IndexMem, FlexBlock Layerwise, PredictiveMultiTier, VeriCache, RuntimeCertified, TriAxialKV, TriAttention, AttentionMatching, KVSculpt, StochasticKV, FibQuant 등)에서 "다항식 절단-민감도 함수를 온라인 추정하고 이를 슬라이딩 윈도우 크기의 이론 하한으로 실시간 적용"하는 기법이 없었다.
- **접근 방법**:
  1. `WynerZivAdaptiveWindowEviction` 클래스 (`src/cache/wyner_ziv_adaptive_window_eviction.py`): `CompressionCodec` 인터페이스 구현
  2. **다항식 민감도 함수 온라인 적합 (Online Polynomial Sensitivity Fitting)**:
     - 민감도 측정: 각 레이어 l에서 현재 토큰의 다음-토큰 분포와 절단 거리 d에서의 다음-토큰 분포의 KL 발산: `S_l(d) = KL(p_full(x|ctx) || p_truncated(x|ctx[:T-d]))`.
     - 절단 거리 샘플: `d ∈ {32, 64, 128, 256, 512}` 구간 — 배치 내 일부 요청(비율 `sensitivity_sample_ratio`, 기본 0.05)에만 측정 적용 (오버헤드 최소화).
     - 온라인 적합: 측정된 `{(d, S_l(d))}` 쌍에 대해 파워 법칙 회귀: `log S_l(d) = log C_l - α_l × log d` → `(C_l, α_l)` EMA 갱신.
       - `α_l_ema = γ × α_l_measured + (1-γ) × α_l_ema` (γ=0.1, 슬로우 EMA — 모델/태스크 의존 상수이므로 급격히 변하지 않음).
     - 초기화: 첫 100 배치 동안 워밍업 측정 → `(C_l, α_l)` 초기값 결정.
  3. **이론 하한 기반 윈도우 크기 결정 (Theory-Guided Window Size)**:
     - 정확도 예산 ε (기본 `perplexity_delta_threshold`, 기본 0.01 = perplexity 1% 이내):
       - 레이어별 이론 최소 윈도우: `W*_l(ε) = (C_l / ε)^{1/α_l}`.
       - 해석: `S_l(W*_l) ≤ ε` → W* 이상의 토큰을 유지하면 정확도 예산 달성 이론적 보장.
     - 전체 윈도우 크기: `W* = max_l W*_l(ε)` — 가장 민감한 레이어 기준 보수적 결정.
     - 메모리 예산 제약 상한: `W_max = available_kv_budget / (kv_size_per_token × n_layers)` — 메모리 제약 상한과 `min(W*(ε), W_max)` 취함.
  4. **동적 윈도우 크기 갱신 주기**:
     - 매 `window_update_interval`(기본 1000 배치)마다 `(C_l, α_l)` 최신 EMA로 `W*(ε)` 재계산.
     - KV 예산 압박(`kv_pressure > 0.8`) 시 즉각 재계산: 현재 ε을 일시적으로 완화(`ε_relaxed = 2 × ε`) → `W*` 축소로 메모리 압박 해소. 압박 해소 후 원래 ε 복원.
  5. **레이어별 차등 윈도우 (Layer-wise Differential Window)**:
     - `W*_l(ε)` 값이 레이어별로 다름 (어텐션 엔트로피가 높은 레이어가 더 큰 W* 요구).
     - 레이어별 독립 슬라이딩 윈도우 크기 적용: `window_size[l] = min(W*_l(ε), W_max_per_layer)`.
     - `configs/wyner_ziv_window_config.yaml`: `{layer_id → (C_l_init, alpha_l_init, window_size)}` 초기값 저장.
     - 온라인 갱신으로 지속 갱신.
  6. **IndexMem(05-27 C-1)과의 통합**:
     - W*(ε) 이내 토큰: 물리적 KV 유지 (슬라이딩 윈도우).
     - W*(ε) 초과 토큰(퇴거 대상): IndexMem Learnable Indexer로 중요도 평가 → 상위 토큰은 잠재 기억 보존, 나머지 완전 퇴거.
     - 조합 효과: "이론 하한이 보장하는 최소 윈도우" + "윈도우 외부 토큰 잠재 기억 보상" → ε 예산 내에서 최대한 작은 물리적 윈도우 유지.
  7. **accuracy-preserving 근거**:
     - (1) `W*(ε)` 계산이 `S_l(W*) ≤ ε` 이론적 조건에서 도출 → 물리적 KV 윈도우 크기가 W* 이상이면 perplexity delta ≤ ε 이론 보장 (Wyner-Ziv Bounds 논문 Theorem 주장).
     - (2) α_l EMA가 슬로우 갱신(γ=0.1)으로 민감도 추정의 분산을 줄임 — 과소 추정으로 인한 과도한 퇴거 방지.
     - (3) 메모리 압박 시 ε 완화를 명시적으로 적용 → 정확도 저하 여부가 스케줄러에 가시적.
     - (4) IndexMem 잠재 기억 보상으로 W*(ε) 외부 토큰의 어텐션 기여 일부 복원.
     - Fallback: 온라인 perplexity 검사(샘플 배치 1%)에서 실제 delta > ε 감지 시 `W*` 즉시 2× 증가.
     - 검증: WikiText-2 perplexity ±1% + RULER-4K/16K/32K + LongBench + 고정 윈도우(W=512) vs. 적응형 W*(ε) 비교 + 다항식 민감도 측정 오버헤드 프로파일.
- **예상 효과**: 메모리 −35~55% (이론 하한 기반 최소 윈도우 → 경험적 고정 윈도우 대비 30~50% 추가 절감), accuracy delta ±0.5~1.0% (이론 보장 하에 ε 예산 내)
- **accuracy-preserving 근거**: 위 항목 7 참조 — Wyner-Ziv 이론 하한이 W*(ε)를 처음으로 이론적으로 근거 있게 결정. 경험적 튜닝 불필요.
- **구현 난이도**: medium
- **우선순위**: 1

### 아이디어 C-2: WynerZivPolynomialSensitivityLayerGroupedQuantizationPolicy (Wyner-Ziv 다항식 민감도 기반 레이어 그룹 차등 양자화 정책)

- **접근 방법**:
  1. `WynerZivLayerGroupQuantizationCodec` 클래스 (`src/cache/wyner_ziv_layer_group_quant_codec.py`): `CompressionCodec` 인터페이스 구현
  2. **α_l 기반 레이어 그룹 분류 (Layer Group Classification by α_l)**:
     - C-1에서 온라인 추정된 `α_l_ema` 값 활용 (코드 재사용).
     - 그룹 분류 규칙:
       ```
       α_l < 1.0 (민감도 느린 감쇠, 정보 보존 중요):  FP8 양자화
       1.0 ≤ α_l < 2.0 (중간 민감도):                  INT8 양자화
       α_l ≥ 2.0 (민감도 빠른 감쇠, 정보 손실 허용):    INT4 양자화
       ```
     - 그룹 임계값 `(alpha_fp8_threshold, alpha_int8_threshold)` YAML 외부화.
  3. **양자화 코덱 적용**:
     - 각 레이어별로 해당 그룹의 양자화 코덱 적용:
       ```python
       def quantize_kv(layer_id, kv_tensor):
           alpha = self.alpha_ema[layer_id]
           if alpha < self.alpha_fp8_threshold:
               return fp8_quantize(kv_tensor)
           elif alpha < self.alpha_int8_threshold:
               return int8_quantize(kv_tensor)
           else:
               return int4_quantize(kv_tensor)
       ```
     - INT8/FP8: 기존 OScaR(05-20) 또는 TriAxialKV(05-20) 코덱 재사용.
     - INT4: bitsandbytes NF4 양자화 적용.
  4. **accuracy-preserving 근거**:
     - α_l < 1.0 레이어는 민감도 감쇠가 느려 먼 컨텍스트의 기여가 오래 유지됨 → 양자화 오차가 이 레이어에서 더 큰 정확도 손실로 이어질 수 있음 → FP8로 오차 최소화.
     - α_l ≥ 2.0 레이어는 민감도가 빠르게 감쇠해 이미 근거리 컨텍스트만 사용됨 → INT4 양자화 오차가 정확도 손실에 미치는 영향 최소 (Wyner-Ziv 이론적 근거).
     - 검증: WikiText-2 perplexity ±1% + 균일 INT8 vs. α_l 기반 차등 양자화 비교 + 레이어별 α_l 분포 측정.
- **예상 효과**: 메모리 −45~65% (INT4 레이어 비율에 따라 균일 INT8 대비 추가 절감), accuracy delta ±0.5~0.9% (α_l 기반 정밀도 보호로 민감 레이어 오차 최소화)

     - A-1, B-1, C-1 세 컴포넌트가 동일 ε 예산 공유.
     - 실시간 perplexity delta 추적: 각 레이어의 기여 분리 → 어떤 컴포넌트가 ε 예산을 얼마나 소모하는지 귀인.
- **예상 복합 효과**: 처리량 +15~30% (resident KV 보호로 재계산 감소 + 안전 재사용 히트율 향상), 메모리 −40~60% (Wyner-Ziv 이론 윈도우 최소화 + IndexMem 잠재 기억), 비연속 안전 히트율 +10~20%, accuracy delta ±0.3~0.8% (3-레이어 정확도 보존 스택)
- **구현 난이도**: medium
- **우선순위**: 2

### 아이디어 Cross-2: GroundedSafetyGatedWynerZivCompressionDecisionBC (B+C) — GroundedCache 소스-버전 민감도 × Wyner-Ziv 다항식 감쇠 결합 재압축 정책
- **관련 Activities**: B+C
- **핵심 아이디어**: 트렌드 리포트의 "B+C 교차점" 분석을 구체화한다. GroundedCache(B)의 소스-버전 유효성 게이트(Gate 3)가 버전 불일치를 감지할 때, 해당 불일치가 "Wyner-Ziv 민감도 경계(α_l 기반 민감도 함수) 이내"인지 이외인지에 따라 재압축 여부를 결정하는 "버전-인식 민감도-안내 재압축 정책"이다. 버전 불일치 규모 d_version을 C-1의 민감도 함수 `S_l(d_version)`으로 수량화해 — S_l(d_version) ≤ ε이면 기존 압축 KV 유지, > ε이면 재압축 트리거 — 불필요한 재압축을 줄이고 필요한 재압축만 정확히 수행한다.
- **구현 방향**:
  1. `VersionSensitivityRecompressionPolicy` 클래스 (`src/cache/version_sensitivity_recompression.py`)
  2. **버전 불일치 거리 수량화**:
     - Gate 3 버전 불일치 시 두 버전 사이의 "컨텍스트 편집 거리" d_version 계산: `d_version = |changed_token_ids| / |original_segment_tokens|` (변경된 토큰 비율).
     - `S_l(d_version) = C_l × d_version^{-α_l}` (C-1의 파워 법칙 모델 재사용) — 버전 불일치가 해당 레이어에 미치는 민감도 추정.
  3. **재압축 결정**:
     - `S_l(d_version) ≤ ε`: 민감도 예산 이내 → 기존 압축 KV 그대로 재사용 (재압축 불필요).
     - `S_l(d_version) > ε`: 민감도 예산 초과 → 해당 세그먼트 재압축 트리거.
  4. **이전 B+C Cross 기법과의 차별점**:
     - 이전 Cross 기법들은 모두 "어떻게 더 많은 세그먼트를 압축·재사용하는가"에 초점. 이 기법은 "버전이 달라졌을 때 언제 재압축이 필요한가"라는 재압축 트리거 결정 문제를 Wyner-Ziv 이론으로 최초로 수량화.
- **예상 복합 효과**: 재압축 트리거 횟수 −40~60% (불필요한 재압축 제거), 메모리 안정성 향상 (버전 표류로 인한 stale KV 재압축 최적화), accuracy delta ±0.4~0.8%
- **구현 난이도**: low (C-1 α_l 추정 코드 + B-1 Gate 3 코드 조합)
- **우선순위**: 3
