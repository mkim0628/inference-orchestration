Grounded Cache Routing(2605.27494)의 4-게이트 동시 검증 — (1) 쿼리 유사도, (2) 검색 증거 중복, (3) 소스 버전 유효성, (4) 어휘/심판 지지도 — 을 `src/scheduler/`의 RAG 요청 처리 경로에 경량 pre-check로 추가하면, "잘못된 KV 재사용으로 인한 정확도 저하"를 방지하는 안전망을 구축하면서 Activity C의 accuracy-preserving 제약(±1% 이내)을 RAG 도메인에서도 강제할 수 있다. 과거 29개 사이클의 모든 A 기법에서 "RAG 캐시 재사용의 안전성 조건을 다중 게이트로 정형화한 라우터"가 없었다.
- **접근 방법**:
  1. `GroundedCacheRoutingGateScheduler` 클래스 (`src/scheduler/grounded_cache_routing_gate.py`): `BaseScheduler` 상속
  2. **4-게이트 동시 검증 설계**:
     ```python
     class GroundedCacheGate:
         def check_all_gates(self, query, cached_result, current_retrieval, corpus_version) -> GateResult:
             g1 = self._query_similarity_gate(query, cached_result.query)  # cosine sim > θ_q
             g2 = self._evidence_overlap_gate(current_retrieval, cached_result.retrieval)  # chunk overlap > θ_e
             g3 = self._source_version_gate(corpus_version, cached_result.corpus_version)  # 버전 일치
             g4 = self._lexical_support_gate(current_retrieval, cached_result.answer)  # 어휘/지지도 > θ_l
             return GateResult(safe=all([g1, g2, g3, g4]), failed_gates=[g for g, ok in zip(["q","e","v","l"],[g1,g2,g3,g4]) if not ok])
     ```
  3. **게이트별 임계값 설정**:
     - 게이트 1 (쿼리 유사도): `θ_q = 0.90` (코사인 유사도) — YAML 외부화.
     - 게이트 2 (증거 중복): `θ_e = 0.70` (청크 Jaccard 중복) — YAML 외부화.
     - 게이트 3 (소스 버전): 정확 일치 (버전 태그 비교, 추가 LLM 호출 불필요).

  4. **게이트 결과에 따른 라우팅**:

     - 게이트 실패: 캐시 재사용 거부 → 전체 재계산 경로. 실패 게이트 ID 로깅.

  5. **경량 구현 최적화**:

     - 게이트 1(쿼리 유사도): 기존 임베딩 캐시 재사용 → 추가 연산 없음.

     - 전체 4-게이트 오버헤드 추정: < 1ms/요청.

## Activity C 아이디어

### 아이디어 C-1: SphericalKVRateDistortionRetentionJointCodec (SPHERICAL KV 구형 파라미터화 + Rate-Distortion Retention 공동 최적화 코덱)
- **가설**: 기존 KV 캐시 압축 방법들이 토큰 선택(퇴거)과 정밀도 할당(양자화)을 독립적으로 최적화하는 분리된 파이프라인을 사용하는 반면, SPHERICAL KV(2605.18856)의 두 컴포넌트 — (1) Angle-Domain Attention(ADA): Key를 스칼라 반경 + 컴팩트 각도 코드의 구형 파라미터화로 저장하고 밀집 Key 재구성 없이 각도 코드에서 직접 어텐션 로짓 계산, (2) Rate-Distortion Retention(RDR): 고정 메모리 예산 하에서 토큰별·헤드별 keep/drop 결정과 정밀도 티어를 Rate-Distortion 이론으로 공동 최적화 — 을 `src/cache/` 레이어에 독립 압축 코덱으로 구현하면, HBM 트래픽을 직접 줄이면서 토큰 선택과 정밀도 할당의 파레토 최적 솔루션을 달성해 동일 메모리 예산에서 기존 분리 최적화 대비 정확도를 더 잘 보존할 수 있다. 과거 29개 사이클의 모든 C 기법에서 "어텐션 기하학(구형 파라미터화 Key)을 Rate-Distortion 이론과 통합해 토큰 선택·정밀도를 공동 최적화"하는 기법이 없었다.
- **접근 방법**:
  1. `SphericalKVADACodec` 클래스 (`src/cache/spherical_kv_ada_codec.py`): `CompressionCodec` 인터페이스 구현
  2. `SphericalKVRDRRetentionCodec` 클래스 (`src/cache/spherical_kv_rdr_codec.py`): `CompressionCodec` 인터페이스 구현
  3. **ADA — Key 구형 파라미터화 (Angle-Domain Attention)**:
     - Key 텐서 분해: `K[t, h] = r[t, h] × direction(θ[t, h])` — 스칼라 반경 `r`(FP16) + 각도 코드 `θ`(INT4/INT8 압축 가능).
     - 각도 코드 저장: `K_angle = quantize_angle(K / ||K||)` — 방향 정보만 압축 저장. FP16 대비 각도 코드 50~75% 저장 공간 절감.
     - 어텐션 로짓 계산: `score[t] = r[t] × (Q · direction(θ[t]))` — Key 재구성 없이 직접 계산.
     - paged·block-local 호환 설계: 각도 코드가 블록 단위로 저장되어 PagedAttention 블록 관리자와 호환.
  4. **RDR — Rate-Distortion 기반 공동 토큰-정밀도 최적화 (Rate-Distortion Retention)**:
     - 최적화 문제 공식화: 고정 비트 예산 `B` 하에서 어텐션 왜곡 최소화:
       ```
       min_{S, P} D(S, P)  s.t.  Σ_t R(s_t, p_t) ≤ B
       ```
       - `S = {s_t}`: 토큰별 keep(1)/drop(0) 결정.
       - `P = {p_t}`: 토큰별 정밀도 티어 (INT4/INT8/FP16).
       - `R(s_t, p_t)`: 비트 비용 (drop → 0비트, INT4 → 4비트/요소, INT8 → 8비트, FP16 → 16비트).
       - `D(S, P)`: 어텐션 출력 왜곡 추정 (어텐션 가중치 분포 변화).
     - 그리디 솔루션: 각 토큰-헤드에 대해 단위 비트당 왜곡 감소율(`ΔD/ΔR`)이 높은 순으로 예산 배분 → tier-homogeneous 페이지 생성.
     - `rdr_budget_bits`: 토큰별 총 비트 예산. YAML 외부화.
  5. **ADA + RDR 통합 코덱**:
     ```python
     class SphericalKVJointCodec(CompressionCodec):
         def compress(self, kv_cache, budget_bits):
             # ADA: Key를 각도 코드로 압축
             K_angle, K_radius = self.ada.decompose(kv_cache.K)
             # RDR: 토큰 선택 + 정밀도 티어 공동 결정
             keep_mask, precision_tier = self.rdr.optimize(kv_cache, budget_bits)
             # 결합 저장
             return SphericalKVEntry(
                 K_angle=quantize(K_angle[keep_mask], precision_tier),
                 K_radius=K_radius[keep_mask],
                 V=quantize(kv_cache.V[keep_mask], precision_tier),
                 keep_mask=keep_mask
             )
     ```
  6. **accuracy-preserving 근거**:
     - (1) ADA의 각도 코드: Key의 방향 정보를 보존하며 스칼라 반경은 FP16 유지 → 어텐션 로짓 계산 정확도 수학적으로 동등. 양자화 오차는 INT4→INT8 정밀도 티어로 제어 가능.
     - (2) RDR의 Rate-Distortion 최적화: 단순 top-k 선택 대비 동일 비트 예산에서 왜곡 최소화를 수학적으로 보장 — 파레토 최적 토큰-정밀도 결합이 분리 최적화보다 accuracy delta를 낮게 유지.
     - (3) tier-homogeneous 페이지: 같은 정밀도 토큰을 동일 페이지에 배치 → 코얼리스드 읽기로 HBM 트래픽 효율화, 혼합 정밀도 오버헤드 최소.
     - (4) Fallback: accuracy delta > 1% 시 `rdr_budget_bits` 증가(비트 예산 완화)로 안전망.
     - 검증: WikiText-2 perplexity ±1% + RULER-4K/16K + LongBench 8개 서브태스크 + ADA 단독 / RDR 단독 / 결합 3-way 비교 + `budget_bits` 스윕(각도 코드 정밀도별) + 독립 퇴거+양자화 파이프라인 대비 accuracy-memory 트레이드오프 비교.
  7. **이전 C 기법과의 차별점**:
     - OScaR(2605.19660, 이미 보고): 양자화 정확도 인증 (Rate-Distortion 없음, 구형 파라미터화 없음).
     - TriAxialKV(2605.17170, 이미 보고): 의미적 역할 3축 INT2/INT4 혼합 정밀도 (기하학 없음, 토큰 선택 없음).
     - IndexMemEvictionCodec(05-27 C-1): Learnable Indexer + Latent Memory (구형 파라미터화 없음, RDR 없음).
     - SphericalKVJointCodec: **Key 구형 파라미터화 + Rate-Distortion 이론으로 토큰 선택·정밀도를 공동 최적화 — 어텐션 기하학을 KV 압축 프레임워크에 통합한 최초의 C 기법.**
- **예상 효과**: 메모리 −40~60% (ADA 각도 코드 압축 + RDR 토큰 선택 결합), accuracy delta ±0.5~0.8% (Rate-Distortion 최적화로 분리 파이프라인 대비 개선), HBM 트래픽 −30~50% (각도 코드 직접 어텐션 계산으로 밀집 Key 재구성 불필요)
- **accuracy-preserving 근거**: 위 섹션 6 참조.
- **구현 난이도**: medium
- **우선순위**: 1

### 아이디어 C-2: MinimalInterventionFacilityLocationVSpaceDiversityEvictionCodec (Minimal-Intervention V-공간 다양성 페널티 greedy facility-location 퇴거 코덱)
- **가설**: 소예산(small-budget) KV 압축에서 argmax-top-k 토큰 선택이 V-공간에서 중복 토큰을 반복 선택해 정보 밀도를 낮추는 구조적 취약점이 있다. Minimal-Intervention KV Retention(2605.14292)의 제안 방법 α — TriAttention 보존 스코어러에 V-공간 중복성 페널티(V-space redundancy penalty)를 추가하는 단일 λ 파라미터 수정 — 을 `src/cache/segmented.py`의 현재 top-k 토큰 선택 로직에 적용하면, argmax-top-k를 greedy facility-location 기반 선택으로 교체해 소예산 환경에서 V-공간 다양성을 강제하고 추론(reasoning) 워크로드의 정확도를 향상시킬 수 있다. 과거 29개 사이클의 모든 C 기법에서 "V-공간 다양성 페널티를 greedy facility-location 선택에 통합한 토큰 퇴거 알고리즘"이 없었다.
- **접근 방법**:
  1. `MinimalInterventionFacilityLocationCodec` 클래스 (`src/cache/minimal_intervention_fl_codec.py`): `CompressionCodec` 인터페이스 구현
  2. **argmax-top-k의 V-공간 중복성 문제 수정**:
     - 기존 top-k 선택: `keep_set = argmax_topk(importance_scores, k)` — 중요도 높은 k개 토큰 단순 선택. V-공간에서 유사한 토큰이 반복 선택되어 정보 다양성 감소.
     - 수정된 greedy facility-location 선택:
       ```python
       def facility_location_selection(importance_scores, V_matrix, k, lambda_div):
           keep_set = []
           for _ in range(k):
               # 다음 토큰 선택: 중요도 + V-공간 다양성 결합
               diversity_bonus = [min_distance_to_selected(v_t, keep_set, V_matrix) for v_t in range(n_tokens)]
               combined_score = importance_scores + lambda_div * diversity_bonus
               next_token = argmax(combined_score)
               keep_set.append(next_token)
           return keep_set
       ```
     - `min_distance_to_selected(v_t, keep_set, V)`: 토큰 t의 V 벡터와 이미 선택된 토큰들의 V 벡터 집합 간 최소 거리 (코사인 거리).
     - `lambda_div`: V-공간 다양성 페널티 가중치 (기본 0.5, YAML 외부화).
  3. **TriAttention 스코어러와의 통합**:
     - `importance_scores = TriAttentionScorer.score(kv_cache)` — TriAttention(2604.04921, 이미 보고)의 보존 스코어 직접 재사용.
     - TriAttention이 없는 환경: `importance_scores = snapkv_importance(kv_cache)` — fallback.
     - 단일 함수 수정: `TriAttentionScorer.select_tokens(k)` → `facility_location_selection(scores, V, k, lambda_div)` 교체만으로 구현 가능.
  4. **소예산 최적화 (b=64, b=128 기준)**:
     - 논문(2605.14292)에서 b∈{64, 128}에서 5패밀리 7메커니즘 비교 결과 α가 일관된 성능 향상 달성.
     - `budget_tokens`: 보존할 토큰 수 절대값. YAML 외부화. 기본: b=128.
     - 소예산(b≤128) 환경에서 V-공간 다양성 효과가 극대화 → `lambda_div` 자동 스케일: `lambda_div_eff = lambda_div × (128 / budget_tokens)` (예산이 작을수록 다양성 강화).
  5. **V-공간 거리 계산 효율화**:
     - `min_distance_to_selected`: 선택된 집합이 k개 → O(k)로 구현 가능. 총 선택 루프: O(n × k). n=512, k=128 기준 < 5ms (GPU 가속 없이).
     - GPU 가속: V 행렬 코사인 유사도를 `torch.cdist`로 배치 계산 → O(n × k) → < 0.5ms/선택.
  6. **accuracy-preserving 근거**:
     - (1) Minimal-Intervention(2605.14292) 원논문에서 α가 MATH-500(Qwen-7B/Llama-8B DeepSeek-R1-Distill)에서 5패밀리 모든 비교 기준선 대비 일관된 성능 향상을 b=64, b=128 양쪽에서 달성 — ±1% 이내 accuracy 보존 요건 충족.
     - (2) V-공간 다양성 페널티: argmax-top-k가 중복 선택하는 정보량을 다양한 토큰으로 교체 → 정보 밀도 향상 → accuracy delta 감소 방향으로 작동.
     - (3) TriAttention 스코어러 재사용: TriAttention(2604.04921)이 이미 AIME25에서 10.7× KV 절감을 달성하면서 검증된 기법 → α는 이 위에서 단일 λ 수정만 추가.
     - (4) Fallback: accuracy delta > 1% 시 `lambda_div` 감소(0.5 → 0.25)로 다양성 강도 완화.
     - 검증: WikiText-2 perplexity ±1% + MATH-500 추론 정확도 + b∈{64, 128, 256} 스윕 + `lambda_div`(0.25/0.5/0.75/1.0) 별 accuracy-memory + argmax-top-k vs. facility-location 직접 비교 + TriAttention 스코어러 vs. SnapKV 스코어러 베이스라인 비교.
  7. **이전 C 기법과의 차별점**:
     - TriAttention(2604.04921, 이미 보고): pre-RoPE 집중도 기반 top-k 퇴거 (V-공간 다양성 없음).
     - H2O/SnapKV/PyramidKV (과거): 어텐션 가중치 기반 top-k (V-공간 다양성 없음).
     - DapQPositionAwareEvictionCodec(05-22 C-3): 위치-인식 유사 쿼리 중요도 (V-공간 다양성 없음).
     - MinimalInterventionFacilityLocationCodec: **argmax-top-k를 greedy facility-location으로 교체해 V-공간 다양성을 선택에 직접 통합 — V-공간 중복성 문제를 단일 λ 파라미터로 해결하는 최초의 C 기법.**
- **예상 효과**: 메모리 −30~50% (소예산 b=64~128 기준), accuracy delta ±0.3~0.6% (소예산 추론 워크로드 기준, 원논문 성능 향상 기반), 소예산 reasoning 정확도 향상 (MATH-500 류 추론 태스크 특히 효과적)
- **accuracy-preserving 근거**: 위 섹션 6 참조.
- **구현 난이도**: low
- **우선순위**: 2

### 아이디어 Cross-1: COMBNativePICSphericalKVAngleCodeBCIntegrationCodec (B+C) — COMB Native PIC cross-attention KV × SPHERICAL KV 각도 코드 통합 압축 파이프라인
- **조합 근거**: COMB(B-1)의 encoder cross-attention이 세그먼트 KV를 위치-독립적으로 저장하고, SPHERICAL KV(C-1)의 ADA가 Key를 각도 코드 + 스칼라 반경으로 분해한다. COMB encoder cross-attention의 Key를 SPHERICAL KV의 각도 코드로 저장하면 — "위치-독립 KV 캐시(COMB) + 각도 코드 압축(SPHERICAL KV ADA)"의 통합이 가능하다. 특히 COMB의 encoder cross-attention에서 Query가 각도 코드와 직접 내적해 어텐션 로짓을 계산하면 밀집 Key 재구성 없이 Native PIC + ADA가 단일 패스에서 작동한다. 트렌드 리포트의 B+C 시너지 포인트를 구체화한 아이디어다.
- **구체 설계**:
  1. `COMBSphericalKVPipeline` 모듈 (`src/engine/comb_spherical_kv_pipeline.py`)
  2. **통합 KV 저장 구조**:
     ```python
     @dataclass
     class COMBSphericalKVEntry:
         segment_id: bytes                    # SHA256(token_content) — 위치-무관
         encoder_K_angle: Tensor              # [n_encoder_layers, n_heads, n_tokens, angle_dim] INT8
         encoder_K_radius: Tensor             # [n_encoder_layers, n_heads, n_tokens] FP16
         encoder_V: Tensor                    # [n_encoder_layers, n_heads, n_tokens, head_dim] (RDR 정밀도 티어)
         rdr_precision_tier: Tensor           # 토큰별 정밀도 티어 (INT4/INT8/FP16)
         keep_mask: Tensor                    # RDR 토큰 선택 마스크
     ```
  3. **통합 처리 흐름**:
     - **Step 1 (세그먼트 분할, B-1 COMB)**: CDC 청킹으로 세그먼트 분할 → `segment_id = SHA256(token_content)`.
     - **Step 2 (COMB encoder cross-attention 실행)**: encoder 레이어가 세그먼트에 대해 cross-attention KV 계산.
     - **Step 3 (ADA 분해, C-1 SPHERICAL KV)**: `K = r × direction(θ)` — 각도 코드 + 반경 분리. `K_angle = quantize_angle(K / ||K||)` (INT8).
     - **Step 4 (RDR 공동 최적화, C-1 SPHERICAL KV)**: 메모리 예산 하에서 토큰 선택 + 정밀도 티어 공동 결정.
     - **Step 5 (통합 KV 저장)**: `COMBSphericalKVEntry` 형태로 CacheStore에 저장.
     - **Step 6 (재사용 시 cross-attention)**: Query × `K_angle_reconstructed` → 밀집 Key 재구성 없이 직접 어텐션 로짓 계산. 위치 수정 불필요 (COMB Native PIC).
  4. **ADA-COMB 수학적 호환성**:
     - COMB encoder의 cross-attention에서 `score[t] = Q · K_encoded[t]`. ADA 적용 시 `K_encoded[t] = r[t] × direction(θ[t])` → `score[t] = r[t] × (Q · direction(θ[t]))`.
     - `Q · direction(θ[t])`: Query와 Key 방향의 내적 — 각도 코드에서 직접 계산 가능.
     - 이 수학적 구조로 COMB cross-attention 경로에서 ADA가 밀집 Key 재구성 없이 직접 작동.
  5. **V-공간 다양성 통합 (C-2 facility-location)**:
     - COMB + SPHERICAL KV 파이프라인에서 RDR 토큰 선택 단계에 Minimal-Intervention α의 facility-location을 추가 적용하면 세 기법의 3-way 결합 가능.
     - `SphericalKVJointCodec.compress(kv, budget_bits)` → `facility_location_selection(rdr_scores, V, k, lambda_div)`.
- **예상 복합 효과**: 처리량 +3~5× (COMB Native PIC 3× + SPHERICAL KV HBM 효율 복합), 메모리 −50~70% (ADA 각도 코드 압축 + RDR 토큰 선택 결합), 비연속 히트율 +60~80% (COMB 위치-무관 세그먼트 재사용), accuracy delta ±0.5~0.8% (ADA 기하학적 보존 + RDR 파레토 최적)
- **구현 난이도**: medium
- **우선순위**: 1

### 아이디어 Cross-2: ResidentKVClaimsCOMBSegmentProtectedABScheduler (A+B) — Resident KV Claims 계약 보호 + COMB Native PIC 세그먼트 선제 확보 통합 스케줄러
- **조합 근거**: COMB(B-1)의 Native PIC cross-attention이 특정 세그먼트 집합에 대한 미래 재사용 의도를 생성하고, Resident KV Claims(A-1)가 해당 세그먼트의 encoder cross-attention KV를 스케줄러-가시적 계약으로 경성 보호 등록한다. COMB가 발견한 재사용 가능 세그먼트를 Claims 계약으로 보호하면 "COMB가 세그먼트를 재사용하기로 계획 → Claims가 해당 KV를 퇴거에서 보호 → 계획된 시점에 HBM에서 즉시 히트"의 A+B 통합 파이프라인이 완성된다. 트렌드 리포트의 A+B 시너지 포인트를 구체화한 아이디어다.
- **구체 설계**:
  1. `COMBResidentClaimsProtectedPipeline` 모듈 (`src/engine/comb_resident_claims_pipeline.py`)
  2. **통합 처리 흐름**:
     - **Step 1 (세그먼트 재사용 의도 생성, B-1 COMB)**: `ThreeTrackArchAwarePICRouter.find_reusable_segments(session_tokens)` → 재사용 가능 COMB 세그먼트 목록.
     - **Step 2 (Resident KV Claims 등록, A-1)**: 각 재사용 가능 세그먼트에 대해:
       ```python
       claim = ResidentKVClaim(
           segment_id=seg_id,
           materialization_predicate=lambda: session_active(),
           lifecycle_state="resident",
           feasibility_outcome=None,
           claim_telemetry={"planned_reuse_time": eta_ttft}
       )
       claims_scheduler.register(claim)
       ```
     - **Step 3 (KV 풀 충돌 사전 방지)**: Claims 등록 시점에 KV 풀 충돌 검사 → 충돌 발견 시 능동적 거부(active refusal) + 재스케줄링.
     - **Step 4 (보호된 세그먼트 재사용, B-1)**: 계획된 시점에 `COMBNativePICCrossAttentionCache.get(segment_id)` → HBM 즉시 히트 (보호 클레임으로 퇴거 방지).
  3. **Grounded Cache Routing 연결 (A-2 안전성 게이트)**:
     - Claims 등록 전 Grounded Cache Routing의 게이트 2·3(증거 중복·소스 버전)으로 COMB 세그먼트의 스테일니스 검사.
     - 게이트 실패 세그먼트는 Claims 등록 제외 → 스테일 세그먼트 보호 방지.
- **예상 복합 효과**: 처리량 +3~5× (COMB Native PIC × Claims 보호로 HBM 히트율 극대화), TTFT −51~94% (COMB Native PIC, 보호 클레임으로 재계산 제거), KV 퇴거율 감소 −40~60% (보호 클레임 + 사전 충돌 방지), Scheduling overhead TTFT +3% 이내 (Claims 등록: O(1) + 충돌 검사: O(claims_count))
- **구현 난이도**: medium
- **우선순위**: 2

### 아이디어 Cross-3: COMBSphericalKVResidentClaimsFacilityLocationABCPipeline (A+B+C) — Resident KV Claims + COMB Native PIC + SPHERICAL KV + V-공간 다양성 통합 파이프라인
- **조합 근거**: 트렌드 리포트(2026-05-30)의 A+B+C 3-Way 6단계 시너지를 구체화한다.   1. `COMBSphericalResidentClaimsABCPipeline` 모듈 (`src/engine/comb_spherical_abc_pipeline.py`)

     - **Step 4 (SPHERICAL KV ADA + RDR 압축, C-1)**: cross-attention KV를 각도 코드 + Rate-Distortion 공동 최적화로 압축 저장.

  3. **비동기 파이프라이닝**:

- **예상 복합 효과**: 처리량 +4~6× (COMB Native PIC 3× + SPHERICAL KV HBM 효율 × Claims 보호 히트율 극대화 × HexAGenT DAG SLO 스케줄링 복합), 메모리 −60~80% (SPHERICAL KV ADA + RDR + Minimal-Intervention α 결합), 비연속 히트율 +70~90% (COMB + Claims 보호 + Grounded 안전성 검증), accuracy delta ±0.5~0.8% (Rate-Distortion 최적화 + V-공간 다양성 + Grounded 안전성 보장)
- **구현 난이도**: high
- **우선순위**: 4
