# 트렌드 리포트 — 2026-05-22

## 전체 요약

2026-05-21 이후 새로 발표된 2605.2x 계열 신규 논문은 아직 공개되지 않았다. 이번 수집은 직전 리포트 사이클에서 누락된 2602~2603 계열 선행 논문들을 보완하는 구성이다. Activity A에서는 PPD 분리(2603.13358)가 멀티-턴 P/D 분리의 핵심 비효율—반복 KV 전송 대역폭 포화—을 "append-prefill은 decode 노드에서 로컬 처리" 라우팅으로 해결해 Turn 2+ TTFT를 68% 단축했고, DualMap(2602.06502)은 캐시-어피니티와 로드 밸런싱의 상충을 이중 해시 매핑으로 해소해 처리량을 2.25× 향상시켰으며, CacheTTL(2511.02230 v4)은 에이전틱 멀티-턴 환경의 KV TTL 메커니즘으로 평균 Job Completion Time을 8× 단축했다. Activity B는 이번 주에도 신규 논문이 없어 4주째 소강 상태다. Activity C에서는 세 편의 압축 논문—VQKV(82.8% 압축 + 98.6% 정확도 보존), EchoKV(유사도 기반 잔차 재구성), DapQ(위치-인식 유사 쿼리 기반 퇴거)—이 확인됐다. 전반적으로 P/D 분리 환경의 KV 전송 최적화 문제가 다각적으로 수렴하는 흐름이며, 압축 분야에서는 고압축비-고정확도 동시 달성을 위한 벡터 양자화 접근이 복수의 독립 연구에서 재현되고 있다.

## Activity A — KV Cache-aware Scheduling / Orchestration

### 새로운 논문·구현체

#### 1. [Not All Prefills Are Equal: PPD Disaggregation for Multi-turn LLM Serving](https://arxiv.org/abs/2603.13358)
- **출처**: arXiv 2603.13358 (2026-03-17, Zongze Li, Jingyu Liu, Zach Xu, Yineng Zhang, Tahseen Rabbani, Ce Zhang)
- **핵심 아이디어**: 멀티-턴 P/D 분리 환경에서 두 가지 구조적 비효율을 식별하고 해결한다. (1) 매 턴마다 이전 프롬프트+응답 전체를 프리필해야 하는 반복 프리필 오버헤드, (2) 프리필 노드와 디코딩 노드 간 KV 반복 전송이 대역폭을 포화시켜 지연 폭발로 이어지는 문제. 핵심 통찰: "append-prefill"(캐시된 KV를 재사용하면서 신규 입력 토큰만 처리)은 full prefill보다 디코딩 지연 영향이 훨씬 적으므로, Turn 2+ 요청의 append-prefill을 디코딩 노드에서 로컬로 처리하는 것이 최적이다. 제안 시스템 PPD(Prefill Prefill-capable Decode) disaggregation은 현재 워크로드, SLO, KV 전송 비용을 바탕으로 append-prefill을 프리필 노드로 보낼지 디코딩 노드에서 처리할지를 동적으로 라우팅한다. 기존 전통적인 PD 배포와 seamless하게 통합된다.
- **연구 목표와의 관련성**: high
- **주목할 점**: Turn 2+ TTFT를 **68% 단축**하면서 TPOT는 경쟁적 수준 유지. P/D 분리 환경에서 "모든 프리필을 프리필 노드로 보내야 한다"는 고정 관념을 깨는 논문이다. AMPD(이미 보고, 2602.14516)가 "어느 노드에서 증분 프리필을 수행하고 KV를 언제 전송할 것인가"를 오프라인 플랜 + 온라인 적응으로 결정했다면, PPD는 동일 문제를 "append-prefill 유형 분류 → SLO-인식 동적 라우팅"으로 더 경량화해 기존 PD 배포에 투명하게 오버레이한다. Activity A의 "KV 전송 오버헤드 최소화"와 "disaggregated prefill 최적화" 목표를 멀티-턴 워크로드 특화 관점에서 가장 직접적으로 다루는 최근 논문이다. KVServe(이미 보고, 2605.13734)의 Bayesian Profiling이 P/D 환경에서 압축 전략으로 KV 전송 비용을 흡수한다면, PPD는 전송 자체를 회피하는 라우팅 전략이라는 보완적 방향을 제시한다.

#### 2. [DualMap: Enabling Both Cache Affinity and Load Balancing for Distributed LLM Serving](https://arxiv.org/abs/2602.06502)
- **출처**: arXiv 2602.06502 (2026-02, OpenReview에도 등재)
- **핵심 아이디어**: 분산 LLM 서빙에서 캐시-어피니티 스케줄링(동일 프롬프트 → 동일 인스턴스 → KV 재사용)과 로드 밸런싱(요청을 인스턴스에 균등 분배)이 구조적으로 상충한다는 문제를 다룬다. DualMap은 각 요청을 두 개의 독립 해시 함수로 두 인스턴스 후보에 매핑한 후, 현재 시스템 상태(부하, TTFT 여유)를 기반으로 더 나은 후보를 선택하는 "이중 매핑(dual-mapping)" 전략을 제안한다. 세 가지 보조 메커니즘: (1) **SLO-인식 요청 라우팅** — TTFT SLO 성능에 따라 캐시-어피니티와 부하-인식 라우팅 간 전환, (2) **핫스팟-인식 재균형** — 과부하 인스턴스에서 과소 인스턴스로 요청을 동적 이관, (3) **경량 이중-해시-링 스케일링** — 인스턴스 추가/제거 시 전역 재매핑 없이 빠른 스케일 지원.
- **연구 목표와의 관련성**: high
- **주목할 점**: 동일 TTFT SLO 하에서 유효 요청 처리 용량 **최대 2.25× 향상**. Activity A의 "prefix-aware batching"과 "cache-locality scheduling"이 단일 인스턴스 수준의 캐시 히트율 최적화에 집중한다면, DualMap은 분산 인스턴스 클러스터 수준에서 캐시 어피니티와 부하 분산을 동시에 달성하는 클러스터-레이어 스케줄링이다. GORGO(이미 보고)가 크로스-리전 KV 라우팅에서 캐시 재사용과 네트워크 지연을 최적화한다면, DualMap은 동일 클러스터 내 인스턴스 간 캐시 어피니티와 로드 밸런싱의 상충을 해소하는 상보적 레이어다. 두 독립 해시 함수의 두 후보 중 런타임 상태로 선택하는 메커니즘은 Activity A의 "request reordering"에서 단일 최적 인스턴스 탐색을 상수 시간으로 근사하는 실용적 구현 패턴이다.

#### 3. [CacheTTL: Efficient and Robust Multi-Turn LLM Agent Scheduling with KV Cache Time-to-Live](https://arxiv.org/abs/2511.02230)
- **출처**: arXiv 2511.02230 (2025-11 최초 제출, v4 2026-05-04 갱신 — Continuum에서 CacheTTL로 제목 변경)
- **핵심 아이디어**: 에이전틱 워크로드에서 LLM이 도구 호출 후 대기(tool execution pause)를 반복하는 동안 기존 추론 엔진이 해당 요청의 KV 캐시를 퇴거시켜 다음 LLM 호출 시 전체 KV를 재계산해야 하는 비효율을 해결한다. CacheTTL은 요청 완료 후에도 KV 캐시를 GPU 메모리에 TTL(Time-To-Live) 동안 보존한다. TTL 계산은 예측된 도구 호출 실행 시간, 스케줄링 측 지연 전파, 워크로드 패턴을 종합해 KV 보존의 비용-편익을 정량화한다. KV 보존 결정을 도구 호출 완료 예측 기반의 확률적 모델로 공식화하며, 기존 서빙 엔진의 스케줄러 레이어에 경량 미들웨어로 통합 가능하다.
- **연구 목표와의 관련성**: high
- **주목할 점**: SWE-Bench, BFCL, OpenHands 실세계 에이전트에서 Llama-3.1 8B/70B, Gemma-3 12B, GLM-4.5 355B 평균 **JCT(Job Completion Time) 8× 단축** + 처리량 향상. 2026-05-04에 v4로 대규모 갱신되며 제목도 CacheTTL로 확정됐다는 점이 주목할 만하다 — v4 갱신이 실세계 에이전트 평가 결과를 추가한 것으로 논문이 강화됐음을 시사한다. CONCUR(이미 보고, 2601.22705)가 혼잡 기반으로 에이전트 수를 제한해 스래싱을 사전 방지하는 "입장 제어" 방식이라면, CacheTTL은 개별 에이전트의 KV를 TTL로 보존해 다음 호출 시 재계산 비용을 제거하는 "보존 연장" 방식으로, 두 접근은 에이전틱 KV 관리에서 완벽히 상보적이다. ThunderAgent(이미 보고, 2602.13692)의 Program 정적 분석이 도구 호출 실행 시간을 사전 추정하는 데 활용되면, CacheTTL의 TTL 계산 정확도가 향상되는 조합이 가능하다.

## Activity B — Non-Contiguous KV Cache Reuse

### 새로운 논문·구현체

이번 기간(2026-05-22 기준 최근 7일) 관련성 high/medium의 신규 항목이 발견되지 않았다. NeurIPS 2026 제출 마감 전후 소강 상태가 4주째 지속되고 있다.

CacheTTL(Activity A 등재)의 TTL 기반 KV 보존 연장이 Activity B와 맞닿는 지점이 있다. 에이전틱 도구 호출 간 TTL로 보존된 KV는 이전 에이전트 단계의 비연속 KV 세그먼트이기도 하다. CacheTTL이 이 KV를 보존하고 CONCUR가 입장 제어로 GPU KV 풀 여유를 확보하면, Activity B의 비연속 세그먼트 재사용 알고리즘이 에이전틱 워크플로우 내 KV를 더 오래, 더 많이 활용할 수 있는 환경이 만들어진다. "CacheTTL TTL 보존(A) → 비연속 세그먼트 재조합 가능 기간 연장(B) → SpecAttn 희소 접근으로 KV 절약(C)"의 에이전틱 3단 파이프라인이 이 논문들의 자연스러운 조합이다.

PPD(Activity A 등재)의 "append-prefill을 decode 노드에서 로컬 처리하며 캐시된 KV를 재사용"하는 접근은 Activity B의 비연속 KV 재사용과 동일한 문제 축을 다룬다. PPD는 "동일 세션 내 이전 턴 KV를 연속적으로 재사용"하는 반면, Activity B는 "서로 다른 요청 간 비연속 세그먼트를 재사용"하는 방향이다. 두 접근의 경계에서 "멀티-턴 세션의 turn-level KV를 비연속 세그먼트로 보존·재조합"하는 세션-인식 비연속 재사용 아키텍처가 새로운 설계 공간이 된다.

### 동향 변화 감지

| 기법 | 이전 상태 | 이번 주 변화 |
|------|---------|------------|
| Segmented Hash / Radix | SGLang RadixAttention 안정화, RelayCaching·ICaRus 발표 | 변화 없음 — 이번 주 신규 논문 없음 |
| CacheBlend / Blending | CacheBlend 구현체 공개 후 후속 연구 대기 중 | 변화 없음 |
| Position-independent caching | AdapShot RoPE 회전 기반 위치 재인코딩 | 변화 없음 |
| Semantic caching | SemantiCache, AdapShot 등 의미 기반 히트 연구 | 변화 없음 |
| Agentic non-contiguous reuse | RelayCaching 디코딩→프리필 KV 재사용, ThunderAgent Program 분석 | CacheTTL(A 등재)의 TTL 보존이 에이전틱 KV의 세그먼트 유효 수명을 연장 — 비연속 재사용 창이 도구 호출 간격만큼 확장되는 간접 효과 |
| Multi-turn session KV | AMPD(2602.14516) 멀티-라운드 증분 프리필 KV 지연 읽기 | PPD(2603.13358, A 등재)의 append-prefill 로컬 처리가 멀티-턴 세션의 turn-level KV 재사용을 네트워크 전송 없이 실현 — 세션-인식 비연속 재사용 설계 공간 부각 |

## Activity C — KV Cache Compression

### 새로운 논문·구현체

#### 1. [VQKV: High-Fidelity and High-Ratio Cache Compression via Vector-Quantization](https://arxiv.org/abs/2603.16435)
- **출처**: arXiv 2603.16435 (2026-03-17, Yixuan Wang 외 5인 — SJTU, Shanghai Innovation Institute, Shanghai AI Lab, Cambridge, NUS)
- **핵심 아이디어**: 기존 학습-프리(training-free) KV 압축 방법들이 저랭크 근사(차원 축소) 또는 스칼라 양자화(독립 스칼라 압축)에 한정되어 고압축비와 고정확도를 동시에 달성하지 못하는 한계를 해결한다. VQKV는 각 KV 캐시 벡터를 단위로 삼아 복수의 코드북에서 가장 가까운 항목으로 매핑하고, 수천 개의 부동소수점 대신 정수 인덱스만 저장하는 벡터 양자화(VQ) 방식을 도입한다. 프리필 단계에서 각 KV 벡터를 KV 코드로 압축하고, 디코딩 시 인덱스로부터 근사 KV를 복원한다. 학습 없이 오프라인 코드북 구성만으로 동작한다.
- **연구 목표와의 관련성**: high
- **주목할 점**: LLaMA3.1-8B 기준 **82.8% 압축률에서 LongBench 베이스라인 98.6% 정확도 보존** + 동일 메모리 예산에서 **4.3× 긴 생성 길이** 지원. Activity C의 "KV 캐시 메모리 −30% 이상" + "압축 정확도 delta ±1% 이내" 목표를 학습 없이 동시에 달성하는 방법이다. FibQuant(이미 보고, 2605.11478)가 랜덤-접근 VQ로 토큰 선택적 압축을 실현했다면, VQKV는 동일한 VQ 방향을 고압축비-고정확도 동시 달성의 관점에서 확장한 독립 연구다. 두 방법의 차이: FibQuant는 랜덤-접근 복원 효율에 집중하고, VQKV는 코드북 설계로 82.8% 압축에서 98.6% 정확도 보존에 집중한다. 비연속 세그먼트(Activity B)를 VQKV로 압축하면 각 세그먼트의 메모리 점유가 80% 이상 줄어들어 동일 KV 풀에 더 많은 비연속 세그먼트를 유지할 수 있다는 점에서 B+C 시너지가 직접적이다.

#### 2. [EchoKV: Efficient KV Cache Compression via Similarity-Based Reconstruction](https://arxiv.org/abs/2603.22910)
- **출처**: arXiv 2603.22910 (2026-03-24, GitHub: github.com/noforit/EchoKV)
- **핵심 아이디어**: 기존 저랭크 압축 방법들이 비가역 파라미터 변환에 의존해 메모리가 충분할 때 풀-프리시전 추론으로 전환이 불가능한 유연성 결여 문제를 해결한다. EchoKV는 레이어 간(inter-layer)·레이어 내(intra-layer) 어텐션 헤드 유사성을 활용해 부분 KV 부분집합에서 잔차 KV 성분을 경량 네트워크로 재구성(reconstruction)한다. 2단계 파인튜닝 전략: (1) 압축 네트워크 사전 학습(1 A100 GPU-시간, 7B 모델 기준), (2) 온라인 경량 파인튜닝으로 도메인-특화 정밀도 보완. 표준 추론과 압축 추론 간 온-디맨드 전환(on-demand switching)이 가능해 메모리 예산에 따라 유연하게 운용된다.
- **연구 목표와의 관련성**: high
- **주목할 점**: LongBench와 RULER 벤치마크에서 다양한 압축 비율에 걸쳐 기존 방법 대비 일관된 정확도 우위 + 단문 시나리오에서 높은 처리량 유지. "표준-압축 추론 간 온-디맨드 전환" 기능은 Activity C의 "정확도 보존(accuracy-preserving)" 제약과 직접 연관된다 — 메모리 예산이 충분한 요청은 풀-프리시전, 부족한 요청은 압축 모드로 동적 전환하는 시나리오가 Activity A의 KVServe 스타일 압축 예산 관리와 결합될 수 있다. Activity B의 비연속 세그먼트에서 레이어 간 유사성 기반 재구성 원리(EchoKV)를 적용하면, 비연속 세그먼트를 저장할 때 레이어 유사성이 높은 헤드의 KV를 압축 보존하고 재사용 시 재구성하는 "압축 비연속 세그먼트 캐시"가 설계 가능하다.

#### 3. [DapQ: Where Matters More Than What — Decoding-aligned KV Cache Compression via Position-aware Pseudo Queries](https://arxiv.org/abs/2603.11564)
- **출처**: arXiv 2603.11564 (2026-03-12, Zhenxu Tian, Yi Su, Juntao Li, Min Zhang — Soochow University; OpenReview에도 등재)
- **핵심 아이디어**: 기존 KV 캐시 퇴거 방법들이 프리필 단계의 어텐션 패턴으로 토큰 중요도를 추정하는 반면 실제 디코딩 단계 쿼리와의 불일치(query drift)가 발생해 중요 토큰이 잘못 퇴거되는 문제를 다룬다. 핵심 발견: **유사 쿼리(pseudo query)** 구성에서 **의미(semantic content)** 보다 **위치 정보(positional information)** 가 더 결정적 역할을 한다. DapQ는 위치-인식 유사 쿼리(position-aware pseudo queries)를 생성해 출력 토큰을 시뮬레이션하는 효과적인 관찰 창을 구성하고, 이를 KV 중요도 평가 기준으로 사용한다.
- **연구 목표와의 관련성**: high
- **주목할 점**: NIAH(Needle-In-A-Haystack)에서 **KV 캐시 예산 3%만으로 베이스라인 대비 99.5% 성능 유지**. Lookahead Q-Cache(2505.20334, EMNLP 2025)가 생성된 응답 접두사를 관찰 창으로 사용해 쿼리 불일치를 줄였다면, DapQ는 의미 대신 위치 정보가 핵심임을 실험으로 입증해 훨씬 경량화된 위치-인식 유사 쿼리 생성으로 동등 이상의 정확도를 달성한다. 이 발견은 Activity C의 "accuracy-preserving" 퇴거 정책 설계에서 KV 중요도 추정 시 위치 인코딩 신호를 의미 임베딩보다 우선시해야 한다는 구체적인 설계 원칙을 제공한다. Activity B의 비연속 세그먼트에서도 동일 원리 적용이 가능하다 — 비연속 세그먼트의 재사용 가능성 평가 시 의미 유사도보다 위치 기반 신호가 더 신뢰할 수 있는 기준이라는 가설이 성립한다.

## Activity 간 시너지 포인트

**A + C (PPD + VQKV/EchoKV)**
PPD가 멀티-턴 환경에서 KV 전송 자체를 decode 노드 로컬 처리로 우회한다면, 전송이 불가피한 full-prefill 요청에는 VQKV의 82.8% 압축으로 전송량을 대폭 줄이는 보완 전략이 가능하다. "PPD 라우팅 → append-prefill은 로컬 처리(전송 0) + full-prefill은 VQKV 압축 전송"의 2단 최적화가 멀티-턴 P/D 분리 환경에서 KV 대역폭 병목을 이중으로 해소한다. EchoKV의 온-디맨드 전환(메모리 여유 시 풀-프리시전, 부족 시 압축)은 CacheTTL의 TTL 기반 KV 보존과 결합해 "KV TTL이 만료되기 직전 EchoKV 압축 모드로 전환해 메모리 점유를 줄이면서 보존 기간을 연장"하는 TTL-압축 하이브리드 보존 정책이 가능하다.

**A + B (CacheTTL + 비연속 세그먼트 재사용)**
CacheTTL의 TTL 보존이 에이전틱 도구 호출 간 KV를 GPU에 유지한다면, Activity B의 비연속 세그먼트 재사용 알고리즘(Louver 검색 + AdapShot 재인코딩)이 이 보존된 KV를 세그먼트 단위로 재조합하는 데 활용할 수 있다. CONCUR(A)의 입장 제어 → CacheTTL(A)의 TTL 보존 → 비연속 세그먼트 재조합(B) → DapQ 위치-기반 중요도 평가(C)의 4단 에이전틱 KV 최적화 파이프라인이 가능하다.

**B + C (VQKV/EchoKV + 비연속 세그먼트)**
VQKV로 각 비연속 세그먼트를 82.8% 압축하면 동일 KV 풀에 유지 가능한 세그먼트 수가 ~5.8× 증가한다. EchoKV의 레이어 간 유사성 기반 재구성은 비연속 세그먼트들이 레이어별로 유사한 KV 패턴을 공유하는 경우 잔차만 저장해 압축률을 추가로 높이는 "비연속 세그먼트 증분 압축"으로 확장 가능하다. DapQ의 위치-인식 중요도 평가는 비연속 세그먼트의 재사용 가능성 예측에도 적용 가능하다.

**A + B + C (3-Way: PPD + 비연속 재사용 + VQKV + CacheTTL)**
- 멀티-턴 에이전틱 워크로드에서의 통합 파이프라인: PPD가 append-prefill을 decode 노드에서 로컬 KV 재사용으로 처리(A) → CacheTTL이 도구 호출 간 KV TTL 연장 보존(A) → 보존된 KV를 비연속 세그먼트로 재조합(B) → VQKV/EchoKV로 보존 세그먼트 압축(C) → DapQ 위치-기반 중요도 평가로 퇴거 결정(C). 이 파이프라인은 KVServe(A, 이미 보고)의 Bayesian 압축 전략 탐색과 결합하면 워크로드 특성에 따라 PPD 라우팅과 VQKV 압축 비율을 동적 최적화하는 완전한 멀티-턴 에이전틱 KV 관리 스택이 된다.
