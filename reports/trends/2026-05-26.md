## Activity A — KV Cache-aware Scheduling / Orchestration

### 새로운 논문·구현체

#### 1. [ObjectCache: Layerwise Object-Storage Retrieval for KV Cache Reuse](https://arxiv.org/abs/2605.22850)
- **출처**: arXiv 2605.22850 (2026-05-16 제출, Yu Zhu, Gustavo Alonso — ETH Zurich; Aditya Dhakal, Dejan Milojicic — HPE Labs; Yunming Xiao — CUHK Shenzhen)
- **핵심 아이디어**: GPU 메모리와 로컬 DRAM을 초과하는 KV 캐시 용량 문제를 해결하기 위해 S3 호환 오브젝트 스토리지를 KV 캐시 계층으로 사용하는 프로토콜-스케줄링 공동설계를 제안한다. 핵심 통찰: KV 캐시를 레이어 단위로 GPU가 소비하는 순서와 동일하게 전달하면 데이터 전송과 GPU 연산을 겹칠 수 있다. Irminsul(이번 주, Activity B 등재)의 MLA-PIC와 함께 분산 스토리지의 KV 캐시 계층화를 실현하는 인프라 논문이다. 세 가지 기술 기여: (1) **S3 확장 프로토콜** — 기존 S3 인터페이스를 콤팩트 디스크립터(매칭된 청크들·모델 레이아웃·전달 순서·RDMA 타겟을 명시)로 확장, 스토리지 서버가 레이어-메이저 페이로드를 조합해 RDMA로 직접 GPU에 전달, (2) **레이어와이즈 전송-연산 오버랩** — 각 레이어 전달을 GPU의 레이어별 연산과 파이프라인으로 겹쳐 총 TTFT를 최소화, (3) **대역폭 인식 요청 스케줄러** — 공유 대역폭 제약 하에서 각 요청의 레이어별 스톨 타겟에 따라 대역폭을 배분해, 등분 배분 대비 TTFT 추가 지연을 1.2~1.8× 감소. 100 Gbps RoCE 클러스터에서 NIXL(NVIDIA, 2026), Ceph RGW, DAOS로 프로토타입 구현 및 Llama 3.1 8B로 평가.
- **연구 목표와의 관련성**: high
- **주목할 점**: 64K 컨텍스트에서 로컬 DRAM 대비 **5.6% TTFT 추가만으로** S3 오브젝트 스토리지 기반 KV 캐시 서빙 달성; 4K 컨텍스트에서는 56~75 ms 추가. 공유 대역폭 캡 하에서 등분 대역폭 할당 대비 TTFT 추가 1.2~1.8× 감소. Activity A의 "멀티-노드 KV 라우팅"과 "KV 캐시 오프로딩" 목표에서, KVDrive(2605.18071)가 GPU/DRAM/SSD의 로컬 3-티어를 관리한다면, ObjectCache는 SSD를 넘어 **원격 S3 오브젝트 스토리지**를 4번째 계층으로 추가하는 설계다 — "KVDrive의 3-티어 + ObjectCache S3 4번째 계층"이 전체 메모리 계층의 완성이 된다. SGLang v0.5.12 HiCache(이미 보고)의 UnifiedRadixTree가 GPU→CPU→SSD를 단일 Radix 트리로 관리하는 반면, ObjectCache는 SSD 너머의 오브젝트 스토리지를 레이어와이즈 RDMA 프로토콜로 서빙 프레임워크에 통합한다. "비연속 세그먼트를 S3에 해시-주소화된 청크로 저장 → RDMA로 레이어별 순서로 GPU에 전달"하는 구조는 Activity B의 분산 비연속 세그먼트 스토리지 아키텍처와 구조적으로 동형이다. DualPath(이미 보고, 2602.21548)가 "스토리지→decode→prefill RDMA" 이중 경로로 NIC 병목을 해소했다면, ObjectCache는 "스토리지 프로토콜 자체를 레이어와이즈 RDMA 페이로드로 재설계"해 오브젝트 스토리지에서 직접 GPU로 전달하는 새로운 경로를 개척한다. 실운영 규모의 용량 제약(GPU+DRAM 초과 KV 캐시)을 S3로 해결하면서도 64K 컨텍스트에서 5.6% TTFT 추가에 그친다는 점은 Activity A의 "스케줄링 오버헤드 TTFT p50 +5% 이내" 목표와 거의 부합한다.

## Activity B — Non-Contiguous KV Cache Reuse

### 새로운 논문·구현체

#### 1. [Irminsul: MLA-Native Position-Independent Caching for Agentic LLM Serving](https://arxiv.org/abs/2605.05696)
- **출처**: arXiv 2605.05696 (2026-05-07 제출, Bole Ma, Jan Eitzinger, Harald Köstler — Friedrich-Alexander-Universität Erlangen-Nürnberg)
- **핵심 아이디어**: 에이전틱 LLM 워크로드에서 비트 동일한 토큰이 매 턴마다 시프트된 위치에 나타나 정확-접두사 캐시가 첫 불일치 지점에서 즉시 무효화된다(operators는 10~16초의 TTFT 폭발 사례를 보고). 기존 위치-독립 캐싱(PIC) 연구들(EPIC, MEPIC, CacheBlend 등)은 GQA/MHA 아키텍처에서 RoPE 재인코딩이나 어텐션 보정을 요구하는 반면, Irminsul은 **MLA(Multi-Head Latent Attention) 아키텍처의 고유한 구조**를 활용한다. MLA는 각 KV 행을 (1) 위치-자유 압축 표현 c_KV와 (2) 64-dim 위치 포함 키 k_r로 분리하며, k_r은 RoPE 행렬로 닫힌 형태(δ-회전)로 수정 가능하다. Irminsul은 두 가지 설계로 SGLang RadixCache를 확장한다: (1) **CDC 청킹 + 콘텐츠-해시 키잉** — CDC(Content-Defined Chunking)으로 세그먼트를 분리하고 토큰 내용으로 해시를 계산해 절대 위치와 무관한 캐시 키를 생성, (2) **δ-회전 규칙** — 세그먼트를 새 위치에서 재사용할 때 k_r 성분에만 단일 δ-회전을 적용해 폐쇄형으로 위치 수정. DeepSeek-V2/V3/R1, Kimi-K2/Moonlight, GLM-5, Mistral Large 3 등 MLA 채택 모델군에 적용 가능.
- **연구 목표와의 관련성**: high
- **주목할 점**: DeepSeek-V2-Lite(16B/2.4B), Kimi Moonlight-16B-A3B, JoyAI-Flash(48B/3B) 세 MLA-MoE 배포에서 평가. 아이겐틱 세션에서 최대 **48%의 시프트된 반복 토큰**이 확인되며, Irminsul이 SGLang 정확-접두사 캐시 대비 **77.2~82.7%의 추가 프롬프트 토큰 회수** 달성 + **63% 프리필 에너지 절감** per cache hit. Activity B의 핵심 질문 — "접두사 불일치에도 임의 위치의 KV 세그먼트를 재사용할 수 있는가" — 에 "MLA 아키텍처에서는 δ-회전 하나로 재사용 가능하다"는 가장 우아한 답을 제시한다. AdapShot(이미 보고, 2605.03644)이 GQA/MHA 모델에서 RoPE 회전 기반 위치 재인코딩을 실험적으로 제안했다면, Irminsul은 MLA 아키텍처의 c_KV 분리 구조를 활용해 위치 수정을 분석적으로 해결하는 최초의 MLA-네이티브 PIC 시스템이다. 두 논문은 아키텍처별 위치-독립 캐싱 방법의 서로 다른 축을 개척한다 — "GQA/MHA 모델은 AdapShot(RoPE 실험적 재인코딩), MLA 모델은 Irminsul(δ-회전 분석적 수정)"의 2-트랙 비연속 재사용 전략이 Activity B의 아키텍처-인식 설계 방향을 확립한다. KV Packet(이미 보고, 2604.13226)이 소프트-토큰 어댑터로 컨텍스트 불연속성을 흡수했다면, Irminsul은 MLA의 구조적 분리를 활용해 훈련 없이 수학적으로 위치 불일치를 제거한다. 2603.20218 CLC 실험(이미 보고)이 "위치 독립 재사용의 정확도 한계 메커니즘"을 규명했는데, Irminsul의 δ-회전이 k_r 성분을 정확히 보정함으로써 그 한계를 원리적으로 해결한다는 점이 학술적으로 유의미하다. vLLM은 공식적으로 MLA를 지원하지 않지만(DeepSeek 커뮤니티 포크 경유), SGLang은 이미 MLA 지원을 포함하므로 Activity B의 6단계 vLLM 이식에서 Irminsul SGLang 통합을 우선 참조 구현으로 활용할 수 있다.

## Activity C — KV Cache Compression

### 새로운 논문·구현체

이번 기간(2026-05-19 ~ 2026-05-26) 관련성 high/medium의 신규 Activity C 항목이 발견되지 않았다. 직전 주(2026-05-25 리포트)까지 보고된 VeriCache(2605.17613), Predictive Multi-Tier(2604.26968), Stochastic KV Routing(2604.22782)이 현재 Activity C의 최전선이다.

**C→A 시너지 관점**: VeriCache(이미 보고, 2605.17613)의 "압축 KV 드래프트(HBM-bandwidth-bound) + 전체 KV 스왑 검증(PCIe-bound) 병렬화" 원칙이 ObjectCache(이번 주, Activity A 등재)의 레이어와이즈 S3 전달과 결합되면 — "ObjectCache의 S3 레이어와이즈 전달(A)이 전체 FP16 KV를 PCIe/RDMA로 GPU로 스트리밍하는 동안, HBM에 상주하는 압축 KV로 VeriCache 드래프팅(C)"하는 파이프라인이 가능하다. 두 논문이 각각 "원격 KV 전달 대역폭 최적화(ObjectCache)"와 "원격 KV 검증 병렬화(VeriCache)"를 담당하는 상보적 시스템이다.

**C→B 시너지 관점**: Irminsul(이번 주, Activity B 등재)의 MLA-네이티브 위치-독립 세그먼트 재사용과 Stochastic KV Routing(이미 보고, 2604.22782)의 깊이 방향 레이어 간 KV 공유를 결합하면, MLA 모델에서 "위치 축(Irminsul δ-회전)과 깊이 축(Stochastic KV Routing 크로스-레이어 공유)"이 직교적으로 절감되는 2축 KV 압축이 가능하다.

## Activity 간 시너지 포인트

**A + B (ObjectCache + Irminsul)**
ObjectCache의 콘텐츠-해시-주소화된 S3 청크 스토리지와 Irminsul의 CDC 청킹 + 콘텐츠-해시 키잉이 **동일한 기본 추상화(CDC 청크 + 콘텐츠 해시)**를 공유한다. Irminsul이 SGLang RadixCache에서 CDC 청크 단위로 MLA KV를 인덱싱하고, ObjectCache가 동일 CDC 청크를 S3에 해시-주소화해 저장·전달하면 — Irminsul의 위치-독립 세그먼트 인덱스가 자연스럽게 ObjectCache의 오브젝트 스토리지 키가 되는 완전한 통합 아키텍처가 가능하다. "Irminsul이 에이전틱 세션에서 반복 CDC 청크를 발견 → ObjectCache S3에서 해당 MLA KV 청크를 레이어와이즈 RDMA로 GPU에 직접 전달 → Irminsul δ-회전으로 위치 수정 → 재사용"의 단일 파이프라인이 Activity A+B 통합의 가장 직접적 경로다.

**A + C (ObjectCache + VeriCache)**
ObjectCache의 레이어와이즈 S3 RDMA 전달(전체 FP16 KV를 원격에서 순서대로 전달)과 VeriCache의 "압축 KV 드래프트 + 전체 KV 스왑 검증 병렬화"가 결합되면 — ObjectCache가 S3에서 FP16 KV를 레이어별로 RDMA 스트리밍하는 동안, 로컬 HBM의 압축 KV로 VeriCache 드래프팅을 병렬로 수행 — "원격 FP16 KV(ObjectCache RDMA-bound) + 로컬 압축 KV(VeriCache HBM-bandwidth-bound)의 병렬 파이프라인"이 VeriCache의 이론적 전제("두 작업의 대역폭 바운드가 다르므로 병렬화 가능")를 원격 S3 스토리지로까지 확장한다. 

**B + C (Irminsul + Stochastic KV Routing + Predictive Multi-Tier)**
Irminsul의 MLA c_KV(위치-자유) 분리가 Stochastic KV Routing의 깊이 방향 크로스-레이어 공유와 결합되면, MLA 모델에서 "위치 축(Irminsul CDC 청크 재사용)과 깊이 축(Stochastic KV Routing 레이어 간 c_KV 공유)"의 2축 동시 절감이 가능하다. Predictive Multi-Tier(2604.26968)의 MLA-인식 정확 크기 조정 + Bayesian 재사용 예측이 이 2축 절감의 메모리 계층 배치를 최적화하는 상위 오케스트레이터가 된다.

**A + B + C (3-Way: ObjectCache + Irminsul + VeriCache + Stochastic KV Routing)**
MLA 모델(DeepSeek/Kimi/Moonlight) 기반 에이전틱 서빙에서의 통합 파이프라인:
1. Irminsul(B)이 에이전틱 세션의 CDC 청크를 콘텐츠-해시로 인덱싱해 반복 청크를 탐지
2. ObjectCache(A)가 S3의 해당 MLA KV 청크를 레이어와이즈 RDMA로 GPU에 전달
3. Irminsul(B)이 δ-회전으로 k_r 위치 수정 → 재사용
4. Stochastic KV Routing(C)이 깊이 방향으로 레이어 간 c_KV를 추가 공유해 절감
5. VeriCache(C)가 압축 KV로 드래프팅하면서 ObjectCache 레이어와이즈 RDMA와 병렬로 검증
6. Predictive Multi-Tier(C/A)가 Bayesian 예측으로 어떤 청크를 S3/DRAM/HBM에 배치할지 결정

이 6단계가 MLA 에이전틱 서빙에서 Activity A(원격 KV 오케스트레이션)·B(위치-독립 재사용)·C(다층 압축 보장) 세 Activity의 완전한 통합을 실현하는 최초의 구체적 파이프라인이다.
