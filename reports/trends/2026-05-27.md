## Activity C — KV Cache Compression

### 새로운 논문·구현체

#### 1. [IndexMem: Learned KV-Cache Eviction with Latent Memory for Long-Context LLM Inference](https://arxiv.org/abs/2605.25475)
- **출처**: arXiv 2605.25475 (2026-05-25 제출)
- **핵심 아이디어**: 기존 KV 캐시 퇴거 방법들(SnapKV, PyramidKV, TOVA 등)이 (1) 휴리스틱 중요도 점수로 부정확하게 토큰을 선택하고 (2) 퇴거된 토큰의 정보를 영구히 폐기해 장문 컨텍스트에서 복구 불가능한 정보 손실을 일으키는 두 가지 근본 문제를 동시에 해결한다. IndexMem은 두 가지 학습 가능한 구성 요소를 결합한다: (1) **학습 가능한 중요도 예측기(Learnable Indexer)** — 입력 의존적인 KV 중요도 분포를 포착해 더 정확한 토큰 유지 결정을 내리는 경량 학습 모듈; 기존 ExpectedAttention·KeyDiff·TOVA 같은 휴리스틱보다 입력에 적응적, (2) **잠재 기억 모듈(Latent Memory Module)** — 퇴거된 토큰들을 영구 폐기하는 대신 압축된 온라인-갱신 잠재 상태(compact, online-updated latent state)로 인코딩해 저장하고, 디코딩 중 의미적 관련성이 높아질 때 잔차 리드아웃(residual readout)으로 어텐션 기여를 보상(compensate). "퇴거 = 영구 삭제"라는 기존 패러다임을 "퇴거 = 잠재 압축 + 조건부 복원"으로 전환하는 설계 원칙이다.
- **연구 목표와의 관련성**: high
- **주목할 점**: RULER-4K·RULER-16K 스위트에서 컨텍스트 길이 1K~12.5K, 바늘 깊이 15%~95% 전 범위에서 안정적 바늘 복원 달성 — 기준선들이 특정 깊이에서 실패하는 구간에서도 일관된 복원력 유지. Qwen·Mistral·Llama 모델 패밀리 전반에서 기존 퇴거 방법 대비 최대 25포인트 개선(공격적 퇴거 조건 기준). Activity C의 "압축 정확도 delta ±1% 이내" 목표를 "퇴거 후 잔차 복원"이라는 새로운 메커니즘으로 달성하는 방법이다 — VeriCache(이미 보고, 2605.17613)가 "압축 KV 드래프트 + 전체 KV 검증"으로 결정론적 동일 출력을 보장한다면, IndexMem은 "퇴거 토큰을 잠재 상태로 보존 + 잔차 리드아웃 복원"으로 확률적 정보 보존을 달성하는 상보적 방향이다. SnapKV·PyramidKV(이미 보고) 대비 접근 방식의 근본 차이: 기존 방법들은 "어떤 토큰을 유지할 것인가"(선택 단계)에만 집중하는 반면, IndexMem은 "어떤 토큰을 유지할 것인가(Learnable Indexer) + 버려진 토큰의 정보를 어떻게 보존할 것인가(Latent Memory)"를 동시에 최적화하는 2단계 구조다. Activity B의 비연속 재사용 관점에서: 비연속 세그먼트 중 히트율이 낮아 퇴거 압박을 받는 세그먼트를 IndexMem의 잠재 상태로 압축 보존하면, 물리적으로 퇴거된 세그먼트의 어텐션 기여를 잠재 리드아웃으로 유지해 "비연속 세그먼트가 물리적으로 퇴거되더라도 의미적으로 유효한 기여를 유지"하는 B+C 통합 방향이 가능하다.

|------|---------|------------|

## Activity 간 시너지 포인트

**B + C (비연속 세그먼트 퇴거 + IndexMem 잠재 기억)**
비연속 세그먼트 캐시(Activity B)에서 히트율이 낮거나 오래된 세그먼트를 퇴거해야 할 때, 해당 세그먼트의 KV 상태를 IndexMem의 잠재 기억 모듈로 압축-보존하면 물리적 퇴거 후에도 그 어텐션 기여를 잔차 리드아웃으로 유지할 수 있다. 이는 Activity B의 "비연속 세그먼트 재사용"과 Activity C의 "정확도 보존 압축"을 "퇴거된 세그먼트도 잠재 상태로 기여"하는 단일 파이프라인으로 통합하는 경로다. KV Packet(B)의 소프트-토큰 어댑터가 컨텍스트 불연속성을 흡수하고, IndexMem(C)의 잠재 기억이 퇴거된 비연속 세그먼트의 기여를 보상하면, 완전한 비연속 세그먼트 재사용의 정보 보존 체계가 된다.

**A + C (에이전틱 KV 스케줄링 + IndexMem)**
CONCUR(A)가 에이전트-레벨 입장 제어로 활성 에이전트 수를 제한해 KV 풀을 혼잡 이하로 유지하는 경우, IndexMem(C)의 잠재 기억 모듈이 혼잡으로 퇴거된 에이전트 KV의 의미적 기여를 보존한다 — "CONCUR 입장 제어(A) → 퇴거 압박 완화 → IndexMem 잠재 기억(C)으로 퇴거 시에도 정보 보존"의 에이전틱 KV 2레이어 관리가 가능하다. CacheTTL(A)의 TTL 보존이 만료될 때 IndexMem의 잠재 기억으로 소프트 전환하면 TTL 만료 후에도 어텐션 기여를 유지하는 "TTL → 잠재 기억 폴백" 체계도 설계 가능하다.

**A + B + C (3-Way: KV 스케줄링 + 비연속 재사용 + 잠재 보존)**
에이전틱 멀티-턴 워크로드에서의 통합 파이프라인 확장:
1. Irminsul(B)이 에이전틱 세션의 CDC 청크를 콘텐츠-해시로 인덱싱, MLA 모델에서 δ-회전으로 위치 수정
2. CONCUR(A)가 활성 에이전트 수를 혼잡 기반으로 제어해 KV 풀 여유 확보
3. ObjectCache(A)가 S3 오브젝트 스토리지에서 해당 CDC 청크를 레이어와이즈 RDMA로 GPU에 전달
4. CacheTTL(A)이 도구 호출 간격 동안 재사용 예정 KV를 TTL로 보존
5. IndexMem(C)이 TTL 만료 또는 공간 압박으로 퇴거되는 세그먼트를 잠재 상태로 압축 보존
6. VeriCache(C)가 압축 KV로 드래프팅하면서 전체 KV로 결정론적 검증
이 6단계가 이전 주(2026-05-26)의 ObjectCache+Irminsul+VeriCache 3-Way에 IndexMem의 "퇴거 세그먼트 잠재 보존" 레이어를 추가한 최신 통합 파이프라인이다.
