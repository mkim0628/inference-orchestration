# 트렌드 리포트 — 2026-05-28

## 전체 요약

이번 주(2026-05-21~2026-05-28)는 Activity A에서 두 편의 신규 항목이 확인됐다. HexAGenT(2605.16637, May 15)는 에이전틱 LLM 워크로드를 온라인-공개 DAG로 모델링하고, KV 캐시 용량과 prefill-decode 이기종 GPU 제약을 동시에 고려하는 워크플로우 단위 스케줄링을 제안해 SLO 충족률을 평균 20.1% 개선한다. PegaFlow(Novita AI, May 18)는 Rust 코어로 구현된 외부 KV 캐시 서비스로, GPU 오프로딩 + SSD 캐싱 + RDMA 크로스-노드 공유를 vLLM/SGLang의 드롭인 KV 커넥터로 제공한다. Activity B와 Activity C는 이번 주 high/medium 관련성 신규 항목이 발견되지 않았으며, 전주까지의 최전선(B: Irminsul, AdapShot, KV Packet; C: IndexMem, VeriCache, OScaR, TriAxialKV)이 유효하다. 전반적으로 NeurIPS 2026 마감 직전 소강 국면이 지속되고 있으며, 6월 중순 이후 2606.x 계열 신규 제출이 급증할 것으로 전망된다.

## Activity A — KV Cache-aware Scheduling / Orchestration

### 새로운 논문·구현체

#### 1. [HexAGenT: Efficient Agentic LLM Serving via Workflow- and Heterogeneity-Aware Scheduling](https://arxiv.org/abs/2605.16637)
- **출처**: arXiv 2605.16637 (2026-05-15 제출; You Peng, Youhe Jiang, Wenshuang Li, Xu Xu, Ke Zhou, Jiawei Jiang, Chen Wang, Binhang Yuan)
- **핵심 아이디어**: 에이전틱 LLM 워크로드는 플래닝·툴 호출·브랜칭·정제·합성 등 다단계 워크플로우로 구성되며, 워크플로우 의존성이 런타임에 점진적으로 공개(online-revealed)된다. HexAGenT는 각 요청을 **온라인-공개 DAG**로 모델링하고 (1) 워크플로우의 독립 완료 시간 지평선(standalone completion horizon)을 실시간 추정, (2) 시간 초과 리스크가 가장 높은 준비 완료(ready) 호출을 우선 처리, (3) KV 캐시 용량 및 prefill-decode 크로스-스테이지 전송 지연을 고려해 prefill 배치·decode 배치·로컬 큐 우선순위를 동시 결정하는 3-way 최적화를 수행한다. A100/H100/H200 이기종 클러스터에서 멀티-에이전트 워크플로우를 대상으로 평가됐다.
- **연구 목표와의 관련성**: high
- **주목할 점**: 대표적 에이전틱 워크로드와 이기종 A100/H100/H200 클러스터에서 SLO 충족에 필요한 SLO 스케일 팩터를 95% attainment 기준 평균 **20.1%**, 99% attainment 기준 **33.0%** 감소 (최대 45.0%, 80.5%). Activity A의 핵심 질문("캐시 재사용률 극대화를 위해 어떤 순서로 배치할 것인가")을 에이전틱 워크플로우 단위로 확장한다 — 기존 PBKV(이미 보고, 2605.06472)가 동적 에이전트 워크플로우의 KV 캐시 예측 기반 관리에 집중한다면, HexAGenT는 KV 캐시 용량 제약과 이기종 GPU 전송 지연을 스케줄링 목적함수에 명시적으로 포함하는 **시스템 수준 통합**을 달성한다. CacheTTL(이미 보고, 2511.02230)의 TTL 기반 에이전트 KV 보존과 달리 HexAGenT는 워크플로우 완료 시간 지평선을 직접 목적함수로 사용한다 — 두 접근이 상보적이다: CacheTTL이 에이전트 턴 간 KV 보존 정책을 담당하고, HexAGenT가 전체 워크플로우의 스케줄링 배치와 우선순위를 결정한다. prefill-decode 분리(P/D disaggregation) 클러스터에서 KV 전송 지연을 목적함수에 포함하는 설계는 Activity A의 "멀티-노드 KV 라우팅"과 "스케줄링 오버헤드 TTFT p50 +5% 이내" 목표 모두와 직결된다.

#### 2. [vLLM x Novita AI: PegaFlow for Production-Grade External KV Cache](https://blog.vllm.ai/2026/05/18/pegaflow.html)
- **출처**: vLLM 블로그 (2026-05-18) + GitHub: [novitalabs/pegaflow](https://github.com/novitalabs/pegaflow)
- **핵심 아이디어**: PegaFlow는 **Rust 코어**로 구현된 고성능 외부 KV 캐시 스토리지 엔진으로, GPU 오프로딩(HBM → 호스트 메모리)·SSD 캐싱·RDMA 크로스-노드 KV 공유를 vLLM과 SGLang의 **드롭인(drop-in) KV 커넥터**로 제공한다. 독립형 Rust 프로세스로 실행되며 Python GIL 경로를 완전히 배제해 핫 패스 오버헤드를 제로로 유지한다. 내장 Prometheus 메트릭 및 OTLP 익스포트로 운영 가시성을 확보하며, 인스턴스 재시작·다중 인스턴스·RDMA 노드 간에 KV 캐시를 보존·공유할 수 있다.
- **연구 목표와의 관련성**: high
- **주목할 점**: 기존 vLLM/SGLang의 KV 오프로딩 커넥터(CPU DRAM 레벨)를 넘어 **RDMA 크로스-노드 KV 공유**까지 단일 엔진으로 통합하는 최초의 오픈소스 Rust 기반 외부 KV 커넥터다. ObjectCache(이미 보고, 2605.22850)가 S3 오브젝트 스토리지를 4번째 KV 계층으로 추가하는 연구 프로토타입이라면, PegaFlow는 **호스트 메모리→SSD→RDMA 노드 간 공유**를 단일 드롭인 커넥터로 묶는 운영 수준(production-grade) 구현체다. SGLang v0.5.12 HiCache(이미 보고)의 SSD 오프로딩이 Mooncake Store 백엔드를 경유하는 것과 달리, PegaFlow는 vLLM-native KV 커넥터 API를 통해 GIL-free Rust 프로세스로 동작해 운영 환경의 성능 안정성을 높인다. Activity A의 "멀티-노드 KV 마이그레이션"과 "KV 캐시 오프로딩 처리량" 목표 모두에서 바로 적용 가능한 오픈소스 참조 구현체다. Activity C의 GPU→SSD 오프로딩과 결합하면 "압축 KV(C)를 PegaFlow SSD에 오프로딩 + RDMA로 인접 노드에서 재사용(A)"하는 A+C 통합 파이프라인이 가능하다.

## Activity C — KV Cache Compression

### 새로운 논문·구현체

이번 기간(2026-05-21 ~ 2026-05-28) 관련성 high/medium의 신규 Activity C 항목이 발견되지 않았다. 직전 리포트(2026-05-27)까지 보고된 IndexMem(2605.25475), VeriCache(2605.17613), OScaR(2605.19660), TriAxialKV(2605.17170), Runtime-Certified(2605.20868), Predictive Multi-Tier(2604.26968), Stochastic KV Routing(2604.22782)이 현재 Activity C의 최전선이다.

**C 관련 업스트림 업데이트**: vLLM XPU 커널(2026-05-08 릴리즈)에서 decode·chunked-prefill 어텐션 커널이 블록 크기 16/32/64/128/192/256을 지원하게 됐다(flexible block size). 이전에는 고정 블록 크기만 지원했으므로 KV 캐시 페이지 구성의 세밀도가 향상돼 압축 알고리즘(예: DepthKV 레이어별 예산, TriAxialKV 3축 양자화)과의 통합 유연성이 증가했다. 단, 이는 신규 알고리즘 논문이 아닌 엔진 개선이므로 "동향 변화 감지" 표에만 기록한다.

## Activity 간 시너지 포인트

**A + B + C (HexAGenT + Irminsul/AdapShot + IndexMem)**
HexAGenT의 온라인-공개 DAG 스케줄러가 에이전틱 워크플로우의 각 단계별 KV 캐시 수요를 사전 추정하고, Irminsul/AdapShot(B)이 위치-독립 비연속 세그먼트를 재사용하며, IndexMem(C)이 퇴거 압력이 높아질 때 잠재 기억 모듈로 세그먼트 기여를 보존하는 3-계층 파이프라인: "HexAGenT DAG 스케줄링(A) → Irminsul δ-회전 비연속 세그먼트 재사용(B) → IndexMem 잠재 기억 폴백(C)".

**A + C (PegaFlow + 압축 KV)**
PegaFlow의 SSD 캐싱 + RDMA 크로스-노드 공유가 압축 KV(Activity C의 VeriCache, OScaR 등)와 결합되면 — "VeriCache가 압축 KV를 드래프트로 생성(C) + PegaFlow가 해당 압축 KV를 SSD에 오프로딩하거나 RDMA로 인접 노드에서 재사용(A)"하는 A+C 통합 파이프라인이 실용 가능하다. 전체 FP16 KV는 검증 시에만 사용하고 압축 KV를 외부 KV 커넥터로 관리함으로써 메모리 절감과 크로스-노드 재사용을 동시에 달성한다.

**A + B (PegaFlow + 비연속 세그먼트 원격 재사용)**
PegaFlow의 RDMA 인프라는 비연속 세그먼트(Activity B)를 원격 노드에서 직접 재사용하는 분산 아키텍처의 하부 전송 계층이 된다 — Irminsul이 콘텐츠-해시로 비연속 MLA KV 세그먼트를 인덱싱하고, PegaFlow RDMA가 해당 세그먼트를 원격 노드의 SSD/DRAM에서 직접 전송하며, δ-회전으로 위치 수정하는 완전한 분산 비연속 재사용 스택이 가능하다.

## idea-generator에게 전달할 포인트

**Activity A**
- HexAGenT의 온라인-공개 DAG + 이기종 GPU 고려 워크플로우 스케줄링이 Activity A의 에이전틱 KV 스케줄링 축에 새로운 시스템 설계 방향을 추가했다. 기존 CacheTTL(TTL 보존)·PBKV(KV 예측)·CONCUR(에이전트 입장 제어)·ThunderAgent(툴 호출 선제 패칭)의 4-축과 HexAGenT(워크플로우 완료 지평선 + 이기종 GPU 통합 배치)를 결합한 5-축 에이전틱 스케줄링 체계를 구성할 수 있다.
- PegaFlow는 Activity A의 "멀티-노드 KV 라우팅" 목표를 운영 환경에서 실현하는 Rust 기반 드롭인 구현체다. 연구 구현(ObjectCache S3 레이어와이즈 RDMA)과 운영 구현(PegaFlow GIL-free Rust 커넥터)이 상호 보완적이므로 시스템 설계에서 두 접근의 조합을 고려할 것.

**Activity B**
- 이번 주 신규 논문 없음. 전주 포인트(GQA/MHA: AdapShot / MLA: Irminsul의 2-트랙 아키텍처-인식 비연속 재사용 체계) 유효.
