## Activity A — KV Cache-aware Scheduling / Orchestration

### 새로운 논문·구현체

#### 1. [Resident KV Claims: A Conformance Contract for Future Reuse under Active KV Pressure](https://arxiv.org/abs/2605.24259)
- **출처**: arXiv 2605.24259 (2026-05-22 제출, Lukas Stepanek)
- **핵심 아이디어**: 현재 vLLM을 포함한 KV 캐시 재사용 메커니즘들은 priority·duration·offload·routing-hint·scheduler-mode·event-stream 등 다양한 힌트를 노출하지만, **"활성 KV(active live KV)와 캐시 보존 KV(resident KV)가 동시에 GPU 풀에 들어갈 수 없을 때 수락된 미래-재사용 상태"에 대한 포터블 계약(conformance contract)이 없다**는 근본 문제를 해결한다. Resident KV Claims는 미래 재사용 의도를 materialization predicate·lifecycle state·active/resident feasibility outcome·claim-level telemetry의 4-투플로 묶는 스케줄러-가시적 계약을 제안한다. 핵심 설계: (1) **경성 보호 잔존 클레임(hard protected resident claim)** — 클레임이 수락되면 해당 KV 블록을 에빅션 대상에서 명시적으로 제외해 미래 재사용을 보장, (2) **충돌 시 능동적 거부(active refusal)** — 잔존 KV 클레임과 활성 프리필이 KV 풀 한도를 초과하면 "KV 풀 부족"으로 조용히 실패하는 대신 스케줄러-가시적 거부(active refusal)와 직접 차단-클레임 귀속(blocking-claim attribution)으로 전환, (3) **최소 vLLM 프로토타입** — vLLM allocator에서 80-블록 KV 풀을 60-블록 잔존 클레임 + 70-블록 활성 프리필이 초과하는 시나리오에서 새 계약의 효과를 실험적으로 검증.
- **연구 목표와의 관련성**: medium
- **주목할 점**: "미래 재사용 의도"를 스케줄러가 명시적으로 인식하는 계약으로 공식화한 최초의 논문이다. 기존 CacheTTL(이미 보고, 2511.02230)이 TTL 값으로 KV 보존 기간을 정의하고 스케줄러가 이를 참조한다면, Resident KV Claims는 TTL 이외에도 materialization predicate와 feasibility 상태를 포함하는 **더 일반화된 계약 레이어**를 제안한다 — CacheTTL이 "보존 기간"을 다룬다면 Resident KV Claims는 "보존 가능성과 충돌 해결"을 다루는 상위 레이어다. Activity A의 "캐시 퇴거율 최소화"와 "스케줄링 오버헤드 TTFT p50 +5% 이내" 목표에서, 잔존 클레임 계약이 없으면 스케줄러가 암묵적 메모리 부족을 경험해 예측 불가능한 TTFT 폭발이 발생하는 시나리오를 방지하는 인프라 레이어로 기능한다. Irminsul(B)의 CDC 세그먼트 재사용 의도를 Resident KV Claims 계약으로 등록하면 비연속 세그먼트의 "예약 보존"이 가능해 Activity A+B 통합 설계에서 직접 활용 가능하다.

#### 2. [Grounded Cache Routing for Retrieval-Augmented Generation: When Is It Safe to Reuse an Answer?](https://arxiv.org/abs/2605.27494)
- **출처**: arXiv 2605.27494 (2026-05-26 제출, Syed Huma Shah — Duke University)
- **핵심 아이디어**: RAG 배포에서 프리픽스-레벨 KV 재사용이 표준이 됐지만, **유사한 쿼리가 서로 다른 정답에 매핑되거나 코퍼스가 업데이트돼 검색 결과가 드리프트되거나 적대적 충돌 공격이 캐시 응답을 오염시키는** 세 가지 구조적 취약성을 가진다. 기존 캐시 라우터들이 "얼마나 빠르게 재사용할 것인가"에 집중하는 반면, GroundedCache는 "재사용이 안전한가"를 4-게이트 동시 검증으로 정형화한다. 4개 게이트: (1) **쿼리 유사도(query similarity)** — 쿼리 임베딩 코사인 유사도 임계값, (2) **검색 증거 중복(retrieved-evidence overlap)** — 현재 검색 결과와 캐시 생성 시 검색 결과의 청크 중복 측정, (3) **소스 버전 유효성(source-version validity)** — 캐시된 답변이 생성될 때의 문서 버전과 현재 버전의 일치 확인, (4) **어휘·심판 지지도(lexical/judge-based support)** — 캐시된 답변이 새로 검색된 컨텍스트에 의해 어휘적으로(또는 LLM 심판으로) 지지되는지 검증. 4개 게이트가 모두 통과할 때만 캐시 응답을 허용하며, 결정론적 합성 벤치마크(exact-repeat·paraphrase·near-miss·document-drift·long-shared-document·bounded-KB CAG)를 제공한다.
- **연구 목표와의 관련성**: medium
- **주목할 점**: RAG 캐시 재사용의 "안전성 판별(when is reuse safe?)"을 최초로 정형화한 논문이다. 4-게이트 검증이 추가 LLM 호출 없이 경량 게이트(어휘 매칭·버전 태그)로 구현 가능해 "정확도 보존" 제약이 있는 RAG+KV 캐시 통합에서 직접 적용 가능하다. Activity A의 "캐시 히트율 극대화"와 Activity C의 "압축 정확도 delta ±1% 이내" 목표 모두와 접점이 있다 — 캐시 히트율을 높이면서도 정확도를 보장하는 라우팅 조건을 명시화한다. Randomization Boosts KV Caching(이미 보고, 2601.18999 ICLR 2026)이 "캐시 퇴거와 라우팅을 통합 수학 모델로 정형화"했다면, Grounded Cache Routing은 "RAG 도메인에서 안전한 캐시 재사용 조건을 정형화"하는 보완적 방향이다. Activity B의 비연속 세그먼트 재사용에서 재사용할 세그먼트의 "소스 버전 유효성" 검증은 스테일(stale) 세그먼트를 배제하는 Grounded Cache Routing의 게이트 3번과 직접 대응되는 설계 원칙이다.

## Activity B — Non-Contiguous KV Cache Reuse

### 새로운 논문·구현체

#### 1. [You Need an Encoder for Native Position-Independent Caching](https://arxiv.org/abs/2602.01519)
- **출처**: arXiv 2602.01519 (2026-02-02 제출, Shiju Zhao, Junhao Hu, Jiaqi Zheng, Guihai Chen; GitHub: [shijuzhao/Comb](https://github.com/shijuzhao/Comb))
- **핵심 아이디어**: 기존 PIC(Position-Independent Caching) 방법들(EPIC, MEPIC, CacheBlend, AdapShot 등)이 decoder-only LLM에서 RoPE 재인코딩 또는 어텐션 보정 등 **부가적(add-on) 수정**으로 위치 독립성을 근사하면서 상당한 정확도 저하가 발생하는 문제를 해결한다. 핵심 통찰: "decoder-only 아키텍처는 원래 PIC를 지원하도록 설계되지 않았다 — 위치 독립성을 네이티브로 달성하려면 아키텍처 자체를 수정해야 한다." COMB는 encoder layer를 decoder-only LLM에 **빗살무늬(comb-like) 방식으로 인터리브**해 재도입하고, 인터리브된 encoder 레이어들이 cross-attention만 수행하도록 훈련한다. 두 가지 핵심 기술: (1) **Native PIC 아키텍처** — encoder 레이어가 캐시 세그먼트에 대해 위치 독립적 cross-attention을 수행해 세그먼트의 절대 위치와 무관하게 컨텍스트를 이해, (2) **COMB 캐싱 시스템** — 기존 추론 프레임워크와 seamlessly 통합되는 PIC-aware 캐시 관리자로, 다른 위치에서 캐시된 세그먼트를 재사용할 때 재인코딩·재계산 없이 cross-attention 경로로 직접 처리.
- **연구 목표와의 관련성**: high
- **주목할 점**: COMB가 TTFT를 **51~94% 절감**하고 처리량을 **3× 향상**하면서 comparable 정확도를 유지한다. DeepSeek-V2-Lite-Chat에서도 효과가 검증돼 다양한 decoder-only LLM에 적용 가능성 확인. Activity B의 핵심 질문 — "접두사 불일치에도 임의 위치의 KV 세그먼트를 재사용할 수 있는가" — 에 "아키텍처 수준에서 encoder를 재도입해 네이티브 PIC를 달성한다"는 세 번째 아키텍처 트랙을 추가한다. 현재 Activity B의 위치-독립 캐싱은 "MLA 모델: Irminsul(δ-회전), GQA/MHA 모델: AdapShot(RoPE 재인코딩)"의 2-트랙이었는데, COMB는 아키텍처 변경이 허용되는 경우 "새로 훈련하는 모델: COMB Native PIC"라는 3번째 트랙을 확립한다 — 배포된 모델에는 Irminsul/AdapShot, 새로 훈련하는 모델에는 COMB가 적합한 상보적 세 축 체계가 형성된다. KV Packet(이미 보고, 2604.13226)이 소프트-토큰 어댑터 증류로 재계산 FLOPs를 제로로 만든다면, COMB는 encoder를 native PIC로 훈련해 아키텍처 레벨에서 재계산 필요성 자체를 제거한다 — "어댑터 패치(KV Packet)"와 "아키텍처 재설계(COMB)"의 비교가 Activity B의 구현 방향 결정에 중요한 트레이드오프다. GitHub 구현체(github.com/shijuzhao/Comb)가 공개돼 Activity B의 src/cache/radix.py에 COMB 스타일 encoder cross-attention 경로를 추가하는 참조 구현으로 활용 가능하다.

## Activity C — KV Cache Compression

### 새로운 논문·구현체

#### 1. [SPHERICAL KV: Angle-Domain Attention and Rate-Distortion Retention for Efficient Long-Context Inference](https://arxiv.org/abs/2605.18856)
- **출처**: arXiv 2605.18856 (2026-05-13 제출, Anay Chauhan, Gurucharan Marthi Krishna Kumar, Arion Das, Amit Dhanda, Vinija Jain, Aman Chadha, Amitava Das)
- **핵심 아이디어**: 장문 컨텍스트 추론은 KV 캐시의 HBM 스트리밍 대역폭이 지배적 병목이 되는데, 기존 방법들이 토큰 제거(eviction) 또는 양자화를 독립적으로 다루는 반면, SPHERICAL KV는 **어텐션 기하학(attention geometry)**을 Rate-Distortion 프레임워크에 직접 통합하는 두 가지 통합 컴포넌트를 제안한다. (1) **Angle-Domain Attention(ADA)** — Key 텐서를 스칼라 반경(scalar radius)과 컴팩트 각도 코드(compact angle codes)의 구형 파라미터화(spherical parameterization)로 저장하고, 밀집 Key를 재구성하지 않고 각도 코드에서 직접 어텐션 로짓을 계산한다. 이 설계는 paged·block-local·fusion-friendly 디코딩 경로를 유지하면서 현실적 서빙 환경에서 HBM 트래픽을 직접 절감하며, (2) **Rate-Distortion Retention(RDR)** — 고정 메모리 예산 하에서 토큰별·헤드별로 keep/drop 결정과 정밀도 티어(precision tier)를 **공동으로(jointly)** 결정한다. 단순히 "어떤 토큰을 유지할 것인가"(퇴거 방법)와 "어떤 정밀도로 저장할 것인가"(양자화 방법)를 분리하는 대신, 두 결정을 Rate-Distortion 최적화로 통합해 tier-homogeneous 페이지와 경량 메타데이터 + 코얼리스드 읽기를 생성한다.
- **연구 목표와의 관련성**: high
- **주목할 점**: 어텐션 기하학을 직접 이용해 KV 선택과 양자화를 공동 최적화하는 첫 번째 Rate-Distortion 프레임워크다. HBM 트래픽을 직접 목표로 삼는 설계가 기존 방법들과 차별화된다. Activity C의 "KV 캐시 메모리 −30% 이상" + "압축 정확도 delta ±1% 이내" 목표에서, 토큰 선택(drop/keep)과 정밀도 티어링(precision tiering)을 단일 Rate-Distortion 목적함수로 통합하는 설계는 각 단계를 독립 최적화할 때보다 파레토 최적 솔루션을 달성하는 원리적 경로다. TriAxialKV(이미 보고, 2605.17170)가 에이전틱 KV의 의미적 역할 3축을 INT2/INT4 혼합 정밀도로 매핑한다면, SPHERICAL KV는 어텐션 기하학(각도 코드 + 반경)과 Rate-Distortion 이론으로 정밀도 할당을 원리적으로 도출하는 상보적 방향이다. 두 방법을 결합하면 "의미적 역할(TriAxialKV) × 기하학적 중요도(SPHERICAL KV RDR)"의 2축 정밀도 결정이 가능하다. ADA의 각도 코드가 RoPE와 어떻게 상호작용하는지는 Irminsul(B)의 MLA δ-회전 및 AdapShot(B)의 RoPE 재인코딩과의 결합 가능성을 결정하는 핵심 질문이다 — KV를 구형 파라미터화로 저장하면 position-offset δ-회전이 각도 코드에 직접 작용하는 수학적 구조가 성립할 수 있다.

#### 2. [Minimal-Intervention KV Retention: A Design-Space Study and a Diversity-Penalty Survivor](https://arxiv.org/abs/2605.14292)
- **출처**: arXiv 2605.14292 (2026-05-14 제출, Libo Sun, Po-wei Harn, Peixiong He, Xiao Qin)
- **핵심 아이디어**: 소예산(small-budget) KV 캐시 압축이 중요해졌지만 다양한 KV 보존 방법들이 어떤 설계 요소가 실제로 성능을 결정하는지 체계적으로 비교된 적이 없다는 공백을 메운다. 이 논문은 5개 패밀리 7개 메커니즘을 예산 b∈{64, 128}에서 체계적으로 비교(long-form 수학 추론 MATH-500, Qwen-7B·Llama-8B DeepSeek-R1-Distill 사용)한다. 핵심 발견: **argmax-top-k 토큰 선택이 V-공간에서 중복 토큰을 반복 선택해 소예산에서 특히 비효율적**이다. 제안 방법 **α**: TriAttention 보존 스코어러에 V-공간 중복성 페널티(V-space redundancy penalty)를 추가하는 단일 함수 수정 — argmax-top-k를 단일 제어 가중치 λ를 가진 greedy facility-location 기반 선택으로 교체해 V-공간 다양성을 강제한다.
- **연구 목표와의 관련성**: medium
- **주목할 점**: 소예산 KV 압축에서 TriAttention 기반 스코어러에 V-공간 다양성 페널티를 추가하는 **단일 λ 파라미터 수정**으로 기준선 대비 일관된 성능 향상 달성. Activity C의 "압축 정확도 delta ±1% 이내" 목표를 추론(reasoning) 워크로드의 소예산 환경에서 강화하는 경량 수정이다. TriAttention(이미 보고, 2604.04921)이 AIME25에서 10.7× KV 절감을 달성했다면, Minimal-Intervention은 TriAttention의 스코어러를 소예산 정확도 관점에서 개선하는 "다음 단계" 연구다 — TriAttention(큰 절감)과 α(작은 수정으로 소예산 정확도 향상)의 결합이 Activity C 구현의 단기 개선 방향이다. 5패밀리 체계적 비교(design-space study) 자체가 Activity C 구현에서 방법 선택의 이론적 기반을 제공한다: argmax-top-k의 V-공간 중복성 문제는 SnapKV·PyramidKV를 포함한 현재 Activity C에 구현된 모든 top-k 기반 퇴거 방법에 동일하게 적용되는 설계 취약점이다 — src/cache/segmented.py의 토큰 선택 로직에 facility-location 기반 greedy 선택을 즉시 적용 가능하다.

## Activity 간 시너지 포인트

**B + C (COMB + SPHERICAL KV)**
COMB(B)의 encoder interleaving이 세그먼트를 위치 독립적으로 cross-attention 처리하고, SPHERICAL KV(C)의 ADA가 Key를 각도 코드로 저장한다. COMB encoder의 cross-attention KV를 SPHERICAL KV 구형 파라미터화로 저장하면 — 위치-독립 KV 캐시(COMB)를 각도 코드 + 반경으로 저장해 HBM 트래픽과 메모리를 동시에 절감하는 "Native PIC × 기하학 압축" 통합 설계가 가능하다. COMB의 cross-attention 경로에서 Query가 각도 코드와 직접 내적해 어텐션 로짓을 계산하면 밀집 Key 재구성 없이 Native PIC + ADA가 단일 패스에서 작동한다.

**A + B (Resident KV Claims + COMB + Irminsul)**
COMB(B)의 Native PIC가 특정 세그먼트 집합에 대한 미래 재사용 의도를 생성하고, Resident KV Claims(A)가 해당 세그먼트의 encoder cross-attention KV를 스케줄러-가시적 계약으로 보호 등록한다. Irminsul(B)의 MLA δ-회전 비연속 세그먼트 + Resident KV Claims의 경성 보호 잔존 클레임으로 — "비연속 MLA 세그먼트의 미래 재사용을 계약으로 보장"하는 Activity A+B 통합 파이프라인이 가능하다.

**A + C (Grounded Cache Routing + IndexMem + VeriCache)**
Grounded Cache Routing(A)의 4-게이트 캐시 안전성 검증이 압축 KV의 재사용 결정에도 적용 가능하다 — VeriCache(C)의 압축 KV 드래프트를 재사용할 때 게이트 3·4(소스 버전 유효성·지지도)를 통과한 경우에만 드래프트로 허용하고 아니면 전체 KV 재검증을 강제하는 "안전성-인식 압축 캐시 라우팅"이 Activity A+C 통합의 새로운 경로다. IndexMem(C)의 잠재 기억이 게이트를 통과하지 못한 세그먼트의 어텐션 기여를 보상할 수 있다.

**A + B + C (3-Way: Resident KV Claims + COMB + SPHERICAL KV + TriAttention α)**
에이전틱 RAG 추론 워크로드에서의 통합 파이프라인:
1. Grounded Cache Routing(A)이 4-게이트 검증으로 재사용 안전 세그먼트를 선별
2. COMB(B)가 안전 세그먼트를 encoder cross-attention으로 위치-독립 처리
3. Resident KV Claims(A)가 재사용 의도를 스케줄러 계약으로 등록해 KV 풀 충돌 방지
4. SPHERICAL KV(C)가 cross-attention KV를 각도 코드 + RDR로 압축 저장
5. TriAttention α(C)가 소예산 환경에서 V-공간 다양성 페널티로 핵심 토큰 선택 최적화
6. HexAGenT(A)의 DAG 스케줄러가 전체 파이프라인의 워크플로우 완료 시간 지평선을 관리

## idea-generator에게 전달할 포인트

**Activity A**
- **Resident KV Claims(2605.24259) — 스케줄러-가시적 KV 보존 계약**: "미래 재사용 약속"을 포터블 계약으로 공식화하는 아이디어는 Activity A의 src/engine/batch_runner.py 스케줄러에서 직접 구현 가능한 인터페이스 레이어다. CacheTTL(TTL 기반 KV 보존) + Resident KV Claims(KV 풀 충돌 해결 계약)를 결합하면 에이전틱 워크로드에서 "TTL로 보존 기간 설정 + Claims로 충돌 시 명시적 거부"하는 2레이어 스케줄링 보호 구조가 완성된다. PBKV(이미 보고)의 KV 예측 기반 관리와 Resident KV Claims의 계약 기반 보호를 통합하면 "예측(PBKV) + 보호(Claims)"의 예방적 KV 스케줄링이 가능하다.
- **Grounded Cache Routing(2605.27494) — RAG 캐시 안전성 4-게이트**: Activity A의 prefix-aware batching 스케줄러에서 RAG 요청의 캐시 재사용 결정에 Grounded Cache Routing의 4-게이트(쿼리 유사도·증거 중복·소스 버전·지지도)를 경량 pre-check로 추가하면 "잘못된 KV 재사용으로 인한 정확도 저하"를 방지하는 안전망이 구축된다. 게이트 2·3(검색 증거 중복·소스 버전 유효성)은 비연속 세그먼트의 스테일니스(staleness) 검사로도 직접 활용 가능해 Activity A+B의 연결 포인트가 된다.

**Activity B**
- **COMB(2602.01519) — Native PIC 3번째 아키텍처 트랙**: encoder interleaving으로 네이티브 PIC를 달성하는 아이디어는 Activity B의 설계 공간을 크게 확장한다. 현재 src/cache/radix.py와 src/cache/segmented.py는 기존 배포 모델(MLA: Irminsul δ-회전, GQA/MHA: AdapShot RoPE 재인코딩)을 지원하도록 설계됐는데, COMB 스타일 Native PIC는 **새로 훈련하거나 파인튜닝하는 모델을 Activity B의 비연속 재사용에 최적화하는 중장기 방향**을 제시한다. 즉각 적용 가능한 단기 방향: github.com/shijuzhao/Comb의 구현을 분석해 encoder cross-attention 경로가 현재 src/cache/segmented.py의 세그먼트 재조합 로직과 어떻게 통합될 수 있는지 인터페이스 설계를 탐색할 것.
- **COMB + Irminsul + AdapShot의 3-트랙 통합 라우터**: "모델 아키텍처에 따라 최적 비연속 재사용 방법을 자동 선택"하는 "아키텍처-인식 비연속 재사용 라우터"를 Activity B의 핵심 구현 목표로 제안한다 — MLA 모델 → Irminsul, GQA/MHA 배포 모델 → AdapShot, COMB-훈련 모델 → COMB Native PIC cross-attention. 이 라우터를 src/cache/base.py의 CacheStore 인터페이스에 아키텍처-감지 dispatch 레이어로 추가하면 Activity B의 실용적 완성이 가능하다.

**Activity C**
- **SPHERICAL KV(2605.18856) — 기하학-인식 공동 최적화**: 토큰 선택과 정밀도 티어링을 Rate-Distortion 프레임워크로 통합하는 설계는 Activity C의 현재 구현(독립적 퇴거 + 독립적 양자화)의 분리된 최적화를 극복하는 원리적 경로다. ADA의 각도 코드 저장이 Irminsul(B)의 δ-회전과 MLA 모델에서 수학적으로 결합 가능한지 — 구형 파라미터화 Key에서 δ-회전이 각도 코드에 닫힌 형태로 작용하는지 — 를 분석하는 것이 Activity B+C 통합의 핵심 이론 문제다.
- **Minimal-Intervention α(2605.14292) — TriAttention 소예산 즉시 개선**: argmax-top-k를 greedy facility-location 선택으로 교체하는 단일 λ 파라미터 수정이 "즉시 구현 가능한" 개선이다. src/cache/segmented.py에 현재 구현된 top-k 토큰 선택 로직에 V-공간 다양성 페널티(λ 가중 facility-location)를 추가하면 Activity C의 "압축 정확도 delta ±1% 이내" 목표를 소예산 조건에서 더 강하게 달성하는 단기 구현이 가능하다. TriAttention(이미 보고)이 이미 src/cache/에 통합 계획이 있다면 α 수정을 동시에 적용하는 것이 가장 효율적이다.
