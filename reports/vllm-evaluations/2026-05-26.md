### Critical Issue: Depth-Axis Cosine Similarity ≠ Attention Error Bound

The depth-axis compression substitutes layer `l`'s `c_kv` with layer `l-1`'s tensor when `cos_sim(c_kv[l], c_kv[l-1]) >= 0.90`. This is **not** sufficient to bound attention output error to ±1%.

**Measured evidence:**

| cos_sim between adjacent layers | Noise scale | Attention output relative error |
|---|---|---|
| 1.0000 | 0.00 | 0.00% |
| 0.9987 | 0.05 | 5.9% (>>1%) |
| 0.9949 | 0.10 | 11.4% |
| 0.9891 | 0.15 | 18.9% |
| 0.9799 | 0.20 | 24.7% |

Even at `cos_sim=0.9987`, the attention error is 5.9%. A threshold of ~0.9999 would be needed to guarantee <1% attention error, which would eliminate almost all sharing opportunities.

**Why the position-axis IS zero-loss:** `c_KV` in MLA is derived from the content projection and is not modified by RoPE positional encoding. Therefore identical segment content → identical `c_KV` → pointer reuse has zero accuracy impact. This is mathematically guaranteed.

**Why the depth-axis is NOT guaranteed low-loss:** Layer sharing substitutes the actual `c_kv[l]` tensor with `c_kv[l-1]`. Even small absolute differences (high cosine similarity) can produce significant attention output error because the attention mechanism amplifies differences via the softmax operation.

### Required Correction (for Loop 2)

1. **Remove depth-axis sharing from the accuracy path.** Depth-axis sharing should either:
   - Store residuals `c_kv[l] - c_kv[l-1]` and reconstruct exactly, OR
   - Use depth sharing only as a memory layout optimization (same physical block, different metadata), with no accuracy impact, OR
   - Raise the threshold to ≥0.9999 (near-lossless), which reduces compression ratio but maintains accuracy contract.

2. **Position-axis deduplication is correct and should remain unchanged.** It is mathematically zero-loss and the primary source of memory savings.

3. **`auto_adjust_threshold`** correctly raises the threshold when accuracy feedback is provided, but it cannot fix the underlying issue if the feedback loop is not connected to a real accuracy measurement.

File: `/home/user/inference-orchestration/vllm_integration/irminsul_attention_backend_patch.py`

Required fix (choose one):
- Option A: Store residuals — add `_depth_residuals: Dict[(str, int), Tensor]` mapping `(segment_id, layer_idx) → c_kv[l] - c_kv[l-1]`, restore exactly in `read_hook`. This preserves memory savings while maintaining zero accuracy loss.
